# 字幕内容与时间轴

## 对话字幕

1. 从`分集剧本.完整剧本`提取人物对白、明确需要展示的心声和必要画外音。
2. 用最终视频的语音和动作定位起止时间。
3. 用`分镜视频生成prompt.台词与声音`、来源 clip 和建议时长辅助对齐。
4. 自动听写只定位时间，不替代正式文本。
5. 视频完全没有说出剧本中的某句时，不强行把整句塞进画面；把该句标为冲突并等待用户决定。

把说话人和台词正文分开存储。`speaker`用于私有对账，渲染`text`只保存引号内或冒号后的实际台词内容。不得把角色姓名、`说话人：`、冒号、括号动作、舞台说明或“说话的情景”写入中文或译文字幕。

默认规则：

- 中文单行建议不超过18个汉字；超过时按语义分成最多两行。
- 双语中文单行建议不超过16个汉字，译文尽量控制为一行或两行短句。
- 最短可读时长建议为800毫秒；极短语气词可缩短到500毫秒。
- 普通字幕持续时间按每秒4至8个汉字估算，再以实际语音时长为准。
- 相邻说话人的紧密接话直接衔接，不添加淡入、淡出或人为空白。
- 同一说话人连续短句可按语义合并，但不能改变停顿和反应节奏。

## 世界观与本集前情说明

### 取材顺序

1. 从完整剧情拓扑定位独立入口和该入口的第一集。
2. 从第一集`完整剧本`、`单集梗概`、`剧本分析`、故事板和最终视频确定开场前情。
3. 从`游戏企划`补足理解第一集所必需的稳定世界规则。
4. 以第一集的观众知识边界过滤剧透。

缺少拓扑或第一集正式内容时，只能产出标有“草案”的候选文字，不能进入最终渲染。

### 信息结构

输出必须包含两个信息层：

- `世界规则层`：时间或时代、地点，以及影响当前冲突的一条核心规则。
- `本集开场层`：用普通事实说明第一集为什么从当前事件开始，并与现有开场画面直接对应。它可以描述人物、任务、异常现象、事故或冲突，不强制出现主角。

不要把整部作品的一句话概述直接当开场字幕。总企划负责提供稳定设定，第一集负责决定此刻该告诉观众什么。

第二句不是剧情预告、悬念文案或人物小传。它应当让第一次观看的人在看到开场画面时明白“原来这一集要演这件事”。不要提前解释画面自己会清楚呈现的视觉答案，也不要用“一场神秘交易”“危险正在逼近”等新谜面代替事实。

### 冻结输入原则

- 以最终视频、正式第一集剧本和故事板为不可逆输入。
- 字幕只做提炼、翻译、排版和时间对齐，不评价第一集是否应该这样写。
- 禁止为了匹配字幕要求用户重写第一集、重做故事板、重新生成镜头或浪费已经消耗的生成额度。
- 现有第一集与总世界观衔接弱时，先分别忠实提炼世界规则和本集开场，再寻找真实桥接事实；不得编造联系。
- 在企划、组织关系、角色资产、场景资产、第一集和视频之间寻找已确认的最短因果桥。桥接事实可以进入第一句，但不能新增世界设定。
- 找不到真实因果桥时，不输出两句互不相关的组合；询问用户只保留世界规则、只保留本集开场或取消介绍。
- 无法在前5秒内以理想独占段说清时，按 Ask User 规则询问生成独立空镜、使用现有视频留白区域或采用用户填写的其他方案；此时不得再次提供取消世界观说明，也不得未经用户选择修改原视频内容。

### 零背景观众测试

假定观众此前没有看过企划、角色表或宣传材料。逐词检查字幕：

- 默认只允许出现地点名和主角名两个专名。
- 不引入尚未在画面中完成介绍的配角名、组织名、能力名、道具名、行业黑话或交易细目。
- 把“老魏怀疑阿九出售的港区情报泄露”降维为“一笔买卖出了问题”。
- 把“地下交易中间人”解释成具体行为，如“替人验货”“替买卖双方判断责任”。
- 如果一句话会让观众追问“这是谁”“这是什么”，删掉该名词；只有答案影响理解当前画面时，才用普通话补足。
- 字幕读完后，观众只需知道“世界的根本矛盾、第一集为什么从当前事件开始”，无需记忆新名词。
- 两句话之间必须能用一条已确认的因果链连接，不能只是题材相同或同时发生在同一城市。

### 表达与长度

- 只使用上游已有事实，使用日常中文，不写氛围散文。
- 逻辑上形成一段完整前情；显示时可以是一句两个分句，也可以拆成两至三张连续字幕卡。
- 前5秒默认总字量控制在24至36个汉字；必须结合实际显示时长和可读速度缩短，不能为了塞入更多信息而加快闪屏。
- 优先删去专有名词堆叠、势力枚举、能力等级和不影响第一集理解的背景。
- 禁止用“不站队”“卷入危机”“危险降临”“平静被打破”“被迫做出选择”等抽象总结代替人物身份、事件和任务。
- 不提前泄露第一集后段事件、分支结果、隐藏身份、幕后真相或结局。
- 第一集刻意通过画面、对白或悬念揭示的信息，不在开场字幕中抢先说明。
- 只出现在对应入口视频前5秒；多入口项目分别生成。
- 双语世界规则和本集前情默认拆成两张顺序字幕卡，每张中文在上、译文在下；不得四行同时堆在画面主体上。

### 质量判断

字幕结束后，首次观看者应能回答：

1. 这个世界最重要的异常规则是什么？
2. 故事此刻发生在哪里或处于什么时代？
3. 第二句是否说明了第一集为什么要演当前剧情？
4. 第二句是否与已经生成的开场画面直接对应？
5. 第二句是否又制造了一个需要解释的新悬念？若有，改成普通事实。
6. 是否出现了需要额外解释的人名或术语？若有，删去或改成普通说法。
7. 是否暗示、要求或建议用户返工上游内容？若有，删除。
8. 能否从现有字段逐项指出“世界规则 → 中间事实 → 本集事件”？不能则不得生成双句组合。

若第3或第4题无法仅凭第一集确定，继续读取第一集内容，不得从总企划猜测。

示例结构：

> 世界规则卡：镜城将异能者视为危险，觉醒者只能藏进地下帮派和黑市求生。
>
> 本集开场卡：今晚，一个异能者帮派的车队路线遭人泄露，沈夜受托查明原因。

## 人物介绍

固定内容：

```text
角色名称
身份定位
```

身份定位过长时，保留最能帮助观众理解当前戏剧关系的身份，不增加上游不存在的头衔。人物介绍以中文身份锚点为主，竖排显示。

建议时长：

- 最短1000毫秒。
- 常规1200至2200毫秒。
- 角色移动很快或画面切换频繁时，优先延续到下一个仍能确认该角色的镜头，但不得跨越角色离场。

## 翻译

- 中英双语：中文在上、英文在下。
- 其他语言：默认中文在上、目标语言在下。
- 用户明确“仅目标语言”时才移除中文对话字幕。
- 人名、地名、组织名、称谓和术语建立项目级词汇表。
- 保留人物语气、身份高低和关系距离，不逐字硬译。
- 不翻译资产ID、文件名和内部技术字段。
- 中英或中文加其他语言模式下，人物介绍默认同时提供姓名和身份译文，并紧邻中文身份锚点排列；中文模式才只显示中文。

## 私有计划事件

每个事件至少包含：

```json
{
  "event_id": "EP01-S01-D001",
  "video_id": "EP01-S01",
  "kind": "dialogue",
  "start_ms": 1200,
  "end_ms": 3100,
  "text": "先别放箭，它坏了，未必冲我们来的。",
  "translation": "",
  "font_key": "source_han_sans",
  "position": {
    "alignment": 2,
    "margin_l": 80,
    "margin_r": 80,
    "margin_v": 64
  },
  "applies_to_routes": ["route-main"]
}
```

`kind`可以是`dialogue`、`worldview`、`character_intro`或烧入现有空镜的`title`。人物介绍额外记录`character_name`、`character_identity`和首次出场证据；黑屏标题使用视频级`title_card`，完整合同见`title-card.md`和`render-and-quality-check.md`。
