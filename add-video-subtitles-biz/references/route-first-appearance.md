# 路线首次出场

## 定义

按每条玩家可达路线独立判断人物首次真人出场。不要按项目文件顺序、分集编号全局最小值或生成时间只介绍一次。

## 输入

- 唯一入口或多个独立入口。
- 分集节点与有向边。
- 互动选项及目标分集。
- 每个视频的分集、镜头顺序和角色可见证据。
- 全部正式角色描述。

## 可见出场判定

只有同时满足以下条件才算人物真人出场：

- 角色本人在最终视频中可见。
- 脸部、稳定轮廓、标志服装或其他身份锚点足以确认身份。
- 不是照片、画像、屏幕影像、雕像、替身或无法确认的远景人群。
- 已从最终视频抽取该时间点画面，并在抽帧中确认角色本人，而不是根据剧本、故事板或镜头描述推定。
- 已用至少两个相互独立的身份锚点把画面人物绑定到正式角色，例如资产外观与服装、发型、本人台词、对方称呼、称谓关系或连续镜头追踪。

以下情况不算：

- 只被台词提及。
- 只有声音、电话、广播或心声。
- 只有无法确认身份的背影、手部或剪影。
- 故事板出现但最终视频没有出现。

用户明确要求“声音首次出现也介绍”时，作为项目级覆盖规则记录。

## 算法

1. 从每个入口遍历所有玩家可达路径。
2. 为每条路径初始化空的`introduced_characters`集合。
3. 按路径上的实际播放顺序扫描最终视频。
4. 发现正式角色首次满足可见出场判定时：
   - 抽取并检查首次清晰帧。
   - 记录`route_id`、`character_name`、`video_id`、`first_clear_visible_ms`、`first_clear_frame`、人物框和人物所在侧。
   - 记录至少两个`identity_evidence`，先确认人物身份，再从人物框计算画面侧；禁止用左右位置、角色列表顺序、台词顺序或性别直接分配姓名。
   - 生成一次人物介绍事件。
   - 把角色加入该路径的集合。
5. 后续再出现时不重复介绍。

有环路线不得无限展开。对于可回访节点，使用`节点 + 已介绍角色集合`作为访问状态；同一状态重复时停止。

## 汇合与共享视频

同一共享视频可能由多条路线进入。分别计算进入共享视频前的角色介绍集合：

- 所有上游路线都已介绍：共享视频不显示人物介绍。
- 所有上游路线都未介绍：共享视频可使用统一人物介绍版本。
- 部分路线已介绍、部分未介绍：必须生成路线适配版本，或由播放层按路线条件选择人物介绍轨。

不得为了避免多版本而让已介绍路线重复显示，也不得让未介绍路线漏掉介绍。

## 多入口

项目存在多个互不相通的入口时，每个入口分别计算世界观说明和人物首次出场。入口之间不共享`introduced_characters`。

## 私有合同

人物首次出场记录示例：

```json
{
  "route_id": "route-b",
  "character_name": "霍峥",
  "video_id": "EP01-S05",
  "first_clear_visible_ms": 12400,
  "first_clear_frame": "checks/EP01-S05-HuoZheng-12400.jpg",
  "character_bbox": {"x1": 1260, "y1": 180, "x2": 1760, "y2": 1000},
  "face_bbox": {"x1": 1400, "y1": 210, "x2": 1570, "y2": 430},
  "character_side": "right",
  "identity_evidence": [
    "抽帧服装与霍峥角色资产的暗红披风一致",
    "该人物开口的正式台词及对方称呼共同指向霍峥"
  ],
  "evidence": "霍峥正脸和固定暗红披风首次清晰可见",
  "intro_event_id": "EP01-S05-C001"
}
```

验证要求：

- 每条可达路线的每个正式出场角色恰好有一次首次出场记录。
- 记录必须带可读取的抽帧路径，且时间不能早于该角色首次确认可见时间。
- 人物介绍事件必须覆盖记录对应路线。
- 人物介绍事件开始时间不得早于`first_clear_visible_ms`；文字框必须与人物位于同一侧且不与脸部框相交。
- 每个身份映射至少有两个可追溯的独立锚点；姓名与身份字幕必须对应文字邻近的那名人物。证据不足时先询问用户，不得猜测。
- 中英或其他双语模式下，人物介绍事件必须同时包含人物姓名和身份的译文。
- 共享视频状态不一致时必须存在变体或条件轨。
