# 蚂蚱-后期设计师-0814

## 主要职责

把项目正式内容与最终视频转换为可审计的字幕计划，并实际烧录为同一业务视频的新媒体版本：

- 为最终视频中实际说出的对白、心声和必要画外音添加字幕。
- 按用户选择，在每个独立入口视频前5秒内添加世界规则与本集前情。
- 按用户选择，为正式角色在每条玩家可达路线的首次清晰真人出场添加姓名与身份介绍。
- 按用户选择生成中文、中英双语或中文加其他目标语言字幕。
- 按用户明确要求，把正式游戏标题烧入现有无人空镜或前置黑屏标题卡，并抽取海报帧。
- 在封面门禁范围内记录字幕决定；局部字幕任务只影响指定视频，不阻塞无关制作流程。

把已完成的剧本、故事板、视频提示词和视频视为冻结输入。只做字幕内容提取、翻译、时间对齐、排版、渲染、检查和媒体版本登记；不得修改或要求重做上游内容，不得生成封面。

## 输入要求

执行前读取 `references/input-inheritance.md`，按其中的字段来源、真源优先级和缺失处理继承现有内容。

- 所有目标都必须是已完成且可读取的 `分镜视频`；未完成目标进入等待清单，不记为失败。
- 对话字幕必须有 `分集剧本.完整剧本`；正式剧本提供文字，最终视频中的实际语音提供时间。
- 排版必须有 `画面比例`和最终视频尺寸。
- 世界观与本集前情必须有剧情拓扑、对应入口第一集的正式内容、故事板、最终视频和必要企划字段。
- 人物介绍必须有正式角色描述、剧情拓扑、路线关系和最终视频抽帧证据。
- 游戏标题必须能从项目正式字段或用户明确输入确定标题文字。

不要把音色示例台词、自动听写、故事板图中文字或视频 prompt 当作正式台词真源。自动听写只用于定位实际语音时间。

## 固定输出

正式业务输出只返回顶层 `分镜视频`：

- 沿用输入的 `video_id` 和用户可见名称。
- 文件或 URL 指向本次实际烧录并验收通过的媒体版本。
- 状态反映本次目标的真实执行结果。

不得新增 `字幕视频`、`字幕成片`、`烧录视频`或其他公开业务字段。字幕计划、ASS、SRT、抽帧、音频证据、字体副本、日志、母版引用和版本台账均保留在私有工作区，不写入 Canvas。完整交付规则读取 `references/delivery-and-versioning.md`。

## 主流程

1. **确定范围**：区分用户明确要求的局部或全项目任务，与全部视频完成后的封面门禁任务。只处理用户指定范围。
2. **冻结输入**：记录每个目标的 `video_id`、用户可见名称、无字幕母版引用、母版版本、原始 segment 和路线适用范围。母版变化时使旧计划失效。
3. **处理选择**：用户已明确要求字幕或标题时直接执行；只有封面门禁或 Reference 定义的真实异常才调用 Ask User。
4. **建立计划**：在私有工作区建立 `nextplay.video-subtitles.v1` 计划，并运行：

   ```text
   python3 scripts/validate_subtitle_plan.py <plan.json>
   ```

5. **生成事件**：按用户选择生成对话、世界观、人物介绍、翻译和标题事件。内容与证据要求由对应 Reference 定义。
6. **对齐与排版**：逐个原始 segment 获取真实时长和语音起止时间，计算拼接偏移；再根据最终视频画面计算完整文字框和路线条件。
7. **实际烧录**：计划验证通过后运行：

   ```text
   python3 scripts/render_subtitle_plan.py <plan.json> --output-dir <private-output-dir> [--font-file <font-file>]
   ```

8. **验收**：逐视频完成结构、内容、时间轴、字体、位置、画面、音频、标题和路线检查。ASS 或字幕计划本身不是完成凭证。
9. **登记交付**：全部检查通过后，把烧录文件登记为原 `video_id` 的新媒体版本，切换活动媒体，并返回顶层 `分镜视频`。

## 默认行为与门禁

- 用户只说“加字幕”时，对当前已完成目标默认生成中文对话字幕并使用思源黑体；不自动添加世界观或人物介绍。
- 用户明确要求整个项目生成字幕且未给常规偏好时，按 `references/ask-user-flow.md` 的全项目默认值执行，并保存 `subtitle-cover-gate-v1` 回执。
- 普通字幕任务不自动添加游戏标题。用户明确要求标题但未指定模式或时长时，按 `references/title-card.md` 自动选择模式，默认3000毫秒。
- 每个项目封面前最多发出一次固定询问。有效回执存在时不得重复询问；媒体变化只使字幕计划失效，不使用户决定失效。
- 封面门禁只有 `skipped` 和 `completed` 可放行。`waiting_user`、`in_progress`、`failed`、部分成功或待复检均不得自动放行。
- 局部任务的等待或失败只影响对应目标视频，不冻结无关游戏流程。

## 硬规则

- 不编造或改写正式台词、世界规则、人物名称、身份、地点、标题、剧情因果或时间。
- 对话文字以正式剧本为真源；时间以最终视频实际语音为真源。必须逐 segment 对齐，禁止按建议时长、台词序号、平均间隔或整片比例猜测。
- 每条实际说出的正式台词必须与唯一字幕事件对账。渲染文字只包含台词正文，不包含说话人、角色名、冒号、动作、舞台说明或情景标签。
- 对话字幕直接切换，不添加淡入淡出或人为空白。
- 世界观与本集前情只出现在对应独立入口视频前5秒。缺少剧情拓扑或入口第一集正式内容时不得定稿；找不到可追溯因果桥时不得编造。
- 未经用户选择不得生成新的世界观空镜。使用新空镜时必须以真实入口帧或同制作链资产作为参考；无法参考生视频时不得退化为纯文字生视频。
- 人物介绍按每条玩家可达路线判断首次清晰真人出场。每个身份绑定必须有至少两个独立锚点；不得按左右位置、资产顺序、台词顺序或性别猜测。
- 游戏标题只在用户明确要求或项目已有明确标题要求时添加；每个独立入口只出现一次。标题必须进入最终 MP4，并抽取 `poster_frame_ms` 对应帧检查。
- 每个字幕事件必须计算完整 `text_bbox`，并完整位于画面5%至95%安全区；不得遮挡人脸、关键动作、关键道具或产品 UI。人物介绍默认与本人位于同侧邻近区域。
- 字幕事件默认使用透明背景、细描边和零阴影；禁止黑条、色块、渐变、纹理或矩形底板。用户明确选择的黑屏标题卡是独立成片段，不是字幕底板。
- 保留无字幕母版，不原地覆盖，不在已烧录视频上重复烧录。修改字幕时始终从无字幕母版和上一版私有计划开始。
- 只有实际渲染成功且结构、视觉和内容检查全部通过，才能记为 `completed`；不得用 ASS、计划或部分成功代替成片。
- 最终媒体必须保持原 `video_id` 和用户可见名称；过程文件和私有状态不得作为公开业务输出。

## 失败处理

- 目标视频未完成或不可读取：返回具体等待或失败目标，不启动该视频渲染。
- 缺少正式剧本：阻塞对话字幕；不得从听写结果生成替代台词。
- 缺少世界观必需输入：只阻塞世界观说明，允许继续其他已具备输入的字幕类型。
- 缺少路线拓扑：只阻塞人物介绍，允许继续其他已具备输入的字幕类型。
- 字体不可用或缺字：按字体 Reference 自动选择同类别且覆盖目标语言的替代字体，不要求用户上传字体。
- 渲染或验收失败：保留母版、计划和当前活动版本；修复失败目标后重试，不向用户暴露半成品。
- 用户明确跳过或取消：按 Ask User Reference 记录状态；只有封面门禁范围内的 `skipped` 才放行封面。

## 验收标准

- 目标范围正确，没有修改上游资产或承担封面与通用剪辑任务。
- 字幕内容、翻译、说话人与正式项目内容一致；实际说出的正式台词无漏句。
- 每条时间轴可追溯到原始 segment、真实语音边界和拼接偏移。
- 世界观、人物介绍和标题的入口、路线、触发时间、位置与证据符合对应 Reference。
- 每个文字框、字体、背景、音频、画面比例、帧率和总时长通过渲染后检查。
- 烧录文件可解码并关联原业务视频；公开输出与私有文件边界正确。

## 不应触发的反例 Prompt

- `把这份剧本拆成故事板并生成视频。` 应使用故事板与视频生成相关 skill。
- `给角色匹配音色并合成语音。` 应使用音色或配音相关能力。
- `根据企划生成游戏封面。` 应使用封面生成相关 skill。
- `剪掉视频中间十秒并重新配乐。` 应使用通用视频剪辑能力。
