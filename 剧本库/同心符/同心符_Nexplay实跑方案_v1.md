# 《同心符》Nexplay 实跑方案 v1

## 目标

在 Nexplay 中先完成一个可点击、可走完三个主要结局的互动样片，再逐镜替换成稳定的 AI 电影画面。单次游玩目标 15—18 分钟；包含所有分支的独立影像总量预计 21—25 分钟。

## 目前已经确认的平台能力

2026-07-31 在实际开发环境 `https://nextplay-dev.sandaii.cn/` 验证：

- 首页支持自然语言创建项目。
- 支持多附件上传，适合同时提交剧本、角色设定图、场景参考图和镜头表。
- 有两种控制模式：
  - **执行前确认**：Agent 每次执行前征得同意。
  - **全自动**：Agent 自主执行并交付最终结果。
- 首页公开作品展示了约 20 分钟的互动项目，类型与视觉风格可被标记。
- 项目创建、开始互动和查看生产流程都要求登录。

尚未确认：

- 每个视频片段的最大时长、分辨率、比例和可重试次数。
- 角色／场景参考资产能否跨镜头锁定。
- 是否能在已有项目中只重做一个镜头而不影响其他节点。
- 视频模型生成中文字幕时，是否支持逐句修改而不重做画面。
- 项目导出、分享、版本回退和分支数据格式。

## 2026-07-31 登录后实测结果

### 剧本忠实度

20 秒测试的大纲层基本忠实保留了输入：深夜出租屋、2 秒环境空镜、1 秒黑屏片名《门外》、阿浩走到门边、唯一一句对白“谁？”，以及“打开门／关灯躲起来”两个选项。系统没有擅自增加对白，人物、场景和道具也分别只建立了阿浩、深夜出租屋门厅和出租屋房门。

但画布投影出现了严重漏失：选择前的公共剧情只存在于大纲／时间轴中，没有生成公共主线路线卡。实际画布从“门外仍无人回应，阿浩该怎么做？”的分支节点直接开始，且该节点没有入线；两张后继路线卡只是“打开门”和“关灯躲起来”。因此平台目前会出现“文字大纲忠实，但可运行结构丢剧情”的情况。

正式导入《同心符》时必须增加硬性约束：

> 本轮是忠实拆分，不是改编。不得增删、合并、改写剧情、对白、选择或结局。必须先把选择前的共用主线建立成可见路线卡，再连接分支节点；每个剧本场次都要在画布中有对应节点。生成媒体前先输出“原剧本场次—画布节点”逐项对照表，缺一项即停止。

### 分集 Skill 触发检查

实际触发链为：

```text
interactive-film-game_dev
→ outline-generator_biz
→ asset-designer_biz
→ episode-generator_biz
→ plan-storyboard-and-generate-video-biz
→ asset-image-generator_biz
```

其中 `episode-generator_biz` 正常加载了：

- `business-interface.md`
- `episode-output-schema.md`
- `upstream-input-translation.md`
- `emotional-spine-state-graph.md`
- `causal-episode-writing.md`
- `chinese-dialogue-craft.md`
- `character-appearance-validation.md`

它还写入 `episode-business-result.json` 并执行了拓扑校验。就“有没有触发、依赖有没有读取、结果有没有保存”而言，分集 Skill 是正确运行的。

但它把两个选择后的入口解释成“两集／两条路线”，界面显示“共 2 集 · 1 个分支”，没有把分支前的公共段落作为可见共用集／路线保存。这说明分集 Skill 的内部生成基本完成，问题更可能出在分集结果到游戏画布的合并／投影合同，而不是完全没有调用分集 Skill。`emotional-spine-state-graph.md` 和 `causal-episode-writing.md` 也意味着它具有主动重组和润色倾向，正式剧本必须明确使用“忠实拆分模式”。

### 已复现的平台缺陷与阻塞

1. 画风选择组件曾长期停在“正在准备回答／提交中”；通过聊天明确发送“选择现代都市并继续”才绕过。
2. 第一次结构生成耗时约 15 分钟，不适合未经核对就直接提交完整长片。
3. Agent 回复中直接渲染了 `$[slot:episode](...)` 一类原始槽位标记，属于输出合同或前端渲染缺陷。
4. 媒体阶段加载 `interactive-film-game_dev · references/media-projection-workflow.md` 失败，导致总任务标记“执行失败”。
5. 父任务失败后，三个 `image_generate` 子任务仍长期显示“正在生成图片”；停止任务和刷新页面都不能回收子任务。
6. 对“打开门”路线单独点击“生成分镜”后，Agent 能正确加载故事板 Skill、导演指南、提示词规则、项目 JSON 和合并合同，但路线卡从“分镜制作中”退回“生成分镜”，仍为 `0/0 分镜`。随后又派生新的图片任务并锁住发送框。
7. 两条路线的“剪辑／打开时间线编辑”均因 `0/0 分镜`而禁用。
8. 字幕测试依赖至少一个可用视频镜头；目前尚未进入视频或时间线阶段，不能宣称字幕能力已验证。

### 当前真实结论

- 结构生成和 Skill 编排能跑，但“剧本内容 → 可运行画布”的完整性不可靠。
- 分集 Skill 看起来正常触发；公共主线漏失更像后续投影／合并问题。
- 媒体投影缺失引用文件是当前首要后端阻塞。
- 剪辑入口确实存在，但没有分镜就不可用。
- 独立字幕入口及视频模型直出中文字幕仍待媒体阻塞解除后验证。

## 当前阻塞

项目已经登录并建立。当前阻塞不是账号，而是媒体链路：缺少 `interactive-film-game_dev/references/media-projection-workflow.md`，且失败后生成子任务不能正常取消。修复该引用或部署一致性后，应先补回选择前公共主线，再重跑一条序章分镜；只有出现 `1/N 分镜` 后才继续验证剪辑和字幕。

## 阶段一：20 秒冒烟测试

### 已提交的测试提示词

> 做一个20秒的单场景互动悬疑短片测试：深夜出租屋，阿浩听见门外有人敲门。先用2秒环境空镜，随后黑屏出现片名《门外》1秒；回到门内近景，阿浩走到门边。结尾给玩家两个选项：A 打开门，B 关灯躲起来。画面写实、低照度、固定机位为主。先建立最小可运行项目，不生成字幕。人物对白只有一句：阿浩：谁？

### 为什么这样测试

这个项目只包含一处场景、一名可见人物、一句对白、一次片名和一个二选一节点，可以用最少成本同时验证：

1. 平台是否先生成结构再生成画面。
2. 互动选项是否真的可点击并进入不同结果。
3. 黑场片名能否准确生成中文。
4. 固定机位、低照度和人物连续性是否可控。
5. 不使用字幕 skill 时，对白能否正常保留。
6. 单镜头失败后能否局部重做。

### 冒烟测试验收

- 从开始到选项出现不超过 15 秒。
- 两个选项均可点击，且导向不同的可见结果。
- 片名只出现一次，持续约 1 秒，不夹杂多余字符。
- 阿浩在不同镜头中脸、衣服和站位基本一致。
- 门的位置、开合方向和光线方向不跳变。
- “谁？”的口型、声音和角色匹配。
- 平台能显示每一步生成状态，并允许回到某个生产节点修改。

任何一项失败，都先记录“平台真实边界”，不在同一提示词里无限叠加补丁。

## 阶段二：先搭骨架，不立即生成全片

登录后的正式项目先切到 **执行前确认**，上传：

1. `同心符_完整互动剧本_v1.5.md`
2. 阿浩角色定妆图：正面、侧面、全身、90 年代末服装。
3. 小月角色定妆图：正常状态和异化状态，但保持同一张脸。
4. 女摊主定妆图。
5. 三个主场景参考：夜市口、姻缘摊、出租屋。
6. 道具表：同心符、合影、旧裁纸刀、铁盒、红灯笼。

第一轮只要求平台输出：

- 项目结构和全部互动节点。
- 共用主线与各分支的节点 ID。
- 角色资产 ID、场景资产 ID和道具资产 ID。
- 镜头清单，不生成成片视频。

先人工核对节点：

```text
共用主线 1-1 → 1-2 → 1-3
  ├─ 算了吧 → 普通结局
  └─ 写下名字 → 1-5-B → 1-6 → 1-7
                         ├─ 不开门 → 死路
                         └─ 打开门 → 1-9 → 1-10 → 1-11 → 1-12
                                                     ├─ 刺向小月
                                                     ├─ 写下阿浩
                                                     └─ 拿起合影
```

确认结构无误后，再切换全自动生成测试镜头；不能让平台先生成十几分钟视频，再发现分支接错。

## 阶段三：四条校准镜头

先只生成四条，确定全片的共同语言：

### C01｜1-1 夜市合影

- 时长：6—8 秒。
- 目标：人物一致性、90 年代夜市质感、闪光前后稳定。
- 机位：固定 35mm 等效中广角。
- 验收：小月在人群中心，阿浩在边缘；闪光后人物不能换脸或换位。

### C02｜1-6 饭桌凝视

- 时长：8—10 秒。
- 目标：不靠怪物特效也能制造恐怖。
- 机位：固定双人中景，大量头顶暗部。
- 声音：无配乐，只有呼吸和“嗒、嗒”滴水。
- 验收：小月几乎不眨眼；阿浩先产生反应；灯位、餐桌、人物位置稳定。

### C03｜1-12 黑水倒灌

- 时长：6—8 秒。
- 目标：验证全片最难的超自然奇观。
- 规则：黑水只从缝隙出现并沿墙向上；湿发只在天花板交织；小月不瞬移、不变脸。
- 验收：观众一眼理解危险正在升级，也一眼看见桌上的三个关键道具。

### C04｜1-13-C 裁掉自己

- 时长：6—8 秒。
- 目标：验证照片碎片复原和人物从照片中被裁下的连续动作。
- 机位：严格顶拍，复用 1-3 的照片素材。
- 验收：碎片一次撒下后快速归位；阿浩一刀裁下自己的完整轮廓；不慢放、不出现额外手指。

四条中至少三条能在两次以内达到可用，才进入批量生产。若 C03 或 C04 做不到，提前改为“实拍／静帧合成＋后期运动”，不要让整个项目被一个高难镜头拖死。

## 阶段四：建立镜头包

平台中的每个视频请求都使用同一格式：

```text
镜头ID：
所属节点：
时长：
画幅／帧率：
角色资产ID：
场景资产ID：
道具资产ID：
景别与焦段：
机位与运动：
光线：
起始构图：
人物动作及顺序：
对白／环境声：
结束构图：
必须连续的上一镜：
禁止项：
字幕：本轮无／本轮补哪一句
```

“禁止项”至少包含：

- 不换脸、不换装、不改变发型。
- 不增加人物、门窗、家具或文字。
- 不改变左右手和道具位置。
- 不自行添加字幕、水印和片名。
- 不把 90 年代场景现代化。
- 黑水只按本镜头指定方向运动。

## 阶段五：按依赖关系生成

不是按剧本顺序从头生成到底，而是按可复用资产顺序：

1. 先做 1-1 完整合影，锁定所有照片相关素材。
2. 再做 1-3 裁照片，保存每块碎片的位置。
3. 做正常出租屋母版，以及同机位的潮湿版、灾变版、多年霉变版。
4. 做小月正常状态，再做湿发／水迹异化层。
5. 生成共用主线。
6. 生成卫生间分支和普通结局。
7. 最后生成三个终局。
8. 用 1-1 的镜头与人物位置制作 1-14-C 回环合影。

这样可以让真结局调用已锁定的照片资产，让伪圆满结局精确复用饭桌构图。

## 片名执行

片名不放在开场第一帧。

1. 1-1 和 1-2 先让观众进入真实夜市。
2. 摊主问：“你要的是她的心，还是她这个人？”
3. 阿浩问：“有什么不一样？”
4. 红灯笼晃动，摊主不回答。
5. 硬切黑场，环境声停半拍。
6. 白色宋体／仿宋片名《同心符》出现 1.5 秒。
7. 直接切入出租屋灯泡。

片名优先由平台的游戏 UI／文字图层制作。只有确认视频模型中文稳定时，才把它烧录进视频。

## 字幕执行

平台没有独立字幕 skill，因此字幕不与第一轮画面绑定。

1. 第一轮生成干净画面、对白声音和口型。
2. 画面锁定后，按镜头逐条向视频模型补字幕。
3. 指令只允许增加指定中文字幕，不允许改画面、声音、时长和口型。
4. 逐字对照 v1.5 剧本验收。
5. 中文字形不稳的镜头，退回游戏平台 UI 或后期字幕层。

优先测试三类字幕：

- 普通对白：“怎么去了这么久？”
- 极短对白：“才五分钟。”
- 情绪对白：“阿浩，你对我做了什么！我恨你！”

三类都稳定后再批量补全。

## 互动 UI 规划

- 选择出现前，画面停住 0.5 秒，不提前显示结果暗示。
- 选项只描述动作：
  - 【算了吧】／【写下名字】
  - 【不开门】／【打开门】
  - 【刺向小月】／【割破手指，在符上写下自己的名字】／【拿起那张合影】
- 三个最终选项使用同一字体、同一颜色、同一尺寸，不给真结局高亮。
- 玩家选择后立刻隐藏全部按钮，0.2 秒内进入对应镜头。
- 所有结局结束后提供“回到最终选择”和“从头开始”，不自动替玩家重选。

## 批量生产的停损线

- 同一角色连续两次换脸：停止该场，回到角色资产锁定。
- 同一道具连续两次文字错误：改用 UI／后期图层，不再重生整镜。
- 同一复杂动作连续三次失败：拆成两个镜头或改为静帧合成。
- 分支接错一次：停止所有视频生成，先修拓扑。
- 任何镜头只有“更漂亮”但不推进信息：删除，不为时长保留。

## 完整交付物

- 可点击的 Nexplay 项目。
- 一条共用主线和五个可到达结果。
- 角色、场景、道具资产库。
- 镜头表及每镜生成提示词。
- 无字幕母版。
- 带中文字幕版本。
- 片名和互动 UI 图层。
- 失败镜头及替代方案记录。
