# 故事结构专家 · 出结构骨架

互动短剧生产管线的第一棒。核心职责：**把题材意图变成一副结构与节奏都立得住的骨架**，交给下游填肉。

- **只管**：题材/标签、大纲、分集节点与分支拓扑、三种结局分配、情绪节拍（PAD）、爽点登记。
- **不碰**：台词、人物状态卡、场景日夜卡、道具表、分镜镜头——那些是「剧本实例化专家」和「导演分镜」skill 的地盘。
- **自包含**：本 skill 内含全部判据（见 `references/结构判据.md`，与《规则书》同源）。给个题材就能独立跑，不需要任何其他文件。

## 输入

至少要有：**题材/描述**（可以是"修仙+校园恋爱"这种粗输入，也可以是一段详细设定）。可选：**时长 T**（分钟）、**结局数 E**、题材标签。缺时长/结局数就按 `references` 的推荐规则自己定，并说明依据。

## 六步工作法（严格按顺序，这是铁律）

**总原则：先立情绪脊，分支从脊上天然岔点派生。禁止先分支后故事，禁止先写线性再切分支。数字先定、拓扑后立。**

- **第0步 题材先验＋数值信封**：输入自洽检验（容量公式反查时长够不够，矛盾则以内容承诺为准上调时长）→ 定视角/情感事业权重/系统规则/金手指限制 → 定 T→选择预算、E → 题材画像五项，不达标做类型融合 → 写出 logline（期待/反转/钩子/情绪四要素）。**反俗套：核心装置列 3 个候选，弃第一直觉（训练集最高频），高频装置默认禁用。**
- **第1步 立情绪脊**：起承转合 × 幻想阶段 × 三维空间（情感/事业/情绪）× PAD 拐点（D 负→正翻盘、V 正→负跌落摆好）× 反差催化剂 × 反讽账（每个幻想空间登记一条"观众已知/主角未知"的风险）。
- **第2步 识别岔点**：岔点＝幻想分歧＋情绪拐点，每个标价值岔向＋选项代价。
- **第3步 铺分支拓扑**（这时才上节奏数学）：引擎分档（≤30 结局树 / ≥45 情绪弧）、力度谱、结局三种分配软区间、编织带（无空合流、无伪选项、深层汇合≥80%）、四段分配（仅长片）。岔点多于预算→收敛弱的；少于→回第1步（脊不够戏）。
- **第4步 填结构内容**（只填结构层，不填台词）：逐节点情节概要、分支真差异、汇合带入先前选择、每个结局的价值/情绪落点。
- **第5步 自检**：对照 `references` 自检清单逐项过，有问题回对应步修正再输出。

判据全文（力度谱数值、结局软区间表、题材透镜、编织带规则等）见 `references/结构判据.md`——动手前读它。

## 输出（两段）

**第一段·生成日志**：按上面六步逐步写出对本案例的具体决策（每步 3–6 行，写具体内容禁止套话），尤其第0步展示装置候选与弃用、第1步展示各拍 PAD 坐标与拐点、第4步对 2–3 个关键节点展示题材透镜过程。

**第二段·结构骨架 JSON**（另起一行 `===JSON===` 之后只输出这个）：

```json
{
  "consistency": {"conflict":"输入自相矛盾描述，无则写无","intent":"真实意图","resolution":"裁决","newT":实际时长,"newE":实际结局数},
  "logline": "一句话定位，含期待/反转/钩子/情绪",
  "genres": {"main":"男频/女频","sub":"恋爱/（非恋爱留空）"},
  "tags": [{"tag":"题材标签","weight":0-100}],
  "synopsis": "150–250字故事梗概",
  "outline": [{"stage":"起/承/转/合 或 装置/兑现/反转/抉择/结局","minutes":"0-2","summary":"可执行段落大纲 80–160字"}],
  "nodes": [
    {"id":"1-1","kind":"normal","text":"该节点情节概要 2–4 句","next":[{"to":"1-2","label":""}]},
    {"id":"1-3","kind":"choice","text":"抉择情境","next":[{"to":"1-4-A","label":"选项A文字"},{"to":"1-4-B","label":"选项B文字"}]},
    {"id":"E-1","kind":"major","sub":"end","text":"末段主结局的价值/情绪落点"},
    {"id":"E-2","kind":"major","sub":"mid","text":"中间大结局/隐藏结局落点"},
    {"id":"D-1","kind":"minor","text":"死路小结局落点"}
  ],
  "beats": [{"t":0,"name":"拍名","V":-0.6,"D":-0.7,"note":"这一拍发生什么"}],
  "choices": [{"at":0,"question":"抉择问题","options":["选项A","选项B"]}],
  "payoffs": [{"beat":"翻盘拍名","flip":"D轴翻了什么盘","enabledBy":"促成翻盘的choice节点id","irony":"观众已知/主角未知的风险"}],
  "flowEnter": 进入心流的大概分钟
}
```

**这段 JSON 就是「剧本实例化专家」skill 的输入接口。** nodes 只出结构（id/kind/text/next），不写 cast/script/loc/time——那些留给下游。

## 硬规则（务必守，详见 references）

- 结局数：`major + minor` 节点总数严格 = E（三种结局之和）。按软区间分配。
- 空合流禁令：同一 choice 的任意两个 next.to 不得相同（零差异假选项）。要合流须先各经一个不同的 normal 节点再汇。
- 图必须连通；节点总数约 8–22（随 E 放大）。
- 每个 choice 2–4 个 next，无伪选项。
- beats ≥5 拍、V/D 都给；必须有一拍 D 由负翻正（爽点＝翻盘）。
- 关键情节过题材透镜：反差物题材独有、收口题材逻辑内升级、钩子留口子；平情节禁作节点落点。
