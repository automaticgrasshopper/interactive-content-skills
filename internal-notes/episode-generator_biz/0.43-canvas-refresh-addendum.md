# episode-generator-biz 0.43 画布刷新交接补充

日期：2026-08-13

0.43 继承 0.42 全部拓扑、双稿丢弃、主要结局锁定选择和交付凭证规则，只新增“用户已在画布上改图后的当前状态重读门禁”。

## 问题

用户在画布新增、删除、移动或重连节点后，Agent 可能继续使用操作前的项目快照。当用户说“生成新加的节点”、“生成第23节点”或“我删了一个节点，理顺前后剧情”时，Agent 如果不重读当前全图，就无法可靠地确定目标节点的真实前驱、后继和当前编号。

## 0.43 规则

- 定位阶段与创作阶段分离。
- 定位阶段必须在本轮用户请求后废弃旧快照，重新读取当前项目 revision、全部节点和全部边。
- 分页或分批读取必须读到结束，不得只扫描当前可见画布区域。
- 指定节点号、标题或 node_ref 必须在当前快照中唯一解析。
- 新增、生成、修改时锁定唯一目标及其全部直接前驱、后继。
- 删除后以当前图新形成的直接相邻节点为接缝锚点，不得继续使用被删节点的事实。
- 全图定位PASS后，创作范围再收窄到用户授权节点与必要接缝，不顺带修改其他路线。

## 新增门禁

`scripts/validate_canvas_snapshot.py` 要求：

- 快照范围必须是`full-graph`。
- 必须有平台返回的`project_revision`。
- 快照必须绑定当前`user-request.md`的SHA-256。
- `node_count`必须与节点数组一致。
- 节点号、node_ref、入边、出边和选项目标必须完整且互相对称。
- 目标必须唯一解析；删除和重连必须锁定当前图接缝锚点。
- PASS回执记录快照哈希、revision、节点数、边数以及目标的真实前驱和后继。

没有`canvas-scan-receipt.json` PASS回执时，Skill 禁止进入局部梗概、剧本生成或写回。

## 确定性测试

- 本轮请求后的完整快照，第23节点唯一位于第09与第13之间：PASS。
- 快照绑定的用户请求哈希已过期：FAIL。
- 快照少节点、引用不存在目标或入出边不对称：FAIL。

## 技术边界

Skill 可以强制忠实执行者在创作前重读全图，并防止内部不一致快照通过门禁。但 Skill 本身不能凭空读取 NextPlay 数据库；快照是否真的来自本轮后的最新项目，最终仍依赖平台读取工具返回真实revision和全量节点。若调用方再次绕过本 Skill，项目写入层仍无法由本 Skill 单方阻止。
