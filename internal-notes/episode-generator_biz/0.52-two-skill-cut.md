# 0.52 分集规划师双 Skill 切割说明

## 实现范围

本次只以`business-skill-track/episode-generator-biz/0.52`为功能蓝本。原目录未改动；0.53、0.54及线上slug未改动。新源码位于`business-skill-track/episode-skill-split/versions/0.01/`，生产 Skill 目录内不放测试、样本、缓存、日志或运行产物。

## 两个 Skill

| 显示名称 | slug | 版本 | 完成边界 |
|---|---|---|---|
| 流程图规划师 | `episode-route-planner-biz` | `0.01` | 正式保存可展示、可编辑的`route-handoff`后立即结束 |
| 分集剧情编剧 | `episode-generator-biz` | `0.55` | 独立验收并保存一个指定`node_id`的`episode-node-patch` |

保留`episode-generator-biz`给分集剧情，以降低最终下游迁移成本；新流程图slug不与仓库现有`episode-branch-planner-biz`实验 Skill 混用。后者属于三 Skill 子任务实验管线，不具备本次正式流程图落盘合同。

## 流程图输入输出合同

输入沿用0.52的可见字段：标题、一句话、大纲正文、故事体量、角色卡片、场景卡片、道具卡片，以及用户本轮明确要求。`route_input_hash`绑定白名单投影；不得读取节点建议和隐藏故事结构字段。

正式输出`nextplay.episode-route-handoff.v1`包含`project_id`、`route_id`、`route_version`、`route_status=accepted`、`route_input_hash`、`route_output_hash`、`accepted_at`、`nodes`、`edges`、`choices`、`endings`。每节点含稳定`node_id`、标题、梗概、冲突、入口状态、状态变化、允许资产、连接、结局、互动、`stop_boundary`和`node_route_material_hash`。不含任何完整剧本或占位正文。

## 分集剧情输入输出合同

输入必须绑定正式路线的`project_id`、`route_id`、`route_version`、`route_output_hash`、`node_id`和`node_route_material_hash`。直接前情、当前停止边界、允许资产与角色信息从该正式路线的目标节点及连接读取。

输出`nextplay.episode-node-patch.v1`只含该节点的完整剧本、真实剧本创作分析、场景展开计划、连续性分析、冷读问题与结论、实际关联资产、派生信息和质量证据。补丁禁止含全图`nodes/edges/choices/endings`及任何路线所有字段。

## 删除的跨界步骤

- 流程图保存不再等待短底稿、Enhancer、正文、角色首次出场、剧本结构验收、单集Acceptance或全剧闭包。
- 流程图不再为满足旧九字段生成占位`完整剧本`、实际资产或假剧本分析。
- 分集剧情不再写完整故事、切主线、审计裂缝、生成两版拓扑、决定节点数、创建选择或分类结局。
- 单节点失败不再使整条路线或其他节点失效；只有路线版本或哈希变化使旧节点输入失效。
- 不建立跨Skill工程服务、共享数据库、自动串联或批处理器。

## 0.52 脚本分流

逐个检查后没有直接整包复制旧脚本。原因是0.52的路径、完成凭证与整组九字段组装器把两端紧耦合；复制会恢复跨界职责。新脚本只保留各自确定性语义：

| 0.52脚本职责 | 处理结果 |
|---|---|
| `build_creative_brief`、完整故事/裂缝/支线/拓扑/路线时长/情绪投影/梗概集合/规划Acceptance系列 | 语义归流程图；由`route_contract.py`对最终独立交接执行字段、拓扑、连接、选择、结局、停止边界和哈希验收 |
| `build_episode_adaptation_source`、`build_episode_writing_input`、`build_enhancer_input`、短底稿/正文/角色出场/结构/单集Acceptance系列 | 语义归分集剧情；由`screenplay_contract.py`对单节点路线绑定、正文结构、真实分析、资产和质量证据验收 |
| `assemble_business_output`、`completion_gate`、`verify_deliverable` | 不复制；它们要求全图所有剧本完成才交付，正是本次要删除的耦合。最终0.52兼容投影由调用方组合正式路线与各节点补丁 |
| `workflow_state`、`run_state`、`action_contracts`、`dependency_binding` | 不复制；新路线是一次正式交接，剧本是一次一个节点的原子补丁，不建立跨Skill总状态机 |
| `validate_canvas_snapshot` | 不复制；display字段和画布revision属于既有工程调用方，两个新Skill只使用稳定`node_id` |
| `validate_business_output` | 不复制；旧验证器强制每节点同时存在梗概与完整正文。新路线和单节点分别由专属合同验收，组合兼容结果仍可在调用方完成后使用旧九字段校验 |

调查还发现0.52目录的`reference-manifest.json`以及`assemble_business_output.py`内部版本常量仍写作`episode-generator-biz/0.51`。本次没有修改这一可追溯基线；两个新manifest和验收器使用各自准确版本，避免延续该标识漂移。

## 工程边界

本地 Skill 已提供正式路线和单节点补丁合同及确定性验收器。真正接入产品时，工程侧仍需把`route-handoff`投影为画布、持久化route版本与哈希，并把单节点补丁写入对应节点剧本区域；这是既有调用方适配工作，不是本次本地 Skill 的硬阻塞，也不应由 Skill 猜测工程字段。
