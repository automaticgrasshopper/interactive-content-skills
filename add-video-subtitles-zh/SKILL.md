# 蚂蚱-后期设计师-0814

## 职责

在游戏制作的任何阶段，为当前指定且已经完成的视频把项目事实和成片内容转化为可审计的字幕时间轴，并实际烧录带字幕的新视频版本。把已经生成的剧本、故事板和视频视为冻结输入，字幕必须适配成片：

1. 为有对白或心声的镜头添加对话字幕。
2. 按用户选择在首个入口视频前5秒添加“世界规则 + 本集前情”双层开场说明。
3. 按用户选择为正式角色在每条玩家可达路线的首次真人出场添加竖排中文姓名与身份。
4. 按用户选择生成中文、中英双语或中文加其他目标语言字幕。
5. 按用户明确要求把正式游戏标题制成海报式标题帧并烧入成片，支持黑屏艺术字卡和现有无人空镜。
6. 只在封面门禁范围内，于字幕完成、用户明确跳过或取消前阻塞封面；任意阶段的局部按需任务不阻塞其他主流程。

不要重写故事事实、人物身份、正式台词、第一集剧情或视频，不要创建新的业务字段，不要生成封面。

## 必读 Reference

按阶段读取，不要一次性加载全部文件：

- 校验输入、选择字段来源和确定文字真源时，读 `references/input-inheritance.md`。
- 调用 Ask User 前，读 `references/ask-user-flow.md`。
- 提炼世界观、整理台词、翻译和安排时间轴时，读 `references/subtitle-content-rules.md`。
- 计算分支路线人物首次出场时，必须读 `references/route-first-appearance.md`。
- 选择字体、生成字体示意、安排字幕位置和安全区时，读 `references/typography-and-placement.md`。
- 用户要求游戏标题或标题帧时，必须读 `references/title-card.md`。
- 生成私有计划、渲染、检查和决定是否放行封面时，读 `references/render-and-quality-check.md`。
- 注册最终视频、保持业务视频 ID、处理字幕修改或决定 Canvas 可见内容时，必须读 `references/delivery-and-versioning.md`。

## 执行门槛

在以下任一条件成立时进入执行：

- 用户在游戏制作的任何阶段明确要求给整部作品、路线、分集、分镜或已有视频添加、修改、翻译或重做字幕。
- 用户明确要求添加游戏标题、片名、标题帧、片头标题、海报帧或等价内容。
- 主流程已确认全部项目视频完成、即将开始封面，且尚无有效 `subtitle-cover-gate-v1` 决定回执。

用户明确调用时，只要求本次目标视频已经完成且可读取，不要求整个项目完成。对尚未生成或仍在处理的点名视频返回等待清单；先处理其余已完成目标，等待项完成后可继续同一任务，不把等待误记为失败。

封面门禁自动进入时，必须先确认全部项目视频完成。仍有视频排队、生成中、失败、缺失或不可访问时，不调用 Ask User；先返回未完成视频清单。

用户只修改某个视频或某种字幕时，仅处理指定范围，并保持其他已确认字幕不变。

## 输入继承

按 `references/input-inheritance.md` 读取现有字段，不要求上游重复输出，也不新增字段合同。

最低输入：

- `分镜视频`：必需，且目标视频必须可读取。
- `分集剧本`：对话字幕必需，包含`完整剧本`和`单集梗概`。
- `分镜视频生成prompt`或等价镜头时间资料：用于说话人、台词与声音、来源 clip 和镜头时长对齐。
- `画面比例`：必需，用于安全区和字号。

条件输入：

- 生成世界观说明时，先读取项目剧情拓扑，锁定每个独立入口及其第一集；再读取对应`分集剧本.完整剧本`、`分集剧本.单集梗概`和`剧本分析`。最后用`游戏企划`中的`时代与地点`、`游戏世界观`、`一句话概述`、`游戏核心目标`和必要的`剧情整体描述`补足稳定世界规则。缺少入口拓扑或第一集正式内容时，不得仅凭总企划直接生成最终世界观字幕。
- 生成人物介绍时，读取全部正式`角色描述`，至少取得`角色名称`和`身份定位`；同时读取路线拓扑、分集编号、关联角色和最终视频。
- 翻译时，以正式中文台词为原文，不从音色示例台词、故事板图内文字或自动听写结果改写事实。

不要把`音色台词（文本）`当成正式对白，不需要读取封面字段。

## Ask User 规则

严格按 `references/ask-user-flow.md` 执行。

1. 封面前仅调用一次固定 Ask User；同一张卡片同时收集是否生成、世界观、人物介绍、语言和字体。保存 `subtitle-cover-gate-v1` 私有回执后禁止重复询问。
2. 用户选择跳过时记为`skipped`并立即放行封面；选择生成时按卡片答案执行，未填写的可选项使用 Reference 中的推荐默认值。
3. 用户在任意阶段明确要求字幕时，不再询问是否生成。已有明确偏好直接执行；只说“加字幕”时对当前目标默认生成中文对话字幕、思源黑体，不擅自添加世界观或人物介绍。
4. 用户明确要求给整个项目生成字幕时，该决定可直接写入封面回执，封面前不再询问。
5. 分析视频后，仅在确有异常时追加询问：
   - 首个视频前5秒没有世界观独占开场段，包括没有安全区、人物已清晰出场、已有对白或关键动作。
   - 用户自定义语言要求仍存在会改变最终结果的歧义。

每个 Ask User 问题都必须提供“其他想法”的自由输入入口。用户填写后，优先在本 Skill 范围内吸收并执行；只有内容存在会改变最终成片的歧义、违反冻结上游或超出字幕阶段权限时才继续追问。

不要把可由已有字段、视频检查或确定性规则解决的问题抛回用户。
字体不可用不属于用户决策：自动选择同风格且完整覆盖目标语言的可用字体；必要时自动安装或下载可商用替代字体。仍不可用时继续按同风格候选降级，直到找到能够正确渲染全部字符的字体，不得要求用户下载或上传字体。
本环境中所有是/否问题都必须使用带显式选项的单选 Ask User；禁止使用无法渲染提交按钮的 boolean 问题，也禁止让用户用普通聊天消息回答等待中的 Ask User 卡片。

封面前询问必须直接使用 `references/ask-user-flow.md` 中的完整固定 payload，不得拆成两次。调用前必须确认恰有 5 个 `select` 问题，ID 顺序为 `generate_subtitles`、`include_worldview`、`include_character_intro`、`subtitle_language`、`subtitle_font`；第一题必填、其余四题可选；选项数量依次为 `2、2、2、2、3`；每个问题都有“其他想法”。结构不完整属于失败，不是有效的`waiting_user`。

结构摘要如下；实际调用必须逐字复制 Reference 的完整展示文案和选项对象：

```json
{
  "description": "封面生成前请一次决定是否生成字幕及其样式；之后不会重复询问。",
  "questions": [
    {"id": "generate_subtitles", "type": "select", "multiple": false, "required": true, "options": ["generate", "skip"], "userInput": true},
    {"id": "include_worldview", "type": "select", "multiple": false, "required": false, "options": ["include", "exclude"], "userInput": true},
    {"id": "include_character_intro", "type": "select", "multiple": false, "required": false, "options": ["include", "exclude"], "userInput": true},
    {"id": "subtitle_language", "type": "select", "multiple": false, "required": false, "options": ["zh", "zh_en"], "userInput": true},
    {"id": "subtitle_font", "type": "select", "multiple": false, "required": false, "options": ["source_han_sans", "source_han_serif", "lxgw_wenkai"], "userInput": true}
  ]
}
```

上面不是可直接提交的 payload。禁止把摘要中的字符串数组传给 Ask User。

## 封面门禁

内部状态只用于流程控制，不作为 Sheet 字段或下游业务输出：

- `waiting_user`：等待必要选择，阻塞封面。
- `in_progress`：正在规划、渲染或检查，阻塞封面。
- `failed`：字幕失败，阻塞封面；向用户提供重试或明确跳过。
- `skipped`：用户明确跳过，放行封面。
- `completed`：所有目标字幕版本渲染并验收通过，放行封面。

只有封面门禁范围内的`skipped`和`completed`可以进入封面生成。不得因超时、工具失败、缺少字体或部分视频成功而自动放行封面。任意阶段局部按需任务失败只影响其目标视频，不得冻结无关游戏流程。

## 核心流程

### 1. 冻结输入

读取目标视频清单、路线拓扑、分集内容、角色描述、画面比例和用户当前选择。对每个目标记录原有`video_id`、用户可见名称、无字幕母版引用和母版版本；渲染过程中母版变化时，使相关字幕计划失效并重新对齐。

字幕阶段无权修改、否定或要求重新生成已经完成的上游资产。即使入口第一集没有理想地体现总世界观，也必须忠实适配现有第一集；不得为了让字幕更顺而建议用户重写剧本、重做故事板或重新生成视频。

已有字幕版本再次修改时，必须从无字幕母版和上一版私有字幕计划开始。禁止把已烧录字幕的视频当作新输入重复烧录。

### 2. 建立私有字幕计划

在画布公开目录之外创建临时或私有 JSON 计划，合同使用`nextplay.video-subtitles.v1`。该计划是执行缓存，不是业务输出字段。

运行：

```text
python3 scripts/validate_subtitle_plan.py <plan.json>
```

计划至少记录目标视频、每个原始 segment 的真实时长和拼接偏移、正式台词清单、路线适用范围、字幕类型、起止时间、原文、译文、字体、预计文字框和人物首次出场抽帧证据。默认 `background_mode` 必须为 `none`。

标题空镜使用 `kind: title`；黑屏标题使用 `video.title_card`。两者都记录正式标题来源、持续时间、完整文字框和 `poster_frame_ms`。

### 3. 生成对话字幕

以`分集剧本.完整剧本`为文字真源，以最终视频实际说话时机为时间真源，以`分镜视频生成prompt`中的`台词与声音`、来源 clip 和建议时长为对齐辅助。

字幕直接切换，不添加淡入淡出。连续接话按实际语音紧密衔接，不人为加入空白。听写只用于定位时间，不得替代正式中文台词。

必须逐个原始 segment 对齐：

1. 用 `ffprobe` 读取每个 segment 的实际时长并计算精确拼接偏移。
2. 在该 segment 的本地音频上定位每句第一音节和最后音节；优先使用带时间戳的语音识别，不可用时结合波形、静音检测和试听。
3. 本地时间加精确偏移得到完整剪辑时间。禁止按建议时长、片段序号、平均间隔或整片比例猜测。
4. 把正式台词逐句登记为 `spoken` 或有证据的 `not_spoken_in_final`，并与对话事件一一对账。任何实际说出的台词没有事件都属于失败，包括同时显示世界观或人物介绍的 segment。

渲染文本只包含实际说出的台词内容。`speaker`仅作为私有对账元数据；不得把“说话人：”、角色姓名、冒号、舞台说明、动作说明或“说话的情景”烧进画面。中文和译文都遵守此规则。

### 4. 生成世界观与本集前情说明

仅在用户选择后生成。不得从总企划直接压缩一句项目简介；按以下顺序处理：

1. 读取完整剧情拓扑，定位每个独立玩家入口、入口第一集以及进入第一集前观众已知的信息。
2. 读取入口第一集的完整剧本、单集梗概、剧本分析、故事板和最终视频，确定这集为什么从当前事件开始，以及开场画面正在展示什么。
3. 从企划补足观众理解第一集所必需的一条核心世界规则。
4. 从企划、组织关系、角色资产、场景资产、第一集剧本和开场画面中寻找一条已确认的最短因果桥，说明世界规则如何造成第一集的当前事件；不得用题材联想补事实。
5. 组成“双层信息”：第一句说明世界根本矛盾，并在必要时吸收因果桥；第二句用零背景观众能理解的事实说明第一集为什么要演当前剧情，并直接对应现有开场画面。第二句不强制出现主角。
6. 执行零背景观众测试：默认只保留地点名和主角名，不引入尚未介绍的配角、组织、物品或行业术语；把它们改写为“有人”“一笔买卖”“一件货”等普通说法。
7. 只保留看懂第一集所必需的信息，不概括整部作品，不泄露第一集后段事件、分支结果、幕后真相或结局。

双层信息可以是一句内含两个分句，也可以拆成两至三张连续字幕卡；逻辑上必须同时回答“这是怎样的世界”和“第一集为什么从这里开始”。若第一集通过画面或对白刻意揭示某项信息，不在字幕中提前揭示。

不要用“不站队”“卷入危机”“危险降临”“平静被打破”等人物评价或抽象局势代替可拍摄事实。第二句必须让没看过任何资料的观众知道眼前正在发生什么，不能用新的悬念解释一个尚未看懂的剧情。

开场字幕不是人物表或设定表。除地点和主角外，任何名字或术语只要需要观众追问“这是谁、这是什么”，就删去或改成通俗行为描述。默认总字量控制在24至36个汉字；超过时先删信息，不能靠加快闪屏解决。

若总企划与现有第一集看似衔接不理想，先检查是否存在已确认的中间事实。例如：城市抓捕异能者 → 异能者被迫进入地下帮派和黑市 → 该帮派依靠秘密车队活动 → 第一集发生路线泄露。只保留对理解两句必要的桥接事实。

若所有现有字段和视频都找不到真实因果桥，不生成两句并列却互不相关的组合，也不编造联系。使用 Ask User 让用户选择只保留世界规则、只保留本集开场或取消这组介绍；不得要求重新生成第一集，也不得把上游质量问题变成字幕阶段的返工要求。

把说明安排在每个独立入口视频的前5秒内。默认推荐让世界观说明独占该信息段；先检测文字、主体、人脸、对白、关键动作和产品UI安全区，并按可读速度验证总字量。首段已有人物清晰出场、正在说话或有关键动作时，视为没有理想的独占开场段。此时使用 Ask User 让用户选择：

- 推荐：为世界观介绍单独生成约5秒无人物、无对白的场景／世界空镜；该选择可能消耗生成视频所需的 token，并把原视频及其全部字幕事件整体后移。
- 直接在现有视频的真实留白区域添加世界观介绍；不生成底板，必须与人物、人物介绍、对话字幕、关键动作和产品 UI 在空间上完全避让。
- 其他想法：让用户自由填写可执行的呈现方案。

用户已在上一步确认需要世界观和前情提要，此处不得再次提供“取消世界观介绍”。选择现有留白区域后，允许世界观与已有画面或对白处于同一时间段，但不得让两类字幕文字框重叠，也不得遮挡人物或关键内容；找不到合格留白时继续询问用户的其他方案，不能静默取消。
不得未经用户同意生成新镜头。

生成独立空镜时，必须以入口视频的真实帧、同一场景资产或同一制作链资产作为视觉参考进行参考生视频；禁止只用文字描述重新猜测画风。空镜需保持原片的画幅、媒介质感、角色／物体设计语言、色彩、光照、天气、镜头运动和空间连续性。运行时不支持参考生视频时，不得退化为纯文字生视频；改用现有视频留白方案或通过“其他想法”询问用户。

世界观双语不得把世界规则与前情四行同时堆在画面中央。默认拆为两张顺序字幕卡：每张中文在上、英文在下，分别放入经多帧确认的稳定留白区域；文字框不得覆盖空镜主体。只有同一留白能容纳全部内容且仍通过可读性检查时才可合并。

### 5. 生成人物首次出场介绍

仅处理资产设计阶段存在的正式命名角色。完整读取并执行`references/route-first-appearance.md`。

按每条玩家可达路线分别维护“已介绍角色集合”。角色本人第一次清晰可见时显示`角色名称`和`身份定位`；仅被提及、声音出现、照片出现、背影无法确认或画外出现，不算真人首次出场。必须从最终视频抽取首次清晰帧并记录人物框、脸部框和人物所在侧；介绍开始时间不得早于该帧。

先确认“画面中的人是谁”，再决定字幕放在哪一侧。不得按角色资产顺序、台词顺序、画面左右、性别猜测或把第一个人物自动绑定第一个名称。每个身份映射至少需要两个相互独立的锚点，例如角色资产外观、服装／发型、称谓关系、本人开口台词、对方称呼、连续镜头追踪；证据不足时用带“其他想法”的 Ask User 请求确认，不得烧录猜测结果。

中文模式使用竖排中文姓名与身份。中英或中文加其他语言模式必须同时显示中文姓名／身份和对应译文：中文保持主要竖排身份锚点，译文以较小字号紧邻同侧排列，不得只翻译对话而漏掉人物介绍。

共享视频在不同上游路线拥有不同介绍状态时，生成路线适配的字幕版本，不把错误的统一版本烧录给所有路线。

### 6. 生成游戏标题帧

仅在用户明确要求或项目已有明确标题要求时生成，普通“加字幕”不自动添加。完整读取 `references/title-card.md`。

未指定呈现方式时先检查入口视频是否有稳定、无人、无对白、无关键动作的空镜：存在则把标题直接烧录进该空镜；不存在则在入口视频前追加黑屏艺术字卡。未指定持续时间时默认3000毫秒，用户指定优先。样式继承项目视觉语言并允许自由艺术方向，不固定模板。

每个独立入口只显示一次标题，不在每个分集、选择节点或结局重复。小结局和结局字幕不由标题能力自动生成。标题必须实际进入最终MP4；抽取标题区间中点作为海报帧验收。

### 7. 选择排版和位置

完整读取`references/typography-and-placement.md`。对话字幕使用画面下方安全区；人物介绍必须位于人物本人同侧的邻近安全区域，同时避开脸部、手部动作、道具焦点和产品UI；世界观说明使用前5秒内最稳定的留白区域。

对位置判断保留逐视频证据。每个事件必须计算完整文字框并验证其处于5%至95%安全区；只验证 ASS 锚点不算通过。不得仅根据故事板推测最终视频安全区。

### 8. 翻译

中文模式只输出中文。中英双语模式使用中文在上、英文在下。其他语言默认使用中文加目标语言；用户明确要求“仅目标语言”时才移除中文。

保持人物名称、虚构地名、组织名、称谓和关键术语在全项目一致。不要逐字硬译口语、隐喻或身份称谓。

### 9. 渲染

完整读取`references/render-and-quality-check.md`和`references/delivery-and-versioning.md`。先验证计划，再使用本 Skill 的确定性 ASS + FFmpeg 执行脚本实际烧录；不得只生成 ASS 后声称字幕完成。

运行：

```text
python3 scripts/render_subtitle_plan.py <plan.json> --output-dir <private-output-dir> [--font-file <font-file>]
```

脚本依次执行计划校验、ASS 生成、逐视频 FFmpeg 烧录以及宽高、时长、音频映射和非空输出检查，并打印 `nextplay.video-subtitles.render.v1` JSON 回执。只有所有目标视频均返回 `rendered`，且后续视觉和内容抽检也通过，才能登记媒体版本并记为完成。

保留无字幕母版，不原地覆盖。每个输出版本必须可追溯到同一个业务`video_id`、母版版本和私有字幕计划。ASS、SRT、计划、抽帧、音频证据、日志、临时合片和旧烧录版本全部留在私有工作区，不得写入 Canvas。

默认只允许白字、细黑描边、透明背景和零阴影。禁止黑条、色块、渐变、纹理、ASS 矩形底板以及 `drawtext box=1`。

以上透明背景限制适用于字幕事件；用户明确要求的 `black_screen` 游戏标题卡属于独立成片段，不是字幕底板。渲染器必须拼入黑屏标题段并同步后移原片音频。

### 10. 验收并放行

逐视频检查：

- 台词无漏句、错字、错人、错语言或错时间。
- 对话时间来自逐 segment 音频定位；完整剪辑时间严格等于本地时间加真实拼接偏移。
- 紧密接话没有不必要淡入淡出或空白。
- 世界观与本集前情说明位于对应入口视频前5秒；第一句讲清世界根本矛盾，第二句准确说明现有第一集为何从当前事件开始并对应开场画面，两句之间存在可追溯的真实因果桥，且不遮挡关键内容。
- 生成空镜时已使用入口视频真实帧或同制作链资产作参考，空镜与后续原片在画风、色彩、光照、天气、物体设计、画幅和空间上连续；纯文字重新猜测画风属于失败。
- 世界观双语卡位于经多帧确认的稳定留白区域，不压住画面主体；世界规则与前情默认顺序显示，不把四行文字同时堆叠在主体上。
- 默认世界观说明独占开场信息段；用户明确选择现有视频留白区域时可与人物介绍或对话字幕同时存在，但文字框不得重叠且必须避开人物与关键内容。补空镜时原视频、音频和全部后续字幕偏移一致。
- 人物介绍按每条可达路线首次清晰真人出场触发，不早于本人出现；身份映射至少有两个独立锚点，姓名与画面人物不得对调；文字和人物在同侧邻近区域，汇合和共享视频版本正确。
- 双语模式的人物姓名与身份也有对应译文，不得只显示中文人物介绍。
- 对话画面只显示台词内容；中英文均无说话人姓名、冒号、舞台说明或场景说明。
- 字体真实可用，缺字、方框、乱码和错误回退为零。
- 字幕完整文字框不越出5%至95%安全区，不遮脸，不覆盖关键道具或产品UI。
- 默认字幕背景完全透明，没有底纹、黑条或矩形色块。
- 音频、帧率、画面比例和总时长没有意外变化。
- 游戏标题只在独立入口出现一次，文字来自正式项目名称；空镜模式保持原时长，黑屏模式新增时长与计划一致且音频同步顺延；`poster_frame_ms` 抽帧通过海报构图检查。

全部通过后，按`references/delivery-and-versioning.md`把烧录文件注册为原`分镜视频`业务项的新媒体版本，保持原`video_id`和用户可见名称不变，再记为`completed`并放行封面。任一目标版本失败时记为`failed`，不以部分成功代替完成。

## 输出

不要新增字幕业务字段或“字幕视频”对象。沿用故事板视频 Skill 的业务输出规则，只返回顶层`分镜视频`：

- 每一项沿用输入中的原`video_id`和用户可见名称。
- 文件/URL 指向本次验收通过的字幕烧录版本，状态反映本次处理结果。
- 前端把它显示为原来的同一条`分镜视频`；不得新增第二条公开视频。

内部计划、路线集合、时间轴、ASS/SRT、抽帧、音频证据、检查记录、日志、门禁状态、无字幕母版引用和版本映射均为私有信息，不作为公开顶层输出，也不得落入 Canvas。

## 硬规则

- 任意阶段均可处理当前指定且已完成的视频；只有封面门禁询问要求全部项目视频完成。
- 每个项目封面前最多询问一次。有效 `subtitle-cover-gate-v1` 回执存在时禁止重复询问；媒体变更沿用原决定和偏好重建计划。
- 用户明确要求字幕时不再询问是否生成；缺少偏好时按 Ask User Reference 的按需默认值执行。
- 用户选择跳过后立即放行封面；用户选择生成后，在`completed`或用户再次明确跳过前持续阻塞封面。
- 不编造台词、世界规则、角色名称、身份、地点或时间。
- 不把音色示例台词当正式剧情对白。
- 对话字幕不使用淡入淡出；说话人紧密接话时按实际时间直接衔接。
- 对话字幕必须逐 segment 依据实际音频定位，并与正式台词逐句对账；不得均分时间或漏掉首段台词。
- 对话字幕只显示台词正文，禁止显示“说话人：”、角色名、冒号、动作、舞台或情景说明；说话人仅保留在私有计划。
- 世界观与本集前情说明只出现在入口处，位于对应入口视频前5秒；多入口项目按每个独立入口及其第一集分别处理。
- 世界观说明不得与人物介绍或对话字幕的文字框重叠；首段已有角色或对白时必须询问补独立世界空镜或使用现有视频留白区域，不得在用户已确认后再次提供取消世界观。
- 不得在缺少剧情拓扑或入口第一集正式内容时，仅凭总企划生成最终世界观字幕。
- 已完成的第一集、故事板和视频是冻结输入。禁止为了匹配字幕要求重写、重做或重新生成任何上游资产。
- 第一集与世界观衔接较弱时，先从现有事实寻找最短因果桥；找不到时询问保留哪一层，不得输出互不相关的两句，不编造因果，也不把字幕问题升级为上游返工。
- 人物介绍按每条玩家可达路线判断首次真人出场。
- 人物介绍不得早于本人首次清晰可见帧，且默认必须与人物处于画面同侧邻近区域。
- 人物身份不得按左右位置、资产顺序或台词顺序猜测；每个姓名到画面人物的绑定至少保留两个独立身份锚点。
- 共享视频的角色介绍状态不一致时生成路线适配版本。
- 人物介绍以竖排中文名称与身份为主要锚点；中英或其他双语模式必须在同侧附带人物姓名和身份译文。
- 所有位置基于最终视频检查，不只依赖故事板。
- 默认所有字幕背景完全透明，只使用细描边；未经异常分支明确授权，不得生成任何底纹或黑条。
- 游戏标题只在明确触发时添加；自动选择优先使用经多帧证明的无人空镜，否则使用黑屏标题卡，默认3000毫秒并输出海报帧。标题卡黑屏不是字幕底纹例外的泛化授权。
- 每个事件必须以完整文字框通过5%至95%安全区检查；任一字被裁切或伸出画面即失败。
- 保留无字幕母版，禁止原地覆盖，禁止在已烧录版本上重复烧录。
- 最终结果必须保持原`video_id`和用户可见名称；烧录文件是同一业务视频的独立媒体版本，不是新业务视频。
- Canvas 不得出现计划、字幕文件、日志、抽帧、音频证据、临时合片、母版或索引。调用方明确以 Canvas 承载最终媒体时，也只允许展示最终`分镜视频`。
- 不在没有实际渲染和验收结果时声称完成。
- `build_ass_subtitles.py` 的 ASS 文件不是成片；必须执行 `render_subtitle_plan.py` 或等价且可验证的真实烧录路径。

## 失败处理

- 缺少或无法读取目标视频：返回具体视频，不调用字幕渲染。
- 缺少正式分集剧本：阻塞对话字幕，要求上游补齐；不要从听写结果生成新台词。
- 缺少路线拓扑但用户要求人物介绍：阻塞人物介绍；允许用户选择只生成对话和世界观字幕。
- 字体不可用：自动按同风格、同字形类别和目标语言覆盖选择替代字体；必要时自动安装或下载可商用字体。不得询问用户下载、上传或重新选择字体。
- 翻译语言不受当前字体覆盖：更换支持该语言的字体或询问用户，不静默生成缺字版本。
- 渲染失败：保留计划和原始视频，针对失败版本重试；仍失败时报告失败并维持封面阻塞。
- 用户明确取消或跳过：记为`skipped`并放行封面。

## 触发测试

- `第三集刚生成好，先给第三集烧录中文字幕，其他集不用等。`
- `这条路线的视频加字幕，游戏其他部分继续制作。`
- `所有分镜视频都生成好了，封面前只问我一次是否加字幕和字幕样式。`
- `给全部视频加中文对白字幕，同时加世界观开场和人物首次出场介绍。`
- `改成中英双语，字体用思源宋体，其他时间轴不要动。`
- `霍峥在路线B第一次出场时补人物介绍，路线A已经介绍过，不要重复。`
- `第一段没有地方放世界观说明，先问我要不要加5秒空镜。`
- `给游戏加一个片头标题，找得到无人空镜就直接烧进去，否则用黑屏艺术字，时长你决定。`

不应用于：

- `把这份剧本拆成故事板并生成视频。`
- `给角色匹配音色并合成语音。`
- `根据企划生成封面。`
- `剪掉视频中间十秒并重新配乐。`
