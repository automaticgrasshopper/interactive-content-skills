# 字体与位置

## 字体候选

### 思源黑体

- 内部键：`source_han_sans`
- 常见字体名：`Source Han Sans SC`、`Noto Sans CJK SC`
- 推荐：默认对话字幕、中英双语、现代题材、小字号。
- 特点：笔画清晰、中性、屏幕可读性高。

### 思源宋体

- 内部键：`source_han_serif`
- 常见字体名：`Source Han Serif SC`、`Noto Serif CJK SC`
- 推荐：历史、古风、正式叙事和世界观说明。
- 特点：叙事感和仪式感更强，小字号时需适当增加细描边。

### 霞鹜文楷

- 内部键：`lxgw_wenkai`
- 常见字体名：`LXGW WenKai`、`霞鹜文楷`
- 推荐：古风、日常、情感、温暖或书信感作品。
- 特点：有人文和书写气息；高速动作场面不作为默认首选。

使用`assets/font-options-preview.svg`展示示意。预览只说明方向；渲染前必须确认运行环境中的真实字体文件和目标语言覆盖。

## 字体可用性

1. 优先使用用户上传或项目已绑定字体文件。
2. 其次使用已安装且名称、字重和字符覆盖匹配的字体。
3. 不按相似名称盲猜字体路径。
4. 检查中文、拉丁字母、标点和目标翻译语言是否缺字。
5. 字体不可用时自动选择同风格、同字形类别且覆盖目标语言的可用字体，不调用 Ask User。
6. 优先同源替代：`Source Han Sans SC` 与 `Noto Sans CJK SC` 互为黑体候选，`Source Han Serif SC` 与 `Noto Serif CJK SC` 互为宋体候选。
7. 本机没有合适字体时，自动安装或下载可商用替代字体；下载失败后继续在系统字体中降级，直到全部实际字幕字符可正确渲染。
8. 宋体只降级到 CJK 衬线体，黑体只降级到 CJK 无衬线体；霞鹜文楷优先降级到 CJK 楷体或手写体，没有时使用 CJK 宋体。
9. 在私有计划中记录 `requested_font`、`resolved_font` 和替代原因。不得要求用户下载或上传字体，也不得在用户可见 Canvas 暴露字体文件、安装日志或下载记录。

## 安全区

按最终视频尺寸计算：

- 对话字幕：默认位于底部安全区，左右各保留画面宽度5%至8%，底部保留画面高度5%至8%。
- 世界观说明：优先使用上方或侧方稳定留白，不固定压在中心。
- 人物介绍：必须位于角色本人所在的同侧邻近区域，让观众能立即建立文字与人物的对应关系；不得默认放到角色对侧。先在人物框同侧的外缘寻找竖排位置，再尝试同侧上方或下方。只有同侧完全没有安全区时才可改用对侧，并在位置证据中明确记录原因。
- 竖屏视频：避免底部交互区和顶部标题区；人物介绍可用左右侧边纵向安全带。
- 游戏标题：黑屏标题卡默认使用画面中心海报构图；现有空镜标题根据真实留白有机对齐。标题可使用独立艺术字体、字距、颜色与轻量阴影，不把对话字幕的单一样式强加给标题。

所有事件都必须记录预计文字框 `text_bbox`，格式为画面像素坐标
`{"x1": ..., "y1": ..., "x2": ..., "y2": ...}`。文字框必须完整位于安全区：

- `x1 >= width * 0.05`
- `x2 <= width * 0.95`
- `y1 >= height * 0.05`
- `y2 <= height * 0.95`

不得只校验 ASS 锚点。锚点在画面内但文字主体伸出画面，仍属于越界失败。
同时也不得只填写一个安全的 `text_bbox`：显式 `x/y` 必须按 ASS
`alignment` 锚定在该文字框的对应边或中心。竖排人物介绍常用4或6对齐，此时
`y`表示整列文字的垂直中心；把`y`填成首字高度会导致列首越界。

## 对话排版

- 中文：水平居中，最多两行。
- 双语：中文在上，译文在下；译文字号为中文的75%至85%。
- 默认只使用白字和2至3像素黑色描边；背景必须完全透明，阴影为0。
- 禁止黑条、色块、渐变、纹理、半透明矩形和其他文字底纹。
- 默认不使用淡入淡出、弹跳、逐字或打字机效果。
- 相邻说话人字幕直接替换。
- 只排实际台词内容，不显示说话人姓名、冒号、动作、舞台说明或情景标签。

## 人物介绍排版

- 中文竖排，按姓名和身份分列或分组。
- 中英或其他双语模式在中文竖排锚点旁增加较小字号的姓名与身份译文；译文与中文必须属于同一个人物、处于同侧安全区。
- 姓名字号大于身份。
- 文字方向和列顺序在全项目一致。
- 只在角色本人第一次清晰可辨的画面出现后显示；不得在只有场景、车辆、背影、画外音或尚未出现本人时提前显示。
- 记录人物首次清晰帧 `first_clear_visible_ms`、抽帧路径 `first_clear_frame`、人物框 `character_bbox`、人物所在侧 `character_side` 和文字框 `text_bbox`。
- `character_side` 取 `left` 或 `right`。人物中心位于画面左半时，文字框中心也必须在左半；人物中心位于画面右半时，文字框中心也必须在右半。
- 文字框不得与人物脸部框相交；与人物框的水平距离默认不超过画面宽度25%，避免文字与人物失去对应关系。
- 只在首次清晰出场附近短暂显示，不跟随角色长时间移动。
- 同时首次出场多人时分别选择安全区；空间不足时按叙事主次错开时间，不覆盖人脸。

## 世界观排版

- 一句说明可分成两行，但不拆散姓名、地点或关键设定。
- 优先静态显示；不使用复杂动画。
- 背景始终透明，不使用底板。首段没有理想独占开场时，推荐生成独立空镜；用户选择现有视频留白区域时，必须把完整文字框放进真实留白，并与人物介绍、对话字幕、人物脸部、关键动作和产品 UI 完全避让。
- 用开始、中点、结束多帧的主体／边缘／运动检测确认稳定留白，记录`stable_whitespace_evidence`。不得因为画面上方“看起来空”就固定居中。
- 双语世界规则和本集前情默认分两张顺序卡显示，每张中文在上、译文在下。文字框随留白区域有机对齐，可左对齐、右对齐或上方排列；不得四行同时压住空镜主体。

## 位置证据

每个非默认位置记录：

- 视频ID和时间范围。
- 选择区域。
- 避开的脸部、动作、道具和UI。
- 画面比例与像素坐标。
- 是否使用独立空镜或现有视频留白区域。
- 事件预计文字框；人物介绍还要记录人物框、脸部框、人物所在侧和首次清晰帧。

最终检查必须读取渲染结果，不能只检查计划坐标。
