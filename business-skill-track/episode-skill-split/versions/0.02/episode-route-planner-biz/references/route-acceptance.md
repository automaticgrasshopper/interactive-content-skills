# 路线验收

验收必须同时检查：

- 根合同、版本、输入哈希及稳定ID合法；节点字段无剧本跨界内容。
- 唯一入口、全部节点可达、无环、全部路线能抵达结局。
- 节点前后关系、边索引、选择索引、默认下一节点完全一致。
- 分支至少两个不同目标；普通节点恰有一个后继；结局无后继、无选择、默认下一节点为`无`。
- 主、期望、失败、小结局各至少一个，期望与主结局不是同一节点。
- 每个节点梗概、冲突、停止边界均是非占位路线材料；状态变化和允许资产类型正确。
- 重要人物行动、决定裂缝及人物关系后续消费节点均携带事实触发、人物理解、由此发生的行动、人或关系变化及后续行为影响；两者不是彼此独立的事实说明和情绪标签。纯功能过桥节点不强制制造关系变化。
- 每条拓扑前双因果运动都被正式节点材料承接；非结局运动的人或关系变化必须在后续可达节点实际影响行为。删去人物理解后行动仍会原样发生，或关系变化没有后续作用，均不得通过。
- 正式选项除事实可执行外，必须具有人物动机和互异的人或关系代价；只有办事顺序、工具或地点不同的任务菜单不得作为情感分支通过。
- 当前候选必须先取得绑定同一项目、路线版本、输入哈希和候选哈希的`PLANNING_ACCEPTED`；完整故事、主线、情绪运动、决定裂缝、两版完整拓扑、匿名一次比较、情绪脊和双复检不得缺项或过期。
- 匿名比较只允许判断是否存在明显更好的版本；没有明显差距时必须选择第二版。不得打分、按节点或路线数量机械择优、生成第三版或混合两版。
- `planning-acceptance.json`必须由`planning_gate.py create CACHE_ROOT`对逐文件阶段链重新验收后生成，并冻结全部依赖哈希；不得由单个汇总证据文件或候选路线自证。
- 节点材料哈希和整条路线输出哈希由验收器确定性生成，候选不得自封PASS。

运行`accept_route.py CACHE_ROOT FORMAL_ROUTE.json`重新核对当前阶段文件、候选路线和私有规划验收回执，只验路线规划闭包。它不得查找或要求完整剧本，也不得启动剧本生成。失败时不写正式输出；成功时原子保存并输出`ROUTE_ACCEPTED`。
