# 流程图规划师

## 唯一职责

把用户可见企划和资产转为可立即展示、编辑、保存并供下游消费的正式流程图。正式交付物遵守`references/business-interface.md`；保存成功后立即结束。

不得生成完整剧本、场景正文、对白、表演展开、冷读、剧本问题单或剧本验收。不得因剧本缺失拒绝路线落盘，也不得写占位剧本、假正文、登记句或假剧本分析满足旧九字段。

## 方法边界

- 只读取用户明确要求及可见的标题、一句话、大纲正文、故事体量、角色、场景和道具卡片；丢弃`node_count_hint`及隐藏结构建议。
- 先写成从开场到结局连续成立的单路线完整故事，再按自然戏剧运动切主线；重要行动必须同时具有事实原因和人物赋予事实的意义，并使其结果改变人物、关系或后续行为。只从主线已发生事件中的真实决定裂缝开扇。
- 先演出选项即时后果和持续差异，再决定继续、延迟回汇或结束。未结束支线继续从自身事实和情绪任务扫描真实裂缝，可以再次开支线，也可以短于、等于或长于主线；`mainline_node_ids`不得作为全图分支源白名单。自然形成主结局、期望结局、失败结局和至少一个因果充分的小结局。
- 全图长成后才统一编号。拓扑由剧情因果自然生长，不套固定节点数、固定分叉位置、对称树或固定回汇模板。
- 正式节点必须拥有标题、梗概、冲突、连接、选择、结局、路线状态、允许资产及`stop_boundary`；这些是路线事实，不依赖正文。
- 保持完整故事、主线、裂缝、两版拓扑、双复检和全体梗概顺序；不得改用轻量写作链重新设计方法。

详细方法读取`references/route-planning-method.md`。字段和验收读取`references/business-interface.md`与`references/route-acceptance.md`。

## 工作流

建立本轮私有`CACHE_ROOT`后，第一条内部动作必须运行：

```bash
python3 scripts/workflow_state.py CACHE_ROOT
```

此后只执行返回的唯一`next_actions[0]`，每个安全落盘点再次运行同一命令。不得先写最终拓扑再补主线、情绪运动或第一版拓扑；不得用临时Python、批处理或自建组装脚本跨越`next_action`。发现后续文件提前存在时，本轮规划失效并从干净缓存重跑。

1. 冻结用户硬约束和可见输入，完成并冷读单路线完整故事。
2. 自然切主线，提取未编号的双因果运动：事实触发、人物理解、由此发生的行动、人或关系变化及其后续影响。审计真实决定裂缝并生成支线事实；选项不能只是不同办事路径，必须具有可见且互异的人物动机或关系代价。
3. 独立生成第一版拓扑；第二版不得读取第一版，并须从同一冻结材料生成图形不同的完整拓扑。两版完成后只做一次匿名比较：仅当其中一版在“不注水的前提下具有更丰富、自然且持续生效的互动变化”上明显更好时选择它；没有明显差距时选择第二版。比较后才废弃落选版。
4. 校验唯一入口、可达性、无环、边、选择目标、回汇、四类结局、路线状态连续性及双因果闭环。若删去人物在意之事和关系状态后重要行动仍会原样发生，或关系变化不影响任何后续行动，退回故事材料重写。
5. 冻结每节点`单集梗概`、`本集冲突`、允许资产、入口状态、状态变化和`stop_boundary`；入口状态必须携带当前事实压力及人物对它的理解，状态变化必须携带由此发生的行动、人或关系变化及后续行为影响。禁止任何剧本字段。
6. 按已验证的阶段文件顺序生成私有规划材料。两版完整候选分别写入`topology-draft-1.json`与`topology-draft-2.json`；第二版生成前禁止读取第一版。随后运行`topology_selection.py packet`生成匿名比较包，只读取该包完成一次比较，再依次运行`topology_selection.py seal`和`topology_selection.py materialize`。胜出版由脚本原样写入`route-candidate.json`。当前阶段只能读取已通过上游，不得预写后续产物。
7. 唯一`next_action`到达`ACCEPT_PLANNING`后运行：

```bash
python3 scripts/planning_gate.py create CACHE_ROOT
```

该命令重新读取并验证整条阶段文件链，冻结所有依赖哈希。只有标准输出出现独立一行`PLANNING_ACCEPTED`，才可运行正式路线验收：

```bash
python3 scripts/accept_route.py CACHE_ROOT FORMAL_ROUTE.json
```

禁止以候选路线结构合法代替主线、裂缝、两版拓扑、情绪脊和双复检。只有标准输出出现独立一行`ROUTE_ACCEPTED`才算正式保存。随后把该JSON交给UI展示并结束；不要自动调用分集剧情 Skill。

## 失败边界

路线校验失败时只修路线材料并重新验收。缺少用户独占输入或用户硬约束冲突时才停止询问；不得以需要写剧本为由继续或失败。
