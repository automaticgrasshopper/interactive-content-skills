# 分集剧情编剧

## 冻结输入

正式路线是只读依赖。一次只接收一个`node_id`，并同时绑定`project_id`、`route_id`、`route_version`、`route_output_hash`和`node_route_material_hash`。读取范围仅限当前节点路线材料、全部直接前情结尾、当前允许的角色与资产、入口状态、状态变化和`stop_boundary`。

路线不存在、`route_status`不是`accepted`、合同版本不支持、任一绑定不一致或节点不存在时，立即返回明确依赖错误。不得自行重建路线、改写梗概或修正拓扑。

## 不可修改

不得修改或提交节点ID、节点类型、标题、父子关系、边、选择数量、选择文案、选择目标、默认后继、结局布尔值、结局类型、路线状态事实、允许资产或停止边界。输出只能是对应`node_id`的`episode-node-patch`，不得提交整个路线。

## 单节点工作流

1. 按`references/business-interface.md`验证并锁定正式路线与指定节点。
2. 提取事件核：明确入口状态、人物当前目标、主要阻力、本集必须发生的变化和停止位置；不复述梗概，不创造路线事实。
3. 先写场景展开表，再写行动底稿。每场明确`场景目的→人物行动→阻力反馈→局面转折→出口状态`；底稿固定事件因果、人物出场和状态变化。
4. 依据`references/node-screenwriting.md`与`references/dialogue-and-quality.md`写正式剧本。先完成动作和反应，再写推动行动的对白；删掉重复可见信息、设定问答和不改变局面的往返话轮。
5. 初稿完成后单独提取全部台词，按`references/dialogue-and-quality.md`执行两步轻量复写：先去作者腔，再补普通话的对象、承接、态度和关系指向。锁定动作、事实、因果、选择与结尾；台词放回原位后重新核对话茬。
6. 冷读并从最早失效步骤返修：核对事件是否逐场发生、对白是否可删、状态变化是否落地、下一入口是否成立以及是否越过`stop_boundary`。随后填写现有五项剧本创作分析，不新增合同字段。
7. 组装一个节点草稿并运行：

```bash
python3 scripts/accept_node_screenplay.py FORMAL_ROUTE.json NODE_DRAFT.json NODE_PATCH.json
```

只有标准输出出现独立一行`NODE_SCREENPLAY_ACCEPTED`才保存该节点补丁。失败不写输出，不影响正式路线、其他节点或已验收节点。

## 批量与预览

预览就是只处理用户指定的一个节点。调用方以后可逐次传入多个节点，但每个节点必须独立读取、生成、提交、验收和保存；禁止临时批处理脚本，禁止一个节点失败回滚其他节点。

## 停止边界

正文必须停在当前`stop_boundary`内。选项动作属于边，选项造成的首个可见后果属于目标节点；当前节点不得提前演出后续独占核验、选择或结果。
