# 流程图规划师 0.20

用户输入第一性；满足用户硬约束与故事因果后，默认交付一张持续开扇、交织、分层结算的丰满故事网络，不能以一组B/C加大量退出路线交差。输入输出见[业务合同](references/business-interface.md)。**一集 = 一个 slot = 一个非选择剧集节点；结局剧集计入集数，选择卡另计，选项是边。**

## 先区分初次生成与已有画布

已有节点时，包括点击任一集“生成剧本”、继续生成素材、检查或编辑画布，先读[当前画布与用户编辑](references/current-canvas-editing.md)。当前画布优先。用户删除已是决定；首次检测到删改，围绕删除后的前后剧情，提供“接顺现有剧情／补写新的过渡／暂不处理”三个具体方案。断线及孤立剧集处理通过后才继续生成；不以恢复旧路线为默认选项，不放松原保存校验。用本Skill的当前材料绑定交给编剧。只有新建完整路线才执行以下流程。

## 新故事：一条连续流程

当前阶段以实际落盘正文和未修问题为准。审读稿里的“稍后补充”不等于已经修改；有问题先改当前正文再读，不把短故事的欠缺转交长故事或编剧。已完成的上游只读取，不因进入下个阶段再次生成。过程自动继续，不逐步请用户确认。

1. 读用户原话、企划及[故事整理](references/story-development.md)。在 `story-core-review.md` 简记主角的任务、阻碍、为何继续和一次确定的结果；区分用户必保事实与可舍弃的AI谜面。此时不读拓扑或图形规则，不写节点、brief或冻结文件。
2. 写 `story-core.md`，用几百字讲完主角的一次经历，不列结局菜单。结束写入后，下一次调用只读短故事全文。按故事整理要求反查关键转折：依据是否足够、时间与动作是否成立；不能只引用一句自证合理。缺口改进短故事本身，再读修订原文，才继续。
3. 只沿修订短故事独立扩写 `mainline-story.md`，补现场行动、实质交谈、发现与后果，主角和观众同步知情。该调用只写长故事，随后另次读全文、修断点。不要同时创建节点或freeze。开头讲清主角、眼前一件事及必要设定，后文各段围绕一个主要事件。
4. 读取[故事切片与拓扑展开](references/story-planning.md)和业务合同。先在原有草稿列明待用抉择及原动作的第一句，再据此选切口，写 `user-request.md`、`brief.json`、`mainline.json`；长故事已存在，不重写。另次读回每个实际切片，引用首尾句核对正文、冲突和停止边界。原行动及后果从选择之后开始，共享段的第一项行动须适用于来路。切片正确再运行 `python3 scripts/route_plan.py freeze CACHE_ROOT`。时长只分类：不足15分钟为短故事，不逐路计算时长或互动节奏。
5. 从冻结主线的真实裂口写完整支线故事，再切片；不先画空图补摘要。重要路线持续双翼展开、交织后再开扇，并保留来路的事实和代价。默认小结局、期望结局、坏结局、真结局齐全，用户明确数量与类型优先。非短故事默认至少两级不同的期望结算阶梯，继续须有新的事件与代价。完整创作要求见故事切片与拓扑展开。
6. 读取[图形合同](references/graph-contract.md)，用临时ID简短探索形状，写 `exploration.md` 后废弃；不验收草图，不进入正式事实源。正式图重新组织，提交完整支线故事及正式图：`route_plan.py submit CACHE_ROOT SUBMISSION.json`。提交成功后再 `route_plan.py check CACHE_ROOT`；未提交成功不检查不存在的正式候选。
7. 非短故事检查小结局、两层分岔、真正双线交织、持续展开、继续发展占主要比重、两级期望结算阶梯；B双翼与C交织为主，A仅补充。基础结构、数量、结局类型、防末端菜单同样按合同执行。机器只检查图形、输入合同与切片投影，不审剧情或虚构状态。依[恢复规则](references/acceptance.md)只修失败项及确有问题的支线，冻结主线不动，已通过展开保留。
8. 图形PASS后，作者读取实际 `route-candidate.json`。按故事切片与拓扑展开的逐来路引用要求，把每条“选择前正文→所选动作→后继事件”读通；追溯人物、证据、权限和已完成行动，不借用另一支路的事实。问题和实际修订记入原有 `story-core-review.md`，修后重读受影响路径；不以“均符合”代替逐来路阅读，不新增机器语义评分或正式回执。第一集、一集一件事及编剧材料完整性同时核对。图形返修过的支线也完成此步，不能check后直接accept。
9. 作者审读完成后运行 `route_plan.py accept CACHE_ROOT`，得到 `PLANNING_ACCEPTED`；它证明图形与投影通过，不代替作者内容责任。若需保存展示，运行 `route_plan.py accept CACHE_ROOT FORMAL_ROUTE.json` 交调用方按现有接口入库。用户只要规划或画布则至此停止，不生成剧本、媒体或操作平台配置。

禁止删除锁、重建缓存或把非短改成短故事绕过失败。只使用本版 `route_plan.py`，不混用旧的逐节点生长、随机抽签、A/B或编剧脚本。
