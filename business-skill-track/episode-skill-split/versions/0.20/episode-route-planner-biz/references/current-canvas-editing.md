# 当前画布与用户编辑

## 删除是已完成的用户决定

每次处理已有项目，完整重读当前route与revision，按当前显示集号或唯一标题解析稳定node_ref。当前节点、正文和真实边优先于旧规划、缓存、canvas_snapshot和旧回执。删除已完成，不再询问是否删除、是否保留原内容或是否恢复完整路线；新增节点视为已存在，不重复创建。用户未明确说恢复，绝不复活已删除对象。

用户编辑时可以暂时断线，Agent不在每次拖拽时打断。用户下一次要求检查或生成时，才检查当前变化。对用户统一称“画布上孤立的剧集”，不用“孤儿节点”，不展示内部ID、哈希、合同或回执错误。

## 一次提问，说清删后怎么接

首次发现一批未确认的画布删改，用ask_user礼貌说明改了哪里，并围绕当前删除后的前后剧情提供三个方向：

1. **保留删除，接顺现有剧情**：用现存前后剧集重新连接，修改必要的梗概衔接，不新增过渡剧集。例：“将《前集》接到《后集》，把两集之间缺少的去向交代清楚。”
2. **保留删除，补写新的过渡**：原段继续保持删除；用新的过渡剧情衔接现存前后剧集。先说明拟写的过渡事件及位置；需要新增剧集时明确新增数量、接入与接出位置。新剧集必须用新稳定ID，不原样复制或改名复活已删除剧情。
3. **保持现状，暂不处理**：不改任何画布内容，停止本次整理和生成，用户可以继续手动编辑。

提出第二项前，对照已删除段落的核心动作与因果链：新标题、新ID或改写句子都不算新过渡。允许承接后续必需的既有事实，但必须用不同的行动事件把当前前后剧集连接起来；若仍复演被删段落的发现过程和行动顺序，就重写方案后再提问。第一项可以经用户确认将必要衔接压缩进现有剧集，不能把这种压缩冒充第二项的新剧情。

不是泛泛问“删还是连”“要保留还是恢复”。两个修复方向都尊重已经完成的删除，只有接法不同。提问描述各自涉及的剧集、选择和连线；不能只给按钮不说明具体动作。两种接法只有一种成立时说明原因，不编造第二种。用户明确固定集数时，新增过渡不得突破硬数量；第二种改为在现有剧集内补写过渡或明确指出需要用户调整数量。

识别到画布上孤立的剧集时，将它们的处理放入上述具体方案：仍可承接的现存后续可以重接；已失去作用的部分只有列入用户确认的删除清单后才清除。不能因为孤立就自动全删，也不能用旧图补齐一切。只剩一个有效方向的选择卡，方案应说明撤掉失效选择并直接接现存后续；零方向也应纳入接缝处理。不要保留虚假二选一来凑结构。

已有明确的本轮接法授权就执行，不重复确认。首次删改若没有接缝问题，也礼貌确认用户希望保留并继续或暂停，不凭空制造修复。用户说“我删了东西，你看看”不能只报看到后结束；必须给出下一步选择。对同一批已处理成功的修改，换一集操作不再询问；新删改才再问。用户上次选择暂停，不代表授权下一次自动整理；再次请求生成而断线仍在时，重新提供处理方案。

可用本Skill的canvas_writing.py observe记录变化指纹；收到真实答案后用confirm记录direct、transition或stop。等待答案时图又变了，先重读差异再确认；不沿用旧方案覆盖并发编辑。旧版keep/repair记录失效，不能解释为允许带断线继续生成。

## 修复后再继续原请求

用户确认后，以新读current为基线只改授权范围。接顺现有剧情只动必要连接与前后梗概，不新增集；补写过渡只新增方案中明确的新事件和剧集。保持已删除节点不存在、稳定ID不重编号，保留其他剧本和媒体。

完成后先核对真实边、全部可达、选择至少两个有效方向、没有悬空目标与环，接缝讲得通；再走现有写入网关的完整保存校验、CAS和读回。校验失败则局部修补本方案，不能自行扩大删改范围，不能恢复旧图，不能修改校验脚本或绕过网关。用户编辑后的数量和形状服从本轮要求，不强迫补回初次生成的复杂度；但基础连通性与保存合法性不能豁免。用户明确要求保留B/C、交织或其他图形性质时，将这些性质列为本轮保留项，修复后从实际画布重新计算对应graph_check证据；不能只验连通，也不能沿用修改前的报告宣称仍保留。未通过就局部修本轮接法，不降低门禁。首次生成有孤立剧集仍判失败，由Agent自行返修，不让用户替生成错误选方案。

保存成功才用record记录读回基线。若用户原请求是生成某集，自动接着做该集，不让用户重新点按钮；原请求只是检查或整理，则报告具体完成内容后停止，不额外生成剧本或媒体。第三项必须停止，不能把“保持现状”理解为继续生成。

已有剧本的剧集若梗概因接缝调整而变化，说明该集剧本待更新；没有授权不覆盖其已生成剧本和素材。用户原本要求生成的目标，则使用当前梗概重写。

## 当前材料与写入边界

基础图形通过后，用[当前写作材料绑定](canvas-writing-contract.md)准备当前剧集材料，不复用旧全图哈希或旧选择。不为绑定问题回滚全图，不把编辑后路线冒充新一次PLANNING_ACCEPTED。

剧本必须匹配修复后的当前连接：撤掉的选择不再要求玩家作答，不显示已删除选项，也不擅自执行原选项。过渡应讲清真实因果，不把应在后集发生的事提前演出。修复确认已明确采用某个叙事方向时，可按该方向调整接缝，不能从未确认的选项中偷偷替用户选择。

写入前再读revision，变化则重新构造局部差量。编剧只写目标剧本与派生信息，媒体只写目标媒体。写后逐项核对删除未复活、新增未重复、其余连接和剧本媒体未回退。

用户另行明确要求恢复某个对象时，才从可确认历史取回指定内容并合入当前图，不回滚其他用户修改。“恢复运行”只是继续任务。
