# 流程图规划师 0.20

正式 slug：`episode-route-planner-biz`。本版本从已在线测试的 0.20 副本晋升，测试副本不进入本次提交。仓库活动版本指向 0.20，正式资源仍须管理员审核后同步。

## 流程图复杂度

一集是一个 slot、一个非选择剧集节点，结局计集数，选择另计。用户明确数量、类型和简单形状要求优先；15 分钟以下为短故事，不按各路线计算时长或节奏。

非短故事默认以双翼展开和真实交织为骨架，单侧深分支只作补充。图形检查验证不同支路的独立路径、多个共享段及后续收束，避免把普通菱形、线条视觉交叉或串联公共选择当作交织。

新增持续展开检查：至少 4 处选择的两边分别进入不同的下一轮抉择，且有至少 3 轮连续展开；两边马上进入同一公共问题不计入。非收尾选择至少三分之二的选项通向后续抉择，给失败前多串几集不算继续发展。至少两个不同的期望结算沿继续路线逐层兑现，其间须有实际剧集，最终抵达真结局；正式结局仍无出边。默认四类结局齐全，用户明确数量与类型冲突时只豁免对应默认要求。

作者从完整主线与决策裂口写出连续支线，再按原文切为可供编剧展开的剧集。机器只验图形、合同和投影，不能证明剧情、情绪或选项语义正确。图形通过后，作者按实际边检查选项执行、来路条件、回汇承接和结局兑现。

## 故事整理与已知限制

恢复短故事→因果长故事→原文切片的顺序，主角与观众同步知情。第一集围绕一个眼前事件，后续各集保留可供编剧展开的实际行动与结果；冻结前分开公共事件和专属收尾。AI企划允许重整，用户明确事实与数量优先。作者检查不可由图形PASS代替：当前自然输入仍可能保留繁复谜面、扩写新增结尾、回汇重复事件或混写来路，详见最新记录。

## 增删节点与局部恢复

当前画布与 revision 优先于旧规划；已删除对象不自动复活，已新增对象不重复创建。新批次首次检查或生成时礼貌询问接法：保留删除并接顺现有剧情、保留删除并补写新过渡、保持现状并暂停。用户已授权本轮接法则直接执行，不重复确认。新过渡必须是新事件和新 ID，不能改名复活被删剧情。

“画布上孤立的剧集”、无目标边、失效选择须纳入具体方案；只有用户确认的范围才能删除或重接。用户可暂时保留编辑中断线，但不能借此放宽首次生成或后续生成的完整图形校验。暂停即不改、不继续生成；修复通过后自动继续原请求。同批修改不重复问，新批修改重读后再确认。

保留稳定 ID、无关节点、剧本和媒体；只有明确要求恢复时才合入指定历史对象。保存前后完整核对当前版本和差量，继续使用既有写入网关、CAS 和读回，不更改平台代码或共享网关。

## 协议、状态与兼容性

- 沿用 `nextplay.episode-route-handoff.v1`、`capability_id=episode-route-planner-biz` 和现有结局枚举；`main` 表示真结局。
- 作者拥有用户输入、简报、完整故事和正式图；`route_plan.py` 创建冻结锁、版本、投影及规划验收回执，图形审计只读上游。初次生成失败仅修问题支线，冻结主线和通过部分保留。
- `canvas_writing.py` 管理编辑观察指纹、真实答案确认和修复后的读回基线；生成当前单集材料快照及单集回执。它不回写当前图、旧规划锁或其他正式文件；快照的 accepted 不等于新一次 `PLANNING_ACCEPTED`。
- 当前梗概与有效边决定写作输入，删除的选择不进入剧本。当前图变化使对应材料失效，媒体、排版或其他剧本变化不强制再次询问接法。旧 keep/repair 确认记录不再解释为允许断线生成。
- 旧版内部规划缓存不直接迁移，旧版本目录保留；编剧 Skill 与写入网关未修改。相对测试副本只正规化 slug、调用名和“当前测试项目”授权措辞，Python 实现不变。
