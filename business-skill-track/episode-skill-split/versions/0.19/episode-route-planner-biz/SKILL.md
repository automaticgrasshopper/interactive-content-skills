# 流程图规划师 0.19

用户输入第一性；满足用户硬约束与故事因果后，优先有效复杂度。输入输出见[业务合同](references/business-interface.md)。**一集 = 一个 slot = 一个非选择剧集节点；结局剧集计入集数，选择卡另计，选项是边。**

## 先区分初次生成与已有画布

已有节点时，用户新增、删除、恢复、修改、重连，或后续生成遇到结构错误，先读[当前画布与用户编辑](references/current-canvas-editing.md)。当前画布优先，不进入初次生成，不从旧规划缓存补回节点。只有新建完整路线才执行以下流程。

## 初次生成流程

1. 完整读取[故事规划](references/story-planning.md)，从正式企划、资产和用户原话完成简报、情绪走向和一条完整主线故事，先完成“故事讲明白”的作者检查，再沿原文切成剧集。主线必须为支线保留真实决定位置：停在选项动作未执行处，原动作及后果从下一剧集继续。生成 `user-request.md`、`brief.json`、`mainline.json`，运行 `python3 scripts/route_plan.py freeze CACHE_ROOT` 冻结。时长只分类：不足15分钟为短故事，不逐路计算时长或互动节奏。
2. 从冻结主线的真实裂口展开完整支线故事，允许深层开扇、长支线、不同来路交织、带差异回汇和再次分岔。先把各条支线事件写完整，再切片；不能先画空图再补摘要。默认小结局、期望结局、坏结局、真结局四类齐全，包括短故事；用户明确数量或类型优先。期望先兑现，再由最终选择停在期望结局或继续走向真结局，是优先采用的递进结构。
3. 读取[图形合同](references/graph-contract.md)。用临时ID作一次简短形状探索，写 `exploration.md` 后废弃；正式图重新组织，不靠改名换编号复用探索。探索不做正式验收，不进入正式事实源。作者提交完整支线故事及正式图；运行 `route_plan.py submit CACHE_ROOT SUBMISSION.json`，再运行 `route_plan.py check CACHE_ROOT`。
4. 非短故事强制小结局、有效交叉线、至少两层分岔；默认四类结局、基础图形、数量与防末端结局菜单也须通过。机器只检查图形、输入合同与切片投影，不审剧情、情绪或虚构状态。按[恢复规则](references/acceptance.md)只修失败项及确有问题的支线，冻结主线不动，已通过部分保留；机器复检全图，作者不重做全图。
5. 图形通过后，作者沿真实路线顺读完整故事切片及所选动作，确认每条路讲得通、汇合不清空经历、每集足够编剧直接展开、选择没有提前执行。问题回对应支线，不另造A/B、语义打分或证据填表。运行 `route_plan.py accept CACHE_ROOT` 得到 `PLANNING_ACCEPTED`。该标记证明图形与投影通过，不代替作者内容责任。
6. 用户要求只到规划就停止。若同时明确要求保存到当前测试项目并展示画布，则允许交接已验收路线后停止；这不授权生成剧本、媒体或修改平台配置。需要交付时运行 `route_plan.py accept CACHE_ROOT FORMAL_ROUTE.json`，交给调用方按现有接口保存展示。无剧本、媒体或平台配置操作。

禁止删除锁、重建缓存或把非短改成短故事绕过失败。只使用本版 `route_plan.py`，不混用旧的逐节点生长、随机抽签、A/B或编剧脚本。
