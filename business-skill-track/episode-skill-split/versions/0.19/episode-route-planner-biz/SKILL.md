# 流程图规划师

将可见企划和资产规划成有真实选择后果的互动影游流程图。输入与对外交接遵守 [业务接口](references/business-interface.md)。本版为 0.19；只负责路线，编剧 Skill 保持独立。

## 用户输入第一性

用户原话中的题材、必保内容、禁区、节点有无、数量、结局数和连接高于默认创作方法。运行 `scripts/user_constraints.py` 提取硬数量；剧情节点不含独立选择卡，只有明确包含选择的总数才锁总卡数。上游自动建议不成为硬约束。四种结局是语义分类，不能强求各有一个或凑至少四个。无分支要求生成单路线。用户要求本身矛盾才询问；不能为通过规则放宽数量。

## 规划顺序

在本轮独立 `CACHE_ROOT` 中运行 `python3 scripts/workflow_state.py CACHE_ROOT`，按返回阶段继续。完整读取当前阶段所需引用。

1. 按 [故事与分支规划](references/route-planning-method.md) 冻结用户原话、意图锁、简报、完整故事、主线切片、情绪运动、决定裂缝和支线事实。完整故事先写一条充分兑现题材承诺的路线；主线不是支线长度上限。
2. 允许规划支线的即时后果、持续差异、再次选择、回汇条件和结局解锁链。**规划可能发生的选项后果，不等于把它写成选择发生前的既成事实。** 选择节点停在行动之前，原主线已执行的动作从下一节点开始。支线可长于主线，不受 FIFO、预定深度、80/20抽签或固定漏斗控制。
3. 按 [拓扑合同](references/planned-topology.md) 先做简短的废弃形状探索，再提交正式全图。探索只帮助发现另一种因果组织，不要求通过正式门禁、不强求指纹不同；它不进入哈希或正式事实源。正式图用临时ID表达所有节点和边，脚本统一编号、冻结与记账。
4. 按 [验收与恢复](references/route-acceptance.md) 对同一冻结包依次做 A/B 两遍语义复检；各自重新读材料，不能复制结论，不声称两个独立评审者。A偏重故事因果，B偏重全路径与结构，两遍都覆盖完整检查。
5. A/B通过后投影每个节点的最终梗概，再检查事件归属及“先执行、后选择”。梗概不能改图、状态、资产、选项或结局。最后生成独立情绪脊，运行 `python3 scripts/planning_gate.py create CACHE_ROOT`。
6. 只有真实输出 `PLANNING_ACCEPTED` 才通过规划。若用户明确要求停在此处，报告并停止；否则运行 `python3 scripts/accept_route.py CACHE_ROOT FORMAL_ROUTE.json`，得到 `ROUTE_ACCEPTED` 后按业务接口保存展示并结束，不进入剧本。

## 内容标准

鼓励交织、鼓励开扇：在故事因果和用户约束允许时，让不同支线相互影响、带差异回汇后再分岔，并让选择展开为多个有独立冲突的行动方向。具体组织见[故事与分支规划](references/route-planning-method.md)；这是创作鼓励，不是必过形状门禁。

保留旧版有价值的复杂性：分支必须产生可见且持续的不同事实；重要分支先承受自身冲突，再决定是否带差异回汇；仍有未结任务时可以继续分岔。回汇进入共同可执行任务，不能重演已完成选择、消除关系债务或凭空获得别路证据。隐藏或递进结局从此前行动和条件逐步打开；当前平台没有隐藏边条件时，用真实可达的不同节点与选项表达，不能在文字中暗设程序不会执行的门槛。

结局演出退出、代价和结算，不能用末尾菜单替代旅程。小结局来自真实离场；修复困难不成为截断支线的理由。复杂度不等于多堆节点，也不能把有价值的独立分支缩成“选完立即回主线”。

梗概用连续人话讲清人物、行动、阻力、信息来源和眼前变化；关系题材需要真实攻略、关系转折和兑现，不能让恋爱人物只充当案件线索供应者。情绪来自这些事件，不用 PAD 数值倒造剧情。

## 局部恢复

未冻结材料直接修对应文件。冻结后用 `topology_plan.py freeze` 追加带当前哈希的修订，保留无关节点及完整旧版本；脚本归档失效下游，按工作流重新派生。只改梗概时保留拓扑与 A/B，重新投影、梗概复检、情绪脊与最终回执。只改情绪诊断时不回写上游。失败分类、具体恢复入口见验收引用。

已有 0.18 `growth-state.json` 的缓存继续使用 [旧版逐步恢复合同](references/route-growth.md) 与原脚本；不要把旧历史转换成新历史。本版新任务使用全图计划，不创建 growth-state。
