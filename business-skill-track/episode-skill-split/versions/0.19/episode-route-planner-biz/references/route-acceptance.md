# 验收与恢复

## A/B：同一个冻结图，两次重新读取

先运行 `planned_gate.py packet CACHE_ROOT` 获取packet_hash、实际图和全路径记账。A、B依次使用完全相同packet_hash；A的存在不依赖B。每次写 `topology-review-A.json` / `topology-review-B.json`：

```json
{"packet_hash":"当前包哈希","review_pass":"A","verdict":"PASS","checks":[{"check":"主线投影与决定裂缝","passed":true,"explanation":"基于当前材料的判断","evidence":[{"node_id":"episode-001","quote":"当前节点中真实存在的逐字片段"}]}],"issues":[]}
```

六个check完整覆盖：

1. 主线投影与决定裂缝：主线事件未重写、遗漏或重复；支线新决定由自己的后果逼出。
2. 选项尚未执行且后果互异：逐个选择读当前梗概、停止位置与每个后继。当前正文没有先执行选项；不同动作产生不同实际后果。
3. 分支持续差异与回汇承接：逐条回汇核对入口、实际任务、持续状态及后续消费。无别路独占线索、瞬间恢复好感、重复解决已完成过程。不同经历可以在共同任务会合，不能无理由抹平。状态脚本只检查已声明的事实，漏声明仍是语义错误。
4. 结局解锁与因果结算：重要终点由此前行动逐渐形成，不能全部留到最后做结局菜单。主要路线承受独立冲突后演出结算；小结局真实离场，不能作为修复捷径。分类服从用户结局总数，不要求四类齐全。
5. 戏剧单位与结构复杂度：逐节点判断必要性，检查回汇、再次分岔、不同路线长度是否由事件决定。拒绝把有持续差异的分支压成普通漏斗，也不凭指标凑深度或强加回汇。用户锁形时记录其限制，不另造形状。
6. 用户题材与硬约束：数量、禁区和题材承诺都满足。恋爱群像不能退化为多人提供案件线索，互动幻想须有实际体验与关系兑现。

每遍用 `planned_gate.py A CACHE_ROOT` / `planned_gate.py B CACHE_ROOT` 校验。脚本验证材料绑定、覆盖和引用，不能自动证明故事好看；不得用循环拼PASS回执。B从原材料重新读，不能抄A。exact同样检查语义，形状由用户锁定不免除“先执行后选择”。

## 梗概与情绪

投影后运行 `planned_gate.py synopsis-packet CACHE_ROOT`，写 synopsis-review.json：

```json
{"candidate_hash":"包中哈希","verdict":"PASS","nodes":[{"node_id":"episode-001","consistent":true,"choice_pending":true,"quote":"当前梗概逐字片段","explanation":"与冻结事件对应；若为选择，说明全部选项为何尚未执行"}],"issues":[]}
```

覆盖所有节点；选择节点choice_pending必须为true，普通节点可为null。逐节点比较冻结事件与最终梗概；新增事件或提前执行选项须先修正文，不能改标记过关。

emotional-spine.json：`{emotional_spine:[{node_id,valence,arousal,dominance,turn,turn_reason}]}`，按正式节点顺序完整覆盖；PAD为[-1,1]，turn为布尔，拐点须解释。只读上游，在独立文件中诊断，不给拓扑追加情绪字段。

`planning_gate.py create CACHE_ROOT` 最后绑定八项上游、拓扑状态、路线记账、A/B、梗概、候选、梗概复检和情绪脊。依赖顺序单向：拓扑→记账→A/B→梗概→候选→梗概审查→情绪脊→最终回执。A/B的包不包含后续产物，不会因情绪脊生成失效。

## 失败分类与最近恢复点

- USER_CONSTRAINT：原话矛盾或正式图数量不符。前者说明冲突；后者局部调整未冻结方案，不能放宽锁。
- STRUCTURE：断边、环、错误回汇状态。首次冻结失败修PLAN后再冻；已冻结图追加带当前哈希的局部修订。只重做受影响内容，下游验收重新生成，不重写完整故事。
- SEMANTIC：选项提前执行、关系抹平、无因果结局等。错误在梗概就只修梗概并重新materialize、梗概复检、情绪脊和最终回执；在冻结事件就追加拓扑修订。不要把断路一律变成小结局。
- RECEIPT：内容没错但回执陈旧。先核对哪个依赖改变，从该依赖之后重验；不得更改hash伪造通过或重建历史。哈希只防不一致修改，不是对同权限写者的安全隔离。

每次恢复记录原因、入口、受影响文件及次数。局部修复授权包含必要的重验；确需用户独占信息或上游冻结内容本身错误时报告证据，不从头静默重跑。
