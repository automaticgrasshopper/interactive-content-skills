# 一步提交合同

脚本管理 `growth-state.json`，作者不能编辑该文件。每轮先读 `route_growth.py status CACHE_ROOT` 或 `workflow_state.py CACHE_ROOT` 的当前 `state_hash` 与待推进项；只在读到当前结果后创作这一步。

```bash
python3 scripts/route_growth.py init CACHE_ROOT
python3 scripts/route_growth.py status CACHE_ROOT
python3 scripts/route_growth.py append CACHE_ROOT STEP.json
python3 scripts/route_growth.py materialize CACHE_ROOT
```

`append` 每次只接受一个对象，不能是数组。`STEP.json` 可每步复用；脚本保存已接受历史。不要先生成未来多个STEP文件。提交只有：

```json
{
  "expected_state_hash": "当前状态哈希",
  "frontier_id": "当前待推进项ID",
  "action": {
    "type": "node",
    "node": {
      "kind": "scene",
      "title": "当前节点标题",
      "route_material": {
        "单集梗概": "本节点实际发生的行动与直接后果，不预告后续支线或收尾。",
        "本集冲突": "当前行动遇到的具体阻力。",
        "entry_state": {},
        "state_changes": {},
        "allowed_characters": [],
        "allowed_scenes": [],
        "allowed_props": [],
        "stop_boundary": "明确当前节点在什么已经发生的时刻停止。"
      },
      "ending_type": null,
      "emotional_movement_ids": ["引用主线情绪运动ID"],
      "mainline_segment_id": null
    }
  }
}
```

- `scene`：一个当前剧情单位，脚本开放一个后续待推进项。
- `choice`：主线上的选择必须另填`mainline_option_index`（当前主线动作在options中的零基索引）；只声明当前动作，不写未来节点。支线选择不得填此字段。其余同样填写当前节点材料，额外增加 `question` 和 `options:["动作一","动作二"]`，至少两个互斥动作。不填目标ID或后果；脚本给每个动作创建待推进项，轮到它时才演出直接后果。
- `ending`：当前事实已满足退出与结算，`ending_type` 为 `main/expected/failure/small` 之一；脚本不再开放后续项。不是“以后将怎样”的计划。
- `mainline_segment_id`：该步承接主线切片时填写对应ID，支线步骤为 `null`。主线仍须有一条连续路径实现，映射随实际生长记录，不能先绑定正式编号。
- `entry_state`、`state_changes` 为状态对象，写清人物眼前知道的事实、关系压力、资源与行动变化；允许资产只能引用登记名称。原正式字段合同仍适用。

回汇不新增节点，只提交：

```json
{
  "expected_state_hash": "当前状态哈希",
  "frontier_id": "当前待推进项ID",
  "action": {
    "type": "merge",
    "target_node_id": "已存在的growth节点ID",
    "reason": {
      "current_facts": "这条路径已经发生、足以支持回汇的具体事实",
      "shared_task": "与目标节点共享的同一个可执行任务"
    }
  }
}
```

回汇必须基于当前已有事实，不预订未来的汇合目标。已有节点材料必须能承接本路径及持续差异；不能为了合流抹平来源差异。确有内容错误可按下述局部修正入口纠正，并核对所有入边和后续承接。脚本检查目标存在、无环与前沿有效；事实及任务是否确实相容由语义验收判断。

## 回汇入口检查

每次读到当前支路前沿后，在创作下一步前先检查已有主线是否有可接入口。status 中的标题列表仅供定位，须读取候选目标的实际 `route_material`；不能仅凭标题、同一地点或最终目的认定可以合线。

- 对照支路已经发生的行动、出口处境和仍有效的关系差异，与目标的 `entry_state`、梗概、`state_changes`、`stop_boundary`。当前事实必须足以开始目标实际演出的下一场戏，而不只是足以到达它最终的目的。
- 目标若会重演支路已经完成的过程，就沿主线实际事件顺序寻找更靠后的已有接点；允许跨过支路已完成或已以另一条因果路径满足的过程，不得跳过目标仍依赖的必要前提。节点数量、growth ID 创建顺序和正式编号都不等于剧情进度。
- 不要求分支差异全部结算后才能回汇。不同经历、关系和未偿后果可以带入共同任务，但已有目标及后续材料必须能承接；若后文依赖另一支路独有的经历，不能假定合线后差异自动消失，也不能回写目标迁就合流。
- 开放形状中，`toward_mainline` 找到相容入口时优先直接回汇，不再补写重复的过渡剧情；`free` 和未抽签支路可以自然回汇，也可因当前真实后果继续独立发展。检查接点不改变80/20抽签或重抽，不要求每条支路最终回主线。`exact` 始终服从用户锁定连接。
- 若支路剧情已超过已有主线，或暂时没有相容入口，就从当前后果继续生长；只有退出与结算已经成立才结束。不能倒退剧情、预订未来节点或为凑回汇制造结局。主线后续节点尚未生成时，仅在以后轮到该支路、读取新的当前状态后重新判断。

例如支路已通过城门盘问，就不能接回“返城途中”或“城门盘问”；只有“入城交证”的实际入口前提也已满足，才可直接接入该节点。

提交回汇时沿用现有两个原因字段：`current_facts` 说明来源出口及仍持续的差异；`shared_task` 说明目标实际开始的共同任务、入口为何满足、为何不重复已完成过程及差异如何承接。无需新增字段或预写未来支线。

只有所有待推进项关闭，`materialize` 才能投影。最终编号与连接由脚本从历史重建，后置验收重新核对历史、输入哈希和候选一致性。任意未完成路径、陈旧提交、未来目标、历史篡改或手改候选都不能通过正常接口。该机制验证实际提交序列，不证明作者脑中没有提前构想，也不是隔离权限的防伪服务。

## 脚本抽签与恢复

新建生长记录使用v2。脚本从主线当前选项登记推导前沿层级：主线为0，首次离开主线为1，支线再次分岔的每个子前沿为2。普通剧情不增加层级。每个第二层子前沿独立调用`secrets.randbelow(100)`，0–79为`toward_mainline`，80–99为`free`，写入产生这些前沿的步骤`branch_draws`并绑定步骤哈希。抽签由脚本生成，作者不能在STEP里填写数值或倾向。

结果随该路径的后代继承，第三层及以后不重抽。status、工作流恢复、失败重试和历史重放只读已保存结果；陈旧STEP不能再次提交。有效抽签与节点在同一次原子写入中落盘，写入前失败不会向作者交付抽签结果。不同路径可能抽到相同倾向，不凑固定比例。

当前前沿显示`branch_depth`、`return_bias`、`bias_origin_frontier_id`及`growth_guidance`。倾向回归时同时列出已存在的主线节点，仅供判断共同事实和任务，不代表这些节点都可合。不得在支线新增节点时改填主线切片、主线选项或主结局来重置层级；实际回汇仍只指向已存在节点并检查无环。

`exact`模式保持层级记录但不抽签；用户锁形优先。旧v1历史按原合同读取和恢复，不追溯补签。正式路线输出不增加抽签、层级或倾向字段。哈希防止不一致编辑，不是阻止同文件写权限者重建历史的安全隔离；脚本随机性不证明文字中的因果已合理。

## 同轮局部修正

原步骤不可擦除，当前有效节点可通过追加修正事件更新。读取最新state_hash及目标节点后，提交以下对象到同一个 `append CACHE_ROOT STEP.json`：

```json
{"expected_state_hash":"当前哈希","frontier_id":null,"action":{"type":"repair","target_node_id":"growth-000003","reason":"具体错误、修正依据及受影响的连接/后续节点","node":{"kind":"scene","title":"修正后的标题","route_material":{},"ending_type":null,"emotional_movement_ids":["原引用ID"],"mainline_segment_id":null}}}
```

示例的route_material须补全普通节点要求的所有字段。普通修正保留节点kind、主线身份和选择选项/连接，修正标题、当前内容、事实及资产引用。主线也支持这种修正。检查所有入边及受影响后续，必要时逐节点追加修正，不改无关内容。

未锁数量/连接且用户允许小结局时，可以把一处支线scene或choice改成ending/small，写完整的当前退出与结算；不修改主线。脚本移除该节点出边，只从当前图移除失去入口的后续支路及待推进项，共享节点和其他前沿保留；原始步骤仍在历史里。用户已锁形状或任何硬数量时，此收束操作被拒绝，改用保留拓扑的内容修正，不能擅自加结局或减节点。

修正不消费其他前沿、不重抽签、不重排剩余队列；完成后按返回状态继续下一个待推进项。全部路径已闭合或已投影后也可修正；脚本把旧候选与验收存入repair-history，再按当前有效图重新投影和验收，不复制整套缓存重开一轮。正式结果只有重新通过双门禁后才替换，不能沿用修正前的通过标记。无法把矛盾修成真实因果时如实保留问题，不伪造通过。

### 过早结局与主线映射修复

`repair` 还允许把过早结束的 ending 改回 scene：节点 ID 和入边不变，在 FIFO 队尾重新开放该节点唯一后续前沿，继承原分支层数与抽签结果；随后正常 append 一步承接遗漏尾声，不重新生成其他节点。用户锁定形状或数量时仍保留拓扑，在现有节点内补齐。主线切片标注错误可以改为冻结输入中尚未被其他节点消费的切片 ID，但不能把支线改成主线或反之。

init 在生成任何节点前先验完整故事、连续切片与情绪绑定；发现输入问题只修对应上游文件再 init，此时不存在节点返工。生长开始后禁止删除 growth-state、修改已接受 steps、重建 nonce/hash 链或通过重跑整图绕过错误；应使用追加 repair 保留原节点和真实历史。

选择节点修正可以纠正问题与选项文字中的事实错误；保留选项数量、顺序、互斥动作本意和对应连接，不新增或删除选项。脚本按原 option_index 更新尚未消费前沿的 option_text，已存在边不变。不得借文字修正更换玩家原先选择的行为。
