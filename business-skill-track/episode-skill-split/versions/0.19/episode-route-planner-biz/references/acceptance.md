# 验收与局部恢复

## 主线不动，缺哪项补哪项

先运行 `route_plan.py status CACHE_ROOT`。状态指向缺少输入、冻结主线、首次提交、失败支线修复或作者顺读后验收。

- small/ending_types失败：从既有可用支线补完整结算，类型合计服从用户数量。
- crossing失败：在支线补足可以进入既有共同节点的完整故事，不硬连不相容剧情。
- depth失败：在支线已经发生的矛盾中补第二层抉择及完整后果。
- 其他图形失败：按具体节点与连接修复。

已通过的节点、连接与故事材料保留；只有确有问题才修改对应部分。不改主线原文、主线切片、主线路径及其节点，不降低门禁、不改短故事分类、不把困难支线砍成小结局逃避失败。

修复时复制当前topology-state.json里的bundle为提交内容，只修改受影响支线的完整故事/切片/图形。填当前expected_hash、具体reason和全部affected_nodes，再submit。脚本拒绝陈旧提交、超范围变更、主线变化和让已通过硬门禁退回失败的修订；每次成功修订保存前一版本。机器重新检查全图，不意味着作者重写通过项。冻结主线缺少合法出口、或用户要求真正冲突时，报告具体锁定位置或冲突；创作困难不是降低规则或追问用户的理由。

## 作者顺读与放行

冻结前先完成故事规划中的可理解性检查；图形PASS后作者沿各路线顺读故事切片：每段能交编剧展开，选择前未执行选项，回汇承接所有来路，结局完成结算，用户约束兑现。作者只修有问题的支线，不新建A/B或语义回执，不以机器PASS冒充内容质量证明。

```bash
python3 scripts/route_plan.py accept CACHE_ROOT
python3 scripts/route_plan.py verify CACHE_ROOT
```

真实独立行PLANNING_ACCEPTED才通过。需要正式对象时，accept另加FORMAL_ROUTE.json参数；只要求规划测试且未要求项目保存展示时不要加；用户同时要求平台画布时，交接已验收对象完成该项目展示后停止。

依赖单向：冻结输入 → 完整支线及图形版本 → 图形报告与原文投影 → 规划回执。机器检查不回写作者故事，修改支线使旧回执失效但不修改主线。直接改候选、伪造报告或沿用旧回执无效；verify重新计算图形和投影。保留真实失败、修复原因、版本数及耗时。

故事由作者负责，工程只负责图形、切片对应和交接完整性。代码不得补写剧情、评价文采或推断虚构状态。
