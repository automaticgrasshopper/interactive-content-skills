# 事件—过程链—场景展开

本文件只约束冻结梗概怎样成为正文，不改变故事、拓扑、梗概或正式业务字段。

## 一、三层不得混用

- 冻结梗概是`Event`：说明处境、戏剧目标和结果。
- 场面展开计划是写后独立建立的`Process Chain`：说明冻结结果本应怎样按时间一步步发生。
- 完整剧本是`Scene`：把每个过程演成同一时间地点内的动作、阻力、核验、回应和结果。

不得从完成后的正文倒找几句话反推过程链。Screenwriter与Enhancer完成并退出后，换一个不读取正文的工作区，只依据冻结梗概、正式资产和完整故事对应来源建立过程链并通过`plan`；随后另行拿过程链检查增强稿。

过程链只属于写后验收，不得转换成编剧材料，不得出现在连续故事输入、草稿、增强上下文、合并问题单或局部修复输入。正文可以合并信息、调整显露顺序和设计自然来回，但写后必须证明所有重大结果都有真实过程。不得为了方便举证把计划返回给编剧或Enhancer逐项补句，也不得由验收者改写增强稿。

## 二、过程链合同

每个事件按梗概原文顺序覆盖，并写明统一戏剧目标、起止状态、状态变化和`process_chain`。每个过程必须包含：

1. `scene`：已冻结场景；时间或地点改变时换场。
2. `actor`：实际执行动作的冻结角色，或确实由物理环境造成时写`环境`。
3. `trigger_or_basis`：执行者此刻为何行动，信息从哪里来。
4. `action`与`object`：谁对哪个冻结道具或允许状态做什么。
5. `resistance_or_verification`：动作怎样受阻、被质疑、被核验或未立即奏效。
6. `result`：位置、持有、权限、知情、风险、承诺、时间压力或关系实际改变了什么。

较长事件至少需要四个连续过程。过程数量不按字数凑；一个结果若跨越多个执行者、地点或重大状态变化，就继续拆，直到相邻过程之间不需要作者补因果。

## 三、资产可执行性

关键行动只能由正式角色或环境执行。银行、警方、法院、员工、客户等未登记主体不能在`action`或`result`里替作者自动完成封门、抓捕、签字、付款、接受或拒绝。确需其到场就退回上游登记角色和资产；不需要其出场时，把后果改写为正式角色在现场收到可见信息后采取的动作。

关键对象必须是冻结道具，或属于允许状态：现场空间、公开信息、人物关系、时间压力、经营权限、投资承诺、安全风险、资金状态。临时出现的证据袋、通知书、钥匙或合同不得承担结果。

## 四、正文证据

每个过程分别引用三处按顺序出现且不重复的正文证据：

- `action_proof`：执行者实际开始动作；
- `resistance_or_verification_proof`：阻力、质疑、失败或核验发生；
- `result_proof`：现场状态已经改变。

事件结束状态另举证，且必须晚于全部过程证据。任何过程只能靠一句结果旁白证明，或者不同过程复用同一句证据，均不通过。

以下均是梗概而不是戏：

- 公开账目后投资人当场撤资；
- 合同随后被收走；
- 银行接着封门；
- 人物决定、机构执行、结果成立之间没有可见接触、核验、阻力和回应。

近似搬运梗概与作者摘要检测只作辅助。核心判据是：所有重大结果都有完整过程链，且过程链能由正文逐项证明。

## 五、与独立冷读的边界

场面展开复检读取梗概、过程链和正文，只核对是否演出。通过后再执行独立冷读。独立冷读不得读取过程链，也不得替正文补全作者意图。

复检失败时只输出当前正文中的精确行号、原文锚点、问题类别和观众看不到的缺环；不输出替换句、过程字段、合格范文或逐项补写指令。问题进入合并问题单后，由局部修复门禁决定是否允许Enhancer修补。覆盖整集或暴露连续故事材料错误时，标记`rewrite_required`并停止局部修复。

有任一复检失败时，本复检另存`review-findings/<episode-id>.dramatization.json`：

```json
{
  "contract_version": "nextplay.episode-review-findings.v1",
  "episode_id": "episode-001",
  "source": "dramatization",
  "script_sha256": "当前增强稿正文SHA-256",
  "status": "FAIL",
  "rewrite_required": false,
  "issues": [
    {
      "issue_id": "D01",
      "category": "动作缺环",
      "start_line": 12,
      "end_line": 14,
      "anchor": "当前正文中的短原文",
      "reason": "只说明结果，没有演出阻力与人物调整。"
    }
  ]
}
```

本复检无问题但另一项失败时，同路径写`status=PASS`、`rewrite_required=false`和空`issues`，供合并门禁确认两个视角都已执行。
