# 单集故事适配

本文件只把冻结材料切成一段可直接改编的单集故事。它不写剧本，不建立过程链，不做质量举证。

## 输入与输出

只读取`episode-adaptation-sources/<episode-id>.json`，输出`episode-story-materials/<episode-id>.json`：

```json
{
  "contract_version": "nextplay.episode-story-material.v1",
  "episode_id": "episode-001",
  "source_sha256": "适配源规范化SHA-256",
  "story": "二至六个自然段组成的连续单集故事",
  "stop_boundary": "一句话说明本集必须停在哪里，以及后续独占的动作不能提前演出"
}
```

`story`是编剧唯一读取的故事内容，不是梗概复述、人物卡、过程表或分场表。它必须把梗概中的摘要动词还原成现场因果：人物怎样发现、第一次怎样尝试、现场怎样反馈、阻力怎样落地、人物怎样调整、哪项可见变化把故事推到停止边界。它用连贯自然语言把人物身份、关系、能力和语体融进事件。不得使用标题、编号、项目符号、字段名或逐人介绍，也不得用“根据现场反馈调整”“冲突继续升级”等抽象句代替实际发生的动作。

## 相邻分集切片

先比较当前梗概与所有直接后续梗概，再决定动作所有权：

- 当前集只拥有当前梗概明确要求已经发生的变化和到达状态。
- 后续梗概把某项动作作为主要冲突、完整核验、选择或结果时，该动作由后续独占；当前集只能建立前提、已有读数、口头报告或尚未执行的压力。
- 同一事实跨集重复时，区分“发现现状”与“主动验证”、“提出问题”与“执行选择”、“危险出现”与“处理危险”，不得在前一集预演后一集的完整作用—阻力—结果。
- 分支节点只演来源集自己的剧情，最后才呈现已冻结的玩家动作；普通节点不得提前把下一集选择写成当前选择。
- `stop_boundary`只说动作边界，不解释节点、拓扑和制作流程，也不替剧本写收尾句。

例：当前集只要求沈砚确认东闸卡锁，后续集以低功率脉冲核验并形成玩家选择为核心时，当前故事可以让她读取停滞回报码并听取现场撞击，停在钥匙尚未转动；不得在当前故事里主动发送测试脉冲。

## 连续故事

围绕一个贯穿本集的现场问题组织材料。各人物和信息必须被前一动作叫进来并改变下一动作，不能按“角色甲汇报—角色乙汇报—角色丙汇报”的顺序逐项盘点。

可以把远端信息作为声音或屏幕回传留在当前地点；若必须表现远端人物的可见动作，就在故事里明确发生地点变化，交给短底稿自然分场。不得在同一地点同时描写别处不可见的表演。

只使用正式资产和冻结事实。可补充不改变状态的天气、声音、停顿、接触、失败尝试和表演反应；不得增加新规则、唯一机会、额外倒计时、角色、道具、选择或结局。
