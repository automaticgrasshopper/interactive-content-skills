# 上游可见信息投影

## 唯一读取范围

第一步只读取两类材料：

1. 用户本轮明确提出并要求保留的内容。
2. 用户端已经展示的标题、一句话、大纲正文、故事体量，以及角色、场景、道具卡片。

可见卡片只取：

- 角色：`name`、`description`
- 场景：`name`、`description`
- 道具：`name`、`description`

不得读取、推断或保留卡片背后的工程字段、内部标签、设计分析和生成过程。

## 明确排除

以下内容即使存在于上游对象中也必须丢弃，且不得进入任何缓存、哈希材料、提示文本或错误消息：

- `node_count_hint`及任何节点数建议；
- 上游主题、关键事件、世界规则和结构建议；
- 上游结局预算、互动数量、情绪脊和分段方案；
- 未向用户展示的角色动机、功能标签、知情边界、能力边界和资产用途。

只有用户明确说“固定为 N 集”时，N才写入`user-intent-lock.json/fixed_episode_count`。不得从“建议N集”“大约N集”“适合N集”推导固定数量。

## 故事体量

`story_volume`原样保留用户端展示文本；缺失时为`null`，不追问。它只用于完整故事完成后的体量比较，不在写作前换算分钟、字数、集数、节点数或互动数，也不构成路线时长上限。

用户明确使用“必须”“固定”“控制在”等措辞锁定体量时，同时把原话登记为用户硬约束。仍不得提前换算节点预算；若自然故事无法满足，先报告不匹配并询问是否改故事或改体量。

## 资产使用

角色、场景和道具卡片共同组成可选资产池，不要求全部使用。使用时保留正式名称和卡片公开事实；可以为完整故事补足必要动机、行动和因果，但不得擅自创建新的正式资产或推翻卡片公开事实。

## 唯一缓存结果

第一步只保留：

```text
user-request.md
user-intent-lock.json
creative-brief.json
```

不得另建运行基础、资产目录、阶段二输入、角色首次出场登记或节点建议追溯文件。字段与命令以`workflow-and-stage-gates.md`为准。
