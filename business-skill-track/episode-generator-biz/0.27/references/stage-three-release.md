# 阶段三统一放行

本文件定义剧本集合从阶段三进入业务组装、路线投影、故事板和视频生产前的唯一硬闸，不增加正式业务字段。

## 一、为什么需要集合放行

逐集回执只能证明每一集在各自生成时通过。正式下游使用的是整套剧本中的`完整剧本`字段，不能用以下事实代替集合放行：

- 文件存在或九字段结构合法；
- 某一历史版本曾经PASS；
- 视频、故事板或时间线已经生成；
- 逐集回执中的哈希与正式路线采用不同对象却沿用同一字段名。

阶段三统一放行必须同时绑定：完整九字段分集文件、其中的完整剧本文本、逐集场面展开回执、逐集冷读回执、冻结梗概集合、拓扑和项目级语义复检。

## 二、双重哈希口径

每集必须同时记录：

- `episode_artifact_sha256`：`episodes/<episode-id>.md`整份九字段材料的字节哈希；
- `full_script_sha256`：从该材料确定性提取的`完整剧本`纯文本哈希。

任何回执、业务JSON或路线投影比较哈希时必须写明比较对象。不得再把整份材料哈希命名为含义不明的`script_sha256`，也不得拿两种哈希直接比较。

## 三、项目级语义复检

`stage_three_release.py packet`只在全体场面展开与逐集质量回执均有效时生成项目级复检包。独立复检必须覆盖：

1. 全集因果连续；
2. 核心目标兑现；
3. 情绪轨迹兑现；
4. 全部结局兑现；
5. 题材期待兑现；
6. 人话与对白一致性。

每项均引用当前完整剧本中的逐字证据，`全部结局兑现`必须覆盖每个结局节点。`人话与对白一致性`必须覆盖每一集，并为每集分别提供一条叙述证据和一条对白证据，证据项使用`kind: narration|dialogue`标明类型；不能用少数自然句替整集或整套剧本背书。发现问题时不得seal；返修任一正文后重新生成逐集回执和项目级复检包。

## 四、下游硬闸

只有当前有效的`stage-three-release.json`存在时，才允许：

- 组装九字段业务JSON；
- 保存业务结果receipt；
- 投影或覆盖正式route；
- 启动故事板、分镜或视频任务。

业务JSON组装后，必须再用`verify-projection`比较三处文本：

```text
阶段三完整剧本 == 九字段业务JSON完整剧本 == proposed/current route中的script.text
```

比较按每集`full_script_sha256`进行。任一集缺失、重复、文本不同，或者完成凭证、阶段三放行凭证失效，命令必须FAIL；FAIL时禁止提交route和启动任何媒体任务。

## 五、旧媒体处理

正文改变后，既有故事板、分镜和视频只视为历史资产，不得继续作为当前剧本的有效下游结果。优先保留其历史记录并从当前路线解除绑定；只有平台无法隔离失效媒体时才删除。不得为了保留旧媒体而绕过剧本放行。
