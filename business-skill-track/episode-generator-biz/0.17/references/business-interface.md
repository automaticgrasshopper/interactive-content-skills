# 业务接口声明

本文件是分集规划师与工程侧之间的唯一字段合同。工程按这里声明的字段名称、类型和层级取值；`episode-output-schema.md`负责字段内容和一致性要求，本文件负责接口结构。

## 接口规则

- 初次生成读取`游戏企划`、`角色描述`、`场景描述`、`道具描述`四个正式上游字段。
- 顶层输出固定为`分集列表`，每项严格使用九个一级字段。
- 每个分集对象对应一集完整剧情；选择问题、选项和默认下一分集只封装在该集的`互动节点`中，不另输出`选择节点`一级字段。
- 角色、场景、道具只使用上游正式名称或已登记别名，不输出资产工程 ID。
- 用户要求源快照、用户意图合同、冲突解决记录、履约证据、情绪脊、拓扑哈希、路径状态、资产索引、首次出场证据、正文哈希、复检包、复检回执、完成凭证、门禁状态、错误摘要和缓存路径都属于 Skill 内部验证数据，不是业务输出字段，也不要求数据库维护。
- 修改、重做、评审或恢复所需的已有完整结果、修改要求和允许修改范围是调用期控制输入，不改变正式业务输出结构。

## Skill 输入字段

### 初次生成

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `游戏企划` | object | 是 | 来自大纲生成师；包含标题、目标、冲突、世界观、体量和结局。内部的`剧情节点总数建议`为可选软区间，缺失不阻塞调用。 |
| `角色描述` | list<object> | 是 | 正式角色资产；至少包含主角及剧情必需角色。 |
| `场景描述` | list<object> | 是 | 正式场景资产；上游明确无正式场景时允许为空列表。 |
| `道具描述` | list<object> | 是 | 正式道具资产；没有关键道具时允许为空列表。 |

### 修改已有分集

修改、重做、评审或恢复模式在四项上游字段之外读取：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `已有分集结果` | object | 是 | 与本文件输出结构相同的完整当前结果，不接收局部片段作为基线。 |
| `修改要求` | string | 是 | 用户本轮要求。 |
| `允许修改范围` | object | 是 | 明确允许变化的分集编号及范围；纯台词修改使用`dialogue`范围。 |

## Skill 输出字段

```text
分集列表 list<object>
└─ 分集对象
   ├─ 分集编号 string
   ├─ 分集标题 string
   ├─ 分集剧本 object
   │  ├─ 单集梗概 string
   │  └─ 完整剧本 string
   ├─ 剧本分析 object
   │  ├─ 本集冲突 string
   │  ├─ 前置节点编号列表 list<string>
   │  └─ 后续节点编号列表 list<string>
   ├─ 关联角色 list<string>
   ├─ 关联场景 list<string>
   ├─ 关联道具 list<string>
   ├─ 是否结局 boolean
   └─ 互动节点 object
      ├─ 是否为分支节点 boolean
      ├─ 是否有选择问题 boolean
      ├─ 选择问题 string
      ├─ 选项列表 list<object>
      │  └─ 选项对象
      │     ├─ 选项编号 string | integer
      │     ├─ 选项文字 string
      │     └─ 目标分集编号 string
      └─ 默认下一分集编号 string
```

## 输出约束

- `分集列表`必须非空，并来自同一份已冻结创作拓扑。
- `分集编号`从`episode-001`开始连续编号；列表长度就是正式分集节点总数。节点总数仍须结合上游软区间、游戏体量、情绪脊、真实分支和结局需求在内部确定，但不作为输出字段重复写入每集。
- 每个分集对象都且只对应一个有完整剧情的分集节点，承载梗概、剧本、资产、结局和互动信息。
- `互动节点.是否为分支节点`与`互动节点.是否有选择问题`必须是原生boolean并保持一致。
- 每个有效选择只在来源分集的`互动节点`中出现一次。选择问题非空，至少两个选项指向不同分集；选择信息不含新剧本、资产、情绪坐标或结局内容。
- 每个选项严格使用`选项编号`、`选项文字`、`目标分集编号`；编号不重复，目标集合与该集`剧本分析.后续节点编号列表`完全一致。
- 分支节点的`默认下一分集编号`必须是其选项目标之一；无选择的普通节点必须等于唯一后续分集；结局节点必须为`无`。
- 无选择时，`是否为分支节点=false`、`是否有选择问题=false`、`选择问题`为空、`选项列表`为空。
- `分集列表`第一项和唯一入口必须是具有非空完整剧情的`episode-001`；若第一集带选择，必须先完整播完第一集正文，之后才能显示选择。
- 创建、修改、重做和恢复都返回当前完整结果，不只返回变化片段。
- 任一强验证门禁失败时，不得返回可被工程当作完成结果的业务对象，也不得把内部错误透传给用户。Skill 在私有空间返修并从最早失效阶段重跑；平台必须展示占位时只显示`正在生成中`。
- `分集列表`只能由业务组装器在全部门禁和三个公开文件通过后一次性写入，并生成不属于业务字段的私有完成凭证。生成、验证和修复期间不得逐节点写入页面。重做必须整组替换旧节点与边，禁止追加或合并中间拓扑。

## 持久化与展示边界

- `分集列表`是正式九字段业务数据。选择信息只有`互动节点`这一份业务事实源，不得复制为第二个业务对象。
- 路线投影只能使用Skill内置确定性投影器。投影器必须从当前缓存重跑完整门禁、重建并逐值核对业务 JSON、验证私有完成凭证；单独通过字段结构校验不得投影。投影中的剧情节点数量必须等于`分集列表`长度；选择数量必须等于`互动节点.是否有选择问题=true`的分集数量；预计可视节点总数等于两者之和。
- 网页路线数组第一项、`entry_node_ref`与唯一入度为0的节点必须是同一个非空剧情节点。路线内剧情卡与选择卡统一取得连续且不可二次改写的`episode_ref`；业务分集编号保存在剧情节点metadata，路线层派生的`choice-xxx`保存在选择节点metadata与interaction。路线不得输出工程合同未声明的`settings`。
- 路线choice节点必须保留非空`content.script.text`与`after_plot_beat`。播放器先展示剧情，再展示问题和选项；拓扑视图不得隐藏该节点的剧情信息或从选择目标重新生成序号。
- 剧情节点固定使用`node_type=video`并禁用interaction；独立选择节点固定使用`node_type=choice`并启用interaction。二者不得合并为同一记录，也不得用metadata逻辑标记代替工程节点类型。
- boolean字段保持JSON原生boolean并按boolean判断。禁止把`true/false`与`是/否`字符串比较或静默转换。
- 本合同是调用期接口，不要求为内部校验数据新增数据库字段；选择节点是否独立持久化由工程实现决定，但业务侧选择只有`互动节点`这一份事实源。
- 业务输出中没有面向玩家的摘要字段，也没有内部验证结果。前端和玩家只消费公开投射，不展示内部 Reference、门禁、哈希、回执或缓存。
- 用户前后明确要求无法同时成立时，Skill 通过 AskUser 取得选择后才继续；冲突问题和解决记录不进入正式九字段。
