# 分集输出结构与内容规则

生成、修改或验证分集结果时读取本文件。字段名称、类型和层级以`business-interface.md`为唯一接口定义；本文件补充内容要求和字段间一致性。

## 顶层结构

正式结果只包含`分集列表`：

```json
{
  "分集列表": [
    {
      "分集编号": "episode-001",
      "分集标题": "示例结局",
      "分集剧本": {
        "单集梗概": "角色甲完成本轮目标，并承担选择造成的结果。",
        "完整剧本": "【示例场景·白天·内】\n角色甲把示例道具交到桌上。\n角色甲：这件事到这里结束。"
      },
      "剧本分析": {
        "本集冲突": "角色甲必须完成目标并承担结果。",
        "前置节点编号列表": [],
        "后续节点编号列表": []
      },
      "关联角色": ["角色甲"],
      "关联场景": ["示例场景"],
      "关联道具": ["示例道具"],
      "是否结局": true,
      "互动节点": {
        "是否为分支节点": false,
        "是否有选择问题": false,
        "选择问题": "",
        "选项列表": [],
        "默认下一分集编号": "无"
      }
    }
  ]
}
```

示例只说明结构，不是金标内容，不得复制示例人物、场景或道具进入真实项目。

## 九字段分集对象

每集严格按以下顺序使用九个一级字段：

1. `分集编号`
2. `分集标题`
3. `分集剧本`
4. `剧本分析`
5. `关联角色`
6. `关联场景`
7. `关联道具`
8. `是否结局`
9. `互动节点`

固定子字段：

- `分集剧本`：`单集梗概`、`完整剧本`
- `剧本分析`：`本集冲突`、`前置节点编号列表`、`后续节点编号列表`
- `互动节点`：`是否为分支节点`、`是否有选择问题`、`选择问题`、`选项列表`、`默认下一分集编号`
- 每个选项：`选项编号`、`选项文字`、`目标分集编号`

用户明确指定的`分集标题`是最高优先级硬事实：原样保留，不检测长度、不追问、不评价、不润色。用户未指定标题时，自行生成不少于2个字符的非空标题；标题不设长度上限。

不得增加、删除、改名、换序或使用英文键替代。`分集数`、`选择数`和`选择节点`都不属于正式业务字段，不得输出。冻结拓扑的分集数量由路线级拓扑完成后的因果展开确定，并等于`分集列表`长度；上游`剧情节点总数建议`只在阶段一记录来源，缺失不阻塞，也不进入阶段二生成上下文。

## 互动字段一致性

带选择的分集使用下面的标准结构：

```json
"互动节点": {
  "是否为分支节点": true,
  "是否有选择问题": true,
  "选择问题": "本集剧情播完后，玩家要怎么做？",
  "选项列表": [
    {"选项编号": "1", "选项文字": "行动一", "目标分集编号": "episode-002"},
    {"选项编号": "2", "选项文字": "行动二", "目标分集编号": "episode-003"}
  ],
  "默认下一分集编号": "episode-002"
}
```

- 唯一入口为`episode-001`；全部分集节点可达、无环并能抵达至少一个结局。
- `是否为分支节点`与`是否有选择问题`必须是原生boolean并同时为真或同时为假。
- 每个有效选择恰好出现一次；问题非空，至少两个选项指向不同分集。
- 每个选项严格使用`选项编号`、`选项文字`、`目标分集编号`；编号不重复，文字非空，目标集合与`剧本分析.后续节点编号列表`完全一致。
- 分支节点的`默认下一分集编号`必须是选项目标之一。
- 非分支、非结局节点不得含问题或选项，且`默认下一分集编号`必须等于唯一后续分集。
- 结局节点不得含问题或选项，`默认下一分集编号=无`，后续节点列表为空。
- 选择问题与选项只存在于`互动节点`，不得复制进剧本正文、另一个一级字段或第二个分集对象。
- `分集列表`第一项必须是`episode-001`且`完整剧本`非空；若它带选择，选择只能在该集正文播完后出现。禁止空剧情直接出选项。
- 预期结局总数、正式结局数和失败结局数必须与游戏企划一致。

## 剧本与资产一致性

- `单集梗概`只能概括本集`完整剧本`实际演出的事件，必须用自然语言独立说清人物面对的问题、本集实际变化和下一入口；不得把未演出的前史、未来结果、作者解释或其他分集内容当成本集剧情。
- 完整剧本至少包含一个`【场景名称·时段·内/外】`格式的场次标题。
- 对白使用`人物：台词`，不加台词引号。
- 正文不含`△`、`出场：`、镜号、景别、机位或运镜说明。
- `关联角色`、`关联场景`、`关联道具`只使用正式资产名称，分类内不重名。
- 关联资产与正文实际出现内容双向一致；角色首次出场满足独立的全路径审计。

## 修改一致性

- 使用基线修改时必须声明允许变化的分集。
- 局部修改期间冻结拓扑不得变化。
- 未授权分集必须与基线逐字段一致。
- `dialogue`范围内，授权分集只能修改对白文字；非台词正文、事实、动作、状态、九字段、选择和结尾不得变化。

## 内部验证边界

情绪脊、资产索引、首次出场证据、哈希、逐集复检包、回执和完成凭证仅供脚本强验证，不得加入正式结果。强验证失败时停止完成态输出，在私有空间返修并重跑；不得把内部失败过程写入业务 JSON 或用户可见消息。

正式业务对象采用提交屏障：生成期间只操作私有缓存，不提前返回局部分集；全部阶段门禁通过后，只由业务组装器一次性写入完整`分集列表`并生成私有完成凭证。重新拓扑时整组替换当前结果，不把旧拓扑与新拓扑混合。
