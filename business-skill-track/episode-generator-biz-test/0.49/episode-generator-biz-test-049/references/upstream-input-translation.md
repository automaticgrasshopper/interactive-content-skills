# 上游资料整理

## 读取范围

完整读取游戏企划。角色、场景和道具只提取分集规划与写作需要的正式信息：

- 角色：名称、身份、目标、人物变化、人物关系、外貌和说话方式。
- 场景：名称、空间性质、可用状态和固定关系。
- 道具：名称、固定外观、剧情用途和状态变化。

## 整理原则

- 先建立`用户锁定约束`：逐条保留用户最新且明确指定的主线、人物关系、世界规则、关键事件、选择、结局和禁改范围。用户明确要求优先于上游生成建议、Skill默认偏好和结构启发式。
- 将大纲的`剧情节点总数建议`原样记录到阶段一`node_count_hint`供来源追溯，不换算、不执行，也不放入阶段二生成包。只有用户明确要求固定为N集时，才把该硬数量写入用户意图合同。
- 将大纲的体量或推荐时长只记录到阶段一`duration`供来源追溯；缺失时写`null`，不追问。它不进入阶段二生成包，不限制单条路线，也不参与拓扑验收。
- 合并重复说明，不另造人物、地点、道具、能力规则和前史秘密。
- 把抽象主题转成角色可以遭遇的事实，但不提前写场次和对白。
- 出现冲突时按`用户最新明确要求 > 用户较早要求 > 正式上游事实 > Skill默认偏好`处理。不得用“更合理”“更适合”或重新拓扑为由删改用户锁定内容。
- 只有安全边界、正式输出合同或客观不可实现与用户要求直接冲突时，才停止并指出具体冲突、保留原要求、提出最小追问；不得静默替换成另一套方案。节点建议区间缺失、表述模糊或与结构推导存在轻微偏差时不追问。

## 私有冻结结果

把整理结果写入`run-basis.json`与`asset-catalog.json`。字段和门禁以`run-basis-and-stage-gates.md`为准；不要另建一份内容重复的制作参考。

`run-basis.json`只保留：

```text
项目标题与一句话概述
主角目标与核心冲突
时代地点与世界规则
正式角色及关系
正式场景
正式道具
节点数量建议区间（可选；缺失时写`未提供，由分集阶段推导`）
结局数量与方向
必须保留的关键事件
安全与一致性限制
```

整理完成并通过阶段一门禁后，情绪脊和拓扑只读取冻结结果，不反复携带原始输入全文。若冻结结果与用户要求或正式上游资料冲突，返回阶段一修正，不在下游偷偷改写。

节点数量建议只是来源记录，不是输入门禁、软目标或最终数量合同。`12–15个`、`12到15集`等写法可以统一记为`[12,15]`，但不得进入阶段二，也不得影响拓扑形状。只有用户明确使用“固定”“必须”“恰好”等措辞指定 N 集时，才把 N 作为硬约束。

只有用户明确固定的集数才约束有剧情、有完整剧本和情绪脊坐标的分集节点。未固定时，完成真实分支规划后统计拓扑中的唯一可演戏剧单位，冻结为确定的剧情分集数量，并由`resolved_node_count`与`分集列表`长度共同体现；正式业务结果不再逐集重复输出`分集数`。选择信息不计入该值，也不回写上游建议集数。
