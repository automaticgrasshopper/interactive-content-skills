# 分集业务输入规则

## 固定接收字段

初次创建必须接收以下四个一级字段，字段名不得改写：

1. `游戏企划`
2. `角色描述`
3. `场景描述`
4. `道具描述`

修改、重做、评审或恢复时，除四项上游事实外，还接收当前完整分集结果和本轮允许修改范围；它们是任务上下文，不改变上述四项正式上游字段。

## 游戏企划

完整读取：

- 游戏标题
- 一句话概述
- 游戏核心目标
- 游戏关键词
- 时代与地点
- 玩家身份与视角
- 剧情整体描述
- 游戏核心冲突
- 游戏世界观
- 游戏基调与情绪
- 游戏主题
- 游戏体量
- 推荐结局数
- 结构信息：游戏结构类型、剧情节点总数建议、结局构成、主线情绪变化、给分集的重点提醒
- 待确认问题

## 正式资产

- `角色描述`：完整读取正式角色名、身份、关系、目标、驱动力、人物弧光、外貌、声音气质、固定特征、允许变化状态、必须保持一致和相关资产。优先覆盖主角、主要关系对象、目标对手、反派和关键配角。
- `场景描述`：完整读取正式场景名、空间描述、布局、识别元素、叙事功能、固定空间关系、允许变化状态、必须保持一致和相关资产。字段必须存在；若上游明确无正式场景，可为空数组。
- `道具描述`：完整读取正式道具名、形象、意义、固定外观、允许变化状态、必须保持一致和相关资产。

正文、关联资产和验证索引只能使用这些正式名称或登记别名，不得临时创造未入资产的角色、场景或关键道具。

## 整理原则

- 保留用户明确指定的主线、人物关系、世界规则、节点建议、结局数量和结局方向。
- 合并重复说明，不另造人物、地点、道具、能力规则和前史秘密。
- 把抽象主题转成角色可以遭遇的事实，但不在输入整理阶段提前写场次和对白。
- 冲突时优先采用更具体、更新且明确确认的输入。
- 冲突会改变主角目标、人物关系、世界规则、节点总量或结局时，停止并只提出一个最关键问题。
- 除上述阻塞冲突外，不要求用户逐阶段确认，主动完成完整工作流。

## 上下文压缩

输入整理后只保留以下紧凑制作参考进入结构阶段：

- 项目标题与一句话概述
- 主角目标与核心冲突
- 时代地点与世界规则
- 正式角色及关系
- 正式场景
- 正式道具
- 节点数量建议
- 结局数量与方向
- 必须保留的关键事件
- 安全与一致性限制

不要在后续每一步重复携带原始输入全文。
