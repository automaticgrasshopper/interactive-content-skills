# 第一版可读故事写作

本步骤只把已经冻结的上游事实写成一篇普通读者可以连续读完的单路线故事。它不规划分集、节点、分支形状或互动数量。

## 唯一输入

写作者只读取已通过`validate_mainline_story_input.py`的`mainline-story-input.json`。该文件除合同与来源指纹外只含六组创作信息：

1. `title`：标题。
2. `core_event`：主角、触发事件、当前目标、主要阻力和失败代价。
3. `story_boundaries`：会实际约束因果、安全或一致性的硬边界。
4. `required_story_facts`：本故事必须发生或最终还原的事实。
5. `essential_assets`：本条故事实际需要的人物、场景和道具及其当前作用。
6. `expected_payoff`：类型体验、基调和期待性结局方向。

使用以下私有合同；`stage_two_input_sha256`取`stage-two-input.json`规范化JSON的SHA-256：

```json
{
  "contract_version": "nextplay.mainline-story-input.v1",
  "stage_two_input_sha256": "规范化来源指纹",
  "title": "冻结标题",
  "core_event": {
    "protagonist": "主角",
    "inciting_event": "迫使故事开始的具体事件",
    "goal": "逐字冻结的核心目标",
    "opposition": "主要阻力",
    "stakes": "拖延或失败的代价"
  },
  "story_boundaries": ["合并后的世界、安全与一致性硬边界"],
  "required_story_facts": ["必须发生或最终还原的事实"],
  "essential_assets": {
    "characters": [{"name":"正式名","public_role":"公开身份","current_motive":"当前动机","key_relationship":null}],
    "scenes": [{"name":"正式场景名","story_function":"当前故事作用"}],
    "props": [{"name":"正式道具名","story_function":"当前故事作用"}]
  },
  "expected_payoff": {
    "genre": "主要类型体验",
    "tone": "基调",
    "ending_direction": "逐字选取的期待性结局方向"
  }
}
```

不得读取或引用原始游戏企划、`run-basis.json`、`stage-two-input.json`、完整资产描述、未编号情绪运动、分集数量、节点建议、结局数量、互动区间、切片规则、拓扑规则、旧梗概或旧正文。用户硬约束已经进入六组信息时按其执行；没有进入的资料只作为后续结构或分集写作材料，不得为覆盖资产而塞进故事。

## 写作标准

- 从一个正在发生的具体异常、欲望或行动开始，沿行动、阻力、调整、发现、关系变化和结算连续推进。
- 只在当前动作需要时引入身份、关系、世界规则、场景和道具。人物出现不等于立即交代其全部背景、秘密和最终作用。
- 每段承担一个主要理解任务；新事实必须改变人物的判断、行动、关系或局面，不能连续登记设定。
- 关键真相由人物行动、可见证据、冲突和反应逐步得出；不得把谜底、人物底牌或上游标签直接改写成作者说明。
- `required_story_facts`必须全部兑现，但“完整”只指核心因果闭合，不要求穷尽上游资料。
- 不写“如果、或者、玩家可以、选择A/B”等分支语言，不提前编号，不为未来切片预制段尾，不写结构说明。
- 完稿应当先作为一篇故事成立。冻结后如何切成主线梗概，由下一步骤只按原文自然边界处理。

出现以下任一情况时不得冻结：

- 开头依次介绍人物、场景和道具后才开始发生事件；
- 连续使用身份标签、关系标签或资产用途替代人物行动；
- 一段同时登记多名人物、多个道具和多个背景事实，却没有局面变化；
- 关键真相只被宣布，没有形成可追踪的发现过程；
- 删除角色姓名与资产名称后，剩余文本只是企划摘要或事实清单。
