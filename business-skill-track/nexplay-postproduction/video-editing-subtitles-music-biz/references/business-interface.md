# 业务接口声明

本文件是视频后期 Skill 与调用方之间的业务字段合同。原有视频后期输入输出保持兼容，新增单独音乐素材模式；先按用户目标选择模式，不要求单独作曲提供视频后期字段。它只声明正式输入、正式输出和允许处理的业务范围，不声明工程实现方式。

## 接口规则

- 用户可见字段使用中文；URL、资产引用和分集、分镜编号可以保留工程提供的值。
- 字段名称、类型和层级必须与本合同一致，不使用同义字段或工程内部字段替代。
- `分集编号 + 分镜编号`是后期处理对象的业务定位；URL 只表示需要读取或交付的内容。
- 输出沿用输入中的分集编号和分镜编号，不因裁剪、拆分、插入、替换或组装重新编号。
- 可选字段没有值时使用`null`或空列表，不虚构内容。
- 运行过程、临时文件、检查记录和工程内部数据不进入正式输出。

## 视频后期输入字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `分集编号` | string | 是 | 当前处理的正式分集编号。 |
| `分集剧本` | string \| null | 按需 | 涉及剧情、台词原意判断时读取；缺少剧本不阻止可凭实际视频完成的操作。 |
| `分镜视频生成prompt` | object \| null | 按需 | 与分镜编号对应的描述和 Prompt；不作为所有后期任务的统一门槛。 |
| `分镜视频` | object | 是 | 当前分集已经生成的视频列表。 |
| `用户要求` | string | 是 | 本轮后期处理目标、范围和需要保留的内容。 |
| `附件` | list<object> | 否 | 用户提供的字幕、图片、视频、背景音乐或其他后期素材。 |
| `游戏企划` | object \| null | 否 | 标题、世界观、人物介绍或整集表达需要的项目信息。 |

### 输入字段层级

```text
分镜视频生成prompt object
└─ prompt列表 list<object>
   ├─ 分镜编号 string
   ├─ 分镜描述 string | null
   └─ prompt文本 string | null

分镜视频 object
└─ 视频列表 list<object>
   ├─ 分镜编号 string
   └─ 视频URL string | null
```

`prompt列表`与`视频列表`中的相同`分镜编号`表示同一个用户可见分镜。目标分镜的`视频URL`为空时，不能执行依赖现有视频的后期处理。

## 视频后期输出字段

```text
后期处理结果 object
├─ 分集编号 string
├─ 处理分镜列表 list<object>
│  ├─ 分镜编号 string
│  ├─ 完成内容 list<string>
│  └─ 结果引用 string | null
└─ 完成说明 string
```

## 输出约束

- 视频后期模式顶层只允许`后期处理结果`。
- `处理分镜列表`只包含本轮实际完成处理的分镜，并沿用输入中的顺序和编号。
- `完成内容`使用简明业务语言说明已经完成的字幕、裁剪、组装、背景音乐或标题处理，不记录实现步骤。
- `结果引用`保存调用方提供的可用结果地址或资产引用；没有独立结果引用时为`null`。
- `完成说明`概括整轮交付结果，不填写排队、处理中、重试等运行状态。
- 只有完成检查全部通过时才输出正式结果；失败、等待输入或尚未完成时不输出可被当作完成结果的对象。

## 允许处理的范围

- 本 Skill 可以处理输入中已有分镜视频的画面与原声、背景音乐、字幕、顺序和标题内容；用户要求配乐时，可为目标视频生成并采用新的背景音乐。
- 本 Skill 不修改分集编号、分镜编号、分集剧本、分镜描述或互动关系；保留素材库原始资产，可通过正式保存入口新增本轮音乐素材，不覆盖无关资产。
- 工程如何保存和展示后期结果不属于本合同。

## 工程排版交接（非完成结果）

字幕布局按[统一请求](subtitle-layout-handoff.md)处理：一片段一份原MCP外层完整JSON，style为对象，保留font_size，不使用subtitle_style，不重复发送MCP七字符串布局。姓名与身份分别占独立轨道，布局与同步规则见[介绍排版](intro-layout.md)。先查询当前目标，保留未改内容、时间与其他轨道，接收/保存/实际渲染分别验收。

## 单独音乐素材模式

用户只要求作曲、准备音乐或存入素材库时使用；不要求分集或镜头存在。不把音乐文件伪装成已处理分镜。混合请求中先完成可独立执行的作曲部分，再按视频后期条件判断是否可入轨。

输入：`用户要求`必填；`游戏企划`和`附件`按需读取，可以使用已有大纲、明确的风格或情绪要求。项目身份沿用当前环境的正式上下文，不自建虚假分集。确实没有可定位的项目或素材保存位置时，先补齐保存依赖，不谎称已经存入素材库。

本模式的业务结果为：

```text
音乐素材结果 object
├─ 音乐素材列表 list<object>
│  ├─ 名称 string
│  ├─ 完成内容 list<string>
│  └─ 结果引用 string
└─ 完成说明 string
```

结果引用必须能读回到本轮已保存的可用素材；检查通过才交付该模式正式结果。仅取得音频链接但未完成用户要求的素材库保存时，说明阶段成果，不输出误导性的完成对象。已有下游消费者只接受视频后期结果时，不把此新增对象硬塞旧解析器；使用前端交互桥支持的消息与真实素材引用交付，并明确保存状态。引导记录、询问卡片和待答状态属于运行交互，不属于上述两类完成结果。
