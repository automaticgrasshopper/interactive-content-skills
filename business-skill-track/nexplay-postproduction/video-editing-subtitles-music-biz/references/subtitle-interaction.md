# 字幕询问与选择

首集全部视频首次保存完成时只输出一次能力提示，不发问；全项目完成提示暂不启用。用户主动要求添加字幕后，确认尚未明确的世界观和人物介绍选项；已指定只要对白、三种都要或其他明确范围时直接通过 MCP 写入可编辑字幕轨，不再询问“写入视频／仅出文案时间码／新增介绍画面”等交付方式；用户明确指定导出或其他方式时按其要求处理。字体未指定沿用实际可用字体，样式按[工程排版交接](subtitle-layout-handoff.md)处理。

## Agent剪辑已有字幕时

用户通过聊天剪辑视频且当前已有字幕、尚未说明是否处理时，AskUser简短询问“剪辑时要一起处理字幕吗？”。提供可提交的“处理字幕”和“不处理，只剪视频”。明确已有答案不重复问；用户在剪辑界面的手动操作不由此规则追加聊天门禁。处理时按[timeline_edit](timeline-mcp.md)独立更新字幕，必要识别由实际语音能力完成；不处理则整条字幕轨内容、时间和样式不动，说明可能不再与剪后视频同步，不自动识别或删除文字。

## 什么时候问

| 当前请求或状态 | 交互 |
|---|---|
| 第一集镜头全部正式完成、尚未引导 | 按完成提示参考直接输出一次普通消息；不提问、不自动执行 |
| 用户明确要对白字幕、指定语言或只改某项 | 直接做指定内容；不再问是否生成，不强加世界观/人物介绍 |
| 用户点击或回复“添加字幕”，附加介绍尚未确定 | 询问是否同时添加世界观和人物首次出场介绍；语言仅在需求不明且影响结果时确认，已确定项不重问 |
| 用户明确要游戏标题 | 正式项目名、自动空镜/黑屏模式、默认3秒；已知细节不重问，普通字幕不自动加标题 |
| 用户明确开启人物介绍 | 采用姓名必填、身份选填、默认3秒；不反复询问每个角色是否需要介绍 |
| 用户明确开启世界观 | 在已有视频中提炼并放置，不再次问是否添加，不生成补视频 |
| 用户要补世界观但当前没有介绍 | 仅在现有视频找位置，安全可放就执行 |
| 世界观缺理想留白 | 按介绍排版调整语义换行与现有开场时段，在左右上角附近选择合适留白并保留指定字号；无法满足时报告限制，不生成视频、不烧录 |
| 没有可靠的设定联系或悬念来源 | 只保留理解开场所需的已确认背景或事件；不编造联系或悬念，不让用户返工原片 |

用户主动要求添加字幕、范围未明确时的问题文案可使用：

- 世界观开场：“要不要在开场用约5秒交代必要背景或眼前事件与悬念？”选项为“添加／不添加”。
- 人物介绍：“要不要同时添加所选范围内的人物首次出场介绍？姓名必填，身份可省略，默认3秒。”选项为“添加／不添加”。
- 语言：“对白字幕使用哪种语言？”提供“中文／中英双语”，其他语言使用当前工具支持的输入方式；整套字幕双语时人物姓名与已有身份一并翻译；只要求对白双语不扩展范围。

## 世界观只放已有视频

用户授权世界观介绍后，按[世界观规则](worldview-opening.md)区分宏大背景、局部特殊设定与生活化引入，提炼对应内容并决定默认语言，用户要求优先。按[介绍排版](intro-layout.md)在左右上角附近选择不挡主体的留白，各显示行独立worldview轨道，始终视觉左对齐，中文40px、需要时译文30px，完整文字框在安全区内且同步显示，与人物介绍错开。留白不足先换侧、精简非必要内容、语义换行或调整现有开场时段，保留指定字号；不提供生成选项、不烧录、不插新镜头，用户指定原文保留。

## 可靠地发问与恢复

调用前读取当前 AskUser 工具与前端交互桥合同，采用真实支持的单选/多选结构，选项必须是可提交的控件，不能只把答案写在说明里。旧版环境曾出现 boolean 无控件的失败，不原样套用旧 payload；用当前支持且确实可提交的明确选择。

发问成功后保存实际交互标识与待答状态，用户选择后继续对应范围。卡片缺选项、工具失败或结果不明不算有效提问；先核实原交互，避免重复投递，不能声称正在等一个无法回答的卡片。未回答不视为同意或跳过。用户跳过则结束对应选择，不再追问剩余偏好。

只等待依赖此选择的任务，其他已授权且独立的工作可继续；不设置整个项目必须等字幕才可继续的门禁。记录作者的本次选择，不维护玩家观看分支或角色状态。
