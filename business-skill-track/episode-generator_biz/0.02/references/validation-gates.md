# 分集强验证流程

本文件规定返回业务 JSON 前必须执行的门禁。业务规则由对应 Reference 定义，脚本提供确定性执行；不能用“人工看过”替代脚本可以验证的事项。

## 一、结构门禁

在写正文前验证：

- 分集编号连续且不重复。
- 唯一入口为`episode-001`。
- 所有节点可达，拓扑无环。
- 结局没有后继；非结局至少有一个后继。
- 所有节点都能抵达至少一个结局。
- 选择至少有两个不同目标，选择目标与后继完全一致。
- 非选择节点不含选项。
- 预期结局总数、正式结局数、失败结局数与企划一致。

情绪脊同时验证：

- 合同为`nextplay.emotional-spine.v1`。
- 节点顺序与冻结拓扑完全一致。
- V、A、D 均为负一到正一数值。
- 拐点为布尔值，真实拐点有理由。
- 情绪脊与拓扑绑定一致。
- 每个选择节点对应`turn=true`。

以上由`validate_emotional_topology.py`在正文开始前执行。只有实际返回`PASS`后才能冻结拓扑，并把`情绪脊与拓扑`门禁登记为通过；不得根据模型自述登记。

## 二、逐集质量门禁

每集台词复写后：

1. 生成与当前正文和当前复检规则绑定的复检包。
2. 填写人物任务、触发代价、行动结果、下一入口四项理解门及正文证据。
3. 覆盖事实来源与知情、首次出现与必要交代、因果相邻与可见后果、话茬与现场目的、口语组织与反过度压缩、普通话表达与叙述可读、结尾画面与下一入口。
4. 普通话项分别提供台词和非台词描述证据。
5. 问题必须为空；正文或复检规则变化后原结论失效。

逐集复检使用`episode_quality_gate.py`生成复检包、封存结论并整体验证。只有所有最终正文都拥有当前有效结论时，才能把`逐集质量`门禁登记为通过。

## 三、角色与资产门禁

- 资产索引合同为`nextplay.episode-assets.v1`。
- 角色、场景、道具均为合法非空字符串，分类内不得重名。
- 可选角色必须属于正式角色；别名只能归属于一个正式角色。
- `关联角色`只能使用正式名称，并与完整剧本中的正式名或登记别名双向一致。
- 非可选正式角色至少实际出场一次。
- 首次出场审计合同为`nextplay.character-introductions.v1`。
- 按真实拓扑路径计算首次出场；互斥路线可产生多个首次出场节点。
- 每个首次出场节点必须有不同的身份、关系、当下作用逐字证据，且可在正文定位。

以上由`validate_character_appearances.py`执行。只有实际返回`PASS`后，才能把`角色与首次出场`门禁登记为通过。

## 四、九字段与拓扑一致性门禁

- 每集九个一级字段和全部子字段必须齐全、无多余字段且顺序固定。
- 分集编号、标题、前置节点、后续节点和结局标记与冻结拓扑一致。
- 分支布尔值、是否有问题、选择问题、选项编号、选项文字、目标分集和默认下一集一致。
- 非分支节点不得带问题或选项；结局的默认下一集为无。
- 关联场景和关联道具只能使用正式资产名。
- 完整剧本至少包含一个`【场景名称·时段·内/外】`场次标题。
- 对白使用`人物：台词`，不得加台词引号；不得混入`△`、`出场：`、镜号、景别或运镜。

最终业务 JSON 由`validate_business_output.py`验证接口顶层、结构、九字段、资产、选择、结局和图关系。只有实际返回`PASS`后，内部运行状态才能把`九字段与全剧`门禁登记为通过。门禁状态只存在于本轮私有验证上下文，不写入业务 JSON。

## 五、修改范围门禁

- 使用基线修改时必须声明允许变化的分集。
- 冻结拓扑必须与基线一致。
- 未授权分集必须与基线一致。
- `dialogue`范围内，授权分集的非台词内容也必须与基线一致。

修改任务在最终业务校验中同时带基线与允许变化分集执行。实际返回`PASS`后，内部运行状态才能把`修改范围`门禁登记为通过。

## 六、最终合同复核

- `分集结构`与`分集列表`来自同一冻结拓扑和最终正文。
- 两处重复字段完全一致。
- 内部情绪脊、资产索引、首次出场证据、哈希、回执和路径信息不得进入业务 JSON。
- JSON 顶层、分集结构和九字段全部符合`business-interface.md`与`episode-output-schema.md`。
- 任一门禁失败时返回`部分完成`、`待补充`或`失败`及真实错误，不得伪报完成。

正式业务 JSON 不承载状态、错误或门禁。上述失败信息只通过运行时错误通道返回；不得生成带`工具结果`、`摘要`、`哈希`或`回执`的替代业务对象。

## 七、不可跳过顺序

门禁状态只允许按以下顺序推进：

`输入冻结 → 情绪脊 → 拓扑绑定与冻结 → 逐集写作 → 台词复写 → 逐集质量 → 角色与首次出场 → 九字段与全剧 → 业务合同`

- 情绪脊或拓扑失败时，不得写正文。
- 台词复写未完成时，不得生成逐集复检包。
- 任一分集复检失败时，不得执行全剧完成态校验。
- 角色首次出场或九字段失败时，不得交付正式业务 JSON。
- 只有全部门禁在本轮真实执行并通过后，才允许把正式业务 JSON交给技术 adapter。
