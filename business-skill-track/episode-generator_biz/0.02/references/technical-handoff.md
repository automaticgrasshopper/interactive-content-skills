# 技术接入与公开投射

本文件说明业务结果之外的技术责任，不作为业务运行时返回，也不由业务 Skill 加载。技术侧只以`business-interface.md`为稳定字段接口。

接口是调用期约定，不等同于数据库 Schema。技术侧无需持久化门禁结果、派生结构或任何内部验证材料；只需接收已经通过本轮全部强验证的正式结果、投射公开文件，并按现有产品定义保存九字段业务数据。正式结果本身不含`工具结果`、摘要或门禁字段。

## 公开文件

画布一级目录只保留：

- `episode-flowchart.svg`：真实分集、选择、结果、汇合和结局。
- `episode-structure.md`：只含分集编号、标题、类型、单集梗概和玩家可见跳转。
- `episode-script.md`：全部九字段分集结果组成的完整剧本。

三份文件必须来自同一份已通过门禁的`分集结构`和`分集列表`并位于同一公开目录。公开目录不得包含第四个文件或子目录；尤其不得创建`cache/`。技术 adapter 必须拒绝内部目录位于公开目录、输出文件名不固定、三个输出不在同一目录、公开目录已有其它内容，或正式结果不符合业务接口。

## 私有内容

上游整理、情绪脊、因果链、路线状态、逐集草稿、检查过程、证据、哈希和修复记录只存在于业务 Skill 的临时验证空间，不写入业务 JSON或玩家可见目录。用户明确要求调试时可以展示结构化结论，但不展示路径、哈希、逐字内部思维或内部 Reference。

## 进度

技术 UI 只使用简短状态：

- `正在整理上游资料`
- `正在生成分集拓扑、结构与流程图`
- `第 N/M 集正在写作`
- `正在检查全剧事实与九字段`
- `正在生成公开文件`

不要公开缓存路径、内部判断、字数、动作数量、审稿记录、逐字证据或修复过程。
