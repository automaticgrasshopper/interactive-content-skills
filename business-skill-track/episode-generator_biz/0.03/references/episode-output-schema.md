# 分集输出结构与内容规则

生成、修改或验证分集结果时读取本文件。字段名称、类型和层级以 `business-interface.md`为唯一接口定义；本文件补充内容要求和字段间一致性。

## 顶层结构

正式结果只包含：

1. `分集结构`
2. `分集列表`

```json

      "类型": "正式结局",

      "单集梗概": "角色甲完成本轮目标，并承担选择造成的结果。",
      "后续节点编号列表": []
    }
  ],
  "分集列表": [
    {
```

## 分集结构

每个结构节点严格按以下顺序使用六个字段：

1. `分集编号`
2. `分集标题`
3. `类型`
4. `是否结局`
5. `单集梗概`
6. `后续节点编号列表`

`类型`保留业务节点类型，并明确区分`正式结局`和`失败小结局`。结局没有后继；非结局至少有一个后继。

## 十字段分集对象

每集严格按以下顺序使用十个一级字段：

1. `分集编号`
2. `分集标题`
3. `分集数`
4. `分集剧本`
5. `剧本分析`
6. `关联角色`
7. `关联场景`
8. `关联道具`
9. `是否结局`
10. `互动节点`

固定子字段：

- `分集剧本`：`单集梗概`、`完整剧本`
- `剧本分析`：`本集冲突`、`前置节点编号列表`、`后续节点编号列表`
- `互动节点`：`是否为分支节点`、`是否有选择问题`、`选择问题`、`选项列表`、`默认下一分集编号`
- 每个选项：`选项编号`、`选项文字`、`目标分集编号`

不得增加、删除、改名、换序或使用英文键替代。

`分集数`必须为正整数，等于冻结拓扑节点总数；同一结果内每个分集对象都重复该总数，不使用当前分集序号或单条路线长度代替。

上游`剧情节点总数建议`只是可选软区间。存在时用于拓扑体量校准，缺失时由游戏体量、情绪脊、真实分支和结局需求推导实际节点总数；无论上游是否提供建议，最终`分集数`都必须填写拓扑完成后的实际值。

## 拓扑和互动一致性

- 唯一入口为`episode-001`；所有节点可达、无环并能抵达至少一个结局。
- `剧本分析`中的前置和后续节点必须与冻结拓扑完全一致。
- 分支节点必须同时标记有选择问题，且至少有两个指向不同后继的有效选项。
- 选择问题非空；选项编号不重复；选项文字非空；选项目标与拓扑后继集合完全一致。
- 分支节点的默认下一集必须属于其后继。
- 非分支节点不含选择问题和选项；单后继节点默认下一集就是该后继；结局默认下一集为`无`。
- 预期结局总数、正式结局数和失败结局数必须与游戏企划一致。

## 剧本与资产一致性

- `单集梗概`在分集结构和分集剧本中完全一致。
- 完整剧本至少包含一个`【场景名称·时段·内/外】`格式的场次标题。
- 对白使用`人物：台词`，不加台词引号。
- 正文不含`△`、`出场：`、镜号、景别、机位或运镜说明。
- `关联角色`、`关联场景`、`关联道具`只使用正式资产名称，分类内不重名。
- 关联资产与正文实际出现内容双向一致；角色首次出场满足独立的全路径审计。

## 修改一致性

- 使用基线修改时必须声明允许变化的分集。
- 局部修改期间`分集结构`和冻结拓扑不得变化。
- 未授权分集必须与基线逐字段一致。
- `dialogue`范围内，授权分集只能修改对白文字；非台词正文、事实、动作、状态、十字段、选择和结尾不得变化。

## 内部验证边界

情绪脊、资产索引、首次出场证据、哈希、逐集复检包和回执仅供脚本强验证，不得加入正式结果。强验证失败时停止完成态输出，通过运行时错误通道返回问题。
