# 技术接入与公开投射

本文件说明业务结果之外的技术责任，不作为业务运行时返回，也不由业务 Skill 加载。技术侧只以`business-interface.md`为稳定字段接口。

接口是调用期约定，不等同于数据库 Schema。技术侧无需持久化用户意图合同、冲突解决记录、履约证据、门禁结果或任何内部验证材料；只需接收已经通过本轮全部强验证的十一字段`分集列表`。正式结果本身不含工具结果、摘要或门禁字段。

业务版没有替代原版生成流程。每次完成态返回前，运行时必须先完整执行`episode-generator v0.1.53`的用户意图合同、情绪脊、拓扑、逐集写作、台词复写、独立冷读、角色首次出场和三文件组装门禁，再从同一冻结结果生成业务 JSON。工程 validator 验证合同绑定、冲突状态、逐字证据、拓扑、指纹、回执有效性和字段一致性；模型仍须独立判断用户要求是否在语义上得到履行，以及设定吞吐、身份交代、台词话茬与因果是否成立。

## 两类节点投射

- `分集数`是互动节点总数。它来自完成情绪脊和拓扑后确定的具体值；上游`剧情节点总数建议`只是优先采用的软区间。
- 每个分集对象恰好对应一个`episode-xxx`互动节点，承载完整剧本、梗概、资产和结局信息。
- 普通互动节点直接按`剧本分析.后续节点编号列表`连接下一互动节点。
- 分支互动节点完整播放后，按`互动节点.后续选择节点编号`进入同一分集对象内封装的`choice-xxx`选择信息。
- 选择节点只含问题、选项文字和目标互动节点编号；它不是分集，不计入`分集数`，不复制为第二个分集对象。
- 为避免同一记录被重复投射，业务输出中的每个分集固定`互动节点.是否为互动节点=true`、`选择节点.是否为选择节点=false`；是否渲染后续选择只看`选择节点.是否有选择问题`及其唯一选择信息。

## 完成态提交屏障

- Skill 在私有空间完成情绪脊、创作拓扑、正文和两类节点校验；生成中间态不调用页面节点创建或更新接口。
- 只有业务校验器通过后，技术 adapter 才接收一次完整`分集列表`。
- 重做或重新拓扑使用整组替换：先以新结果构造完整互动节点、选择节点和边集合，再原子替换当前集合；禁止对旧集合追加、拼接或按文本去重。
- adapter 必须校验互动节点编号连续、选择节点编号连续、每个分集恰好一个互动节点、每个有效选择恰好封装一次，并拒绝选择内容出现在两个对象中。
- Skill 使用内置`build_route_projection.py`生成路线提案，并用`validate_route_projection.py`在合并前后分别交叉验证业务 JSON 与路线。运行时不得临时手写投影脚本。
- `route.data.nodes`只保存互动剧情节点；选择由来源节点的`interaction`和对应`choice`边表达。`episode_router`与`episode`槽位必须来自同一已验证事实源，不能各自重新推导选择。
- 所有节点与结局标记使用原生boolean；禁止把boolean与`是/否`字符串比较。

## 公开文件

画布一级目录只保留：

- `episode-flowchart.svg`：真实互动节点、选择、结果、汇合和结局。
- `episode-structure.md`：只含分集编号、标题、类型、单集梗概和玩家可见跳转。
- `episode-script.md`：全部十一字段分集结果组成的完整剧本。

三份文件必须来自同一份已通过门禁的冻结结果并位于同一公开目录。公开目录不得包含第四个文件或子目录；尤其不得创建`cache/`。

## 私有内容

上游整理、冷读、情绪脊、因果链、拓扑推导、路线状态、逐集草稿、检查过程、证据、哈希和修复记录只存在于业务 Skill 的临时验证空间，不写入业务 JSON或玩家可见目录。用户要求排查时只展示结论、影响和处理结果，不展示内部路径、哈希、门禁日志、逐字内部思维或内部 Reference。

## 进度

技术 UI 和 Agent 中间消息采用“静默优先、单句降级”：默认不展示过程状态；若平台强制需要长任务占位，只能逐字显示`正在生成中`。不得附带原因、完成项、下一步或任何内部阶段说明。技术侧必须丢弃这一句之外的过程状态；尤其不得展示合同更新、拓扑重整、门禁执行、节点去重、冷读、复检、缓存路径、内部判断、字数、动作数量、审稿记录、逐字证据或修复过程。
