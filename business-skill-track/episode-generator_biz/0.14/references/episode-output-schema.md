# 分集输出结构与内容规则

生成、修改或验证分集结果时读取本文件。字段名称、类型和层级以`business-interface.md`为唯一接口定义；本文件补充内容要求和字段间一致性。

## 顶层结构

正式结果只包含`分集列表`：

```json
{
  "分集列表": [
    {
      "分集编号": "episode-001",
      "分集标题": "示例结局",
      "分集数": 1,
      "分集剧本": {
        "完整剧本": "【示例场景·白天·内】\n角色甲把示例道具交到桌上。\n角色甲：这件事到这里结束。",
        "单集梗概": "角色甲完成本轮目标，并承担选择造成的结果。"
      },
      "剧本分析": {
        "本集冲突": "角色甲必须完成目标并承担结果。",
        "前置节点编号列表": [],
        "后续节点编号列表": []
      },
      "关联角色": ["角色甲"],
      "关联场景": ["示例场景"],
      "关联道具": ["示例道具"],
      "是否结局": true,
      "选择节点": {
        "是否为选择节点": false,
        "是否有选择问题": false,
        "选择节点编号": "无",
        "选择问题": "",
        "选项列表": []
      },
      "互动节点": {
        "是否为互动节点": true,
        "互动节点编号": "episode-001",
        "后边是否接选择节点": false,
        "后续选择节点编号": "无"
      }
    }
  ]
}
```

示例只说明结构，不是金标内容，不得复制示例人物、场景或道具进入真实项目。

## 十一字段分集对象

每集严格按以下顺序使用十一个一级字段：

1. `分集编号`
2. `分集标题`
3. `分集数`
4. `分集剧本`
5. `剧本分析`
6. `关联角色`
7. `关联场景`
8. `关联道具`
9. `是否结局`
10. `选择节点`
11. `互动节点`

固定子字段：

- `分集剧本`：`完整剧本`、`单集梗概`
- `剧本分析`：`本集冲突`、`前置节点编号列表`、`后续节点编号列表`
- `选择节点`：`是否为选择节点`、`是否有选择问题`、`选择节点编号`、`选择问题`、`选项列表`
- 每个选项：`选项编号`、`选项文字`、`目标互动节点编号`
- `互动节点`：`是否为互动节点`、`互动节点编号`、`后边是否接选择节点`、`后续选择节点编号`

不得增加、删除、改名、换序或使用英文键替代。`选择数`不属于最新版业务字段，不得输出。

`分集数`必须为正整数，等于冻结创作拓扑中的互动节点总数。同一结果内每个分集对象都重复该确定值。上游`剧情节点总数建议`只是可选软区间；存在时优先在区间内确定互动节点数，缺失时由游戏体量、情绪脊、真实分支和结局需求推导。

## 互动节点与选择节点一致性

带选择的分集使用下面这组标记；这是两个字段职责分离后的标准组合，不得把`是否为选择节点`改成真：

```json
"选择节点": {
  "是否为选择节点": false,
  "是否有选择问题": true,
  "选择节点编号": "choice-001",
  "选择问题": "本集剧情播完后，玩家要怎么做？",
  "选项列表": [
    {"选项编号": "1", "选项文字": "行动一", "目标互动节点编号": "episode-002"},
    {"选项编号": "2", "选项文字": "行动二", "目标互动节点编号": "episode-003"}
  ]
},
"互动节点": {
  "是否为互动节点": true,
  "互动节点编号": "episode-001",
  "后边是否接选择节点": true,
  "后续选择节点编号": "choice-001"
}
```

- 唯一入口为`episode-001`互动节点；全部互动节点可达、无环并能抵达至少一个结局。
- 每个分集对象恰好封装一个互动节点。`互动节点.是否为互动节点`恒为真，`选择节点.是否为选择节点`恒为假，两个身份严格互斥；`互动节点编号`必须等于`分集编号`。
- 无选择的互动节点：`后边是否接选择节点=false`、`后续选择节点编号=无`；其下一互动节点由`剧本分析.后续节点编号列表`表达。
- 有选择的互动节点：`后边是否接选择节点=true`，且`后续选择节点编号`等于同一对象内非空的`选择节点编号`。
- 每个有效选择恰好出现一次；当前分集记录仍保持`选择节点.是否为选择节点=false`，只用`是否有选择问题=true`声明后续选择存在。问题非空，至少两个选项指向不同互动节点。
- 选择节点编号按来源互动节点顺序使用连续的`choice-xxx`；它不是分集，不计入`分集数`，不另生成一条分集对象。
- 每个选项严格使用`选项编号`、`选项文字`、`目标互动节点编号`；编号不重复，文字非空，目标集合与`剧本分析.后续节点编号列表`完全一致。
- 无选择时`选择节点编号=无`、`选择问题`为空、`选项列表`为空；`是否有选择问题=false`，且`是否为选择节点`仍为假。
- 选择问题与选项只能存在于`选择节点`，不得复制进`互动节点`、剧本正文或第二个结构对象。
- `分集列表`第一项必须是`episode-001`互动节点且`完整剧本`非空；若它带选择，选择只能在该集正文播完后出现。禁止第一项被识别成选择节点，禁止空剧情直接出选项。
- 预期结局总数、正式结局数和失败结局数必须与游戏企划一致。

## 剧本与资产一致性

- 完整剧本至少包含一个`【场景名称·时段·内/外】`格式的场次标题。
- 对白使用`人物：台词`，不加台词引号。
- 正文不含`△`、`出场：`、镜号、景别、机位或运镜说明。
- `关联角色`、`关联场景`、`关联道具`只使用正式资产名称，分类内不重名。
- 关联资产与正文实际出现内容双向一致；角色首次出场满足独立的全路径审计。

## 修改一致性

- 使用基线修改时必须声明允许变化的分集。
- 局部修改期间互动节点与选择节点构成的冻结拓扑不得变化。
- 未授权分集必须与基线逐字段一致。
- `dialogue`范围内，授权分集只能修改对白文字；非台词正文、事实、动作、状态、十一字段、选择和结尾不得变化。

## 内部验证边界

情绪脊、资产索引、首次出场证据、哈希、逐集复检包和回执仅供脚本强验证，不得加入正式结果。强验证失败时停止完成态输出，通过运行时错误通道返回问题。

正式业务对象采用提交屏障：生成期间只操作私有缓存，不向页面逐节点发布；全部门禁通过后才一次性提交完整`分集列表`。重新拓扑时整组替换，不与已有页面节点合并。
