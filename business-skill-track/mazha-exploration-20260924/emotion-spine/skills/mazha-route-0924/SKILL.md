# 影游创作

## 创意起步与确认

先判断当前是创意提案、确认后的首批创作、续写还是局部修改，不让用户重复已经完成的步骤。新输入先用 web_search 简短调研、fetch 阅读最相关的具体页面；热梗/IP 同时核对身份与二创语境，官网只证明身份，首页/下载页不算二创证据。最多三轮针对性搜索；仍不明白时坦白具体缺口，让用户提供片段或选择仅依据已确认身份自由原创，不把角色名套进通用模板、不编造热度或视频观看经历。自定义设定优先，已有可靠材料不重复搜。

创意提案默认 150–250 字、两小段：主角正在做什么、遇到什么麻烦、因此要做什么、谁在阻止、代价和未解钩子；再说明玩家可采取的具体行动及不同可能后果。用人话讲行动因果，不写抽象宣传句，不重复一行概括，不提前演完全篇或列完整结局菜单。未指定就不固定集数。

有依据后尽早给公开创意标签，每组单独一行：【主标签】一个；【副标签】最多两个；【创意词】四至六个具体意象/冲突词。它们是创作摘要，不是内部推理。来源及未知项简记在回复，不写入故事正文。

保存提案到现有 story.outline 并读回一次，结束此轮，交前端编辑/确认/重新创意；不创建图或资产，不重复发批次 AskUser。用户重新创意则换方向后再等确认，微调只动相关内容。确认后读回含用户手改的最新提案，再进入下文；不重做已确认创意、不把简介当完整短故事。已有作品直接处理用户当前续写/修改，不重新跑起步搜索与确认。

## 范围

短故事是整部作品的方向底稿，不是本批必须演完的剧情。首次只展开开头一个局部单元：人物处境、眼前行动、首个天然抉择及不同即时后果。节点多少由事件边界决定，不把整部故事压进三集，不提前兑现主结局。后续脊点保留在工作稿里，未写部分不建空卡。用户明确要求完整作品时，也逐批生长与写剧本，不先画完整图。本 Skill 是唯一创作入口，不再调用独立 bootstrap、编剧或资产设计 Skill；只复用 nextplay-cli 处理工程读写。

本版取代旧的“完整线性长故事→冻结切片→整图强校验”方法。旧包 references 与 scripts 仅作历史备份，不加载或运行其整图配额、主线冻结、强制双翼、期望结算阶梯和缓存流程。平台读写使用已绑定 nextplay-cli 的真实当前合同，不降低保存校验、不直接改项目 JSON。

## 创作：短故事 → 情绪脊 → 岔点 → 本批拓扑

1. 读当前项目、用户确认及手改的创意、已有短故事与路线。已有合格短故事直接复用；没有时用几百字写清主角想做什么、因何行动、遇到什么阻力及可能走向，一次因果自检即可。不扩写完整线性长故事后再切分支。首批长度与整部作品时长是两回事；不能因为只做开头而把作品判成短片。
2. 按规则书第二、四部分立情绪脊：沿起承转合简记主角的事件、期待、实际后果与情绪拐点。情感/事业权重服从题材；PAD 中 V 是愉悦、A 是激活、D 是掌控。关注压制到翻盘、得意到跌落的有效变化；每次获得都考虑观众看见而主角尚未知的风险。只详细写本批脊点，远期保留方向，不提前写完所有场面。
3. 从“幻想空间出现分歧＋情绪发生转折”的位置找天然岔点。先让玩家经历具体矛盾，再给选择；每个选项写明动作、想要的获得、代价及即时结果。不要随机抽拓扑、先造空图或为了数量硬挖分支。
4. 只把当前局部变成节点与边，再填本批每节点的具体事件、入场事实、变化与停止边界。每集围绕一件事；选择之前不演选择后的行动。首次通常只需一个自然抉择及其结果，后续从未展开边界继续。需要的人物、场景、道具文字在本批用到之前建立，不要求全作资产配齐，不选画风、配音或生成图片。

## 编织带与待续边界

- 依规则书 3.5，分支时分时合，首层不超过四条；通常给两三个真正不同的选项。选项先各自落到不同结果节点，再在事实兼容处回线；禁止两个选项直接指向同一节点而没有差异。
- 汇合保留选择带来的关系、证据和代价；共享正文只使用所有来路都成立的事实。不回线须有故事依据，可落到确实成立的小结局，也可保留待续，不强迫每条支路立即结束。一个互动不能全是死路。
- 开场交互落在第一个情节点的高潮处。长作品按每 2–4 集一次互动、连续不超过 4 集无互动控制节奏；深层继续分支的汇合比例等整部预算在累计展开时核对，不把全片结局数、七拍或百分比塞进首批。完整短片使用规则书的结局树引擎；“几百字短故事”不等于短片时长。
- 区分三件事：本批写完、此路线暂未展开、这条故事真正结束。待续边界不标结局、不接不存在的 ID、不伪造终局。工作稿记录 frontier：现有末节点、入场事实、未解目标和下一段情绪方向；这些是内部计划，不向平台发明新字段。
- 通过当前 CLI 支持的草稿/非结局末端方式保存局部图。若实际平台合同强制所有末端都是结局，说明具体不兼容，保留工作稿；禁止改成假结局、伪造通过或悄悄补完全部故事。

## 拓扑、编剧、人物场景道具属于同一个创作循环

本 Skill 同时承担路线、正式编剧和文字资产设计，不再调用独立的“生成人物简介／生成场景设定”阶段，也不要求 bootstrap 或 asset-designer 先做全作资产。人物、场景、道具不是上游必齐输入，而是当前节点与真实剧本逐步带出的产物。

每次只处理眼前可保存的小段：从脊点确定事件与选择 → 找到这一段真正登场的人物/场景/道具 → 复用已存在设定，补充新出现的文字描述 → 保存当前合法节点与连接 → 在前情齐备时接续该节点的剧本。随后再长下一段，不先写齐本批/全作所有资产，也不等整张图完成再写正文。平台要求引用先存在时，仅提前保存这一段用到的记录；这是依赖写入，不是独立创作阶段。写正式剧本时发现必需的新人物、场景或道具，就在当前创作过程中设计并登记，再继续正文；无需退出到另一个 Skill。新设定必须服务眼前动作，不能偷改用户确认的事实、塞入未来独占信息或无因果地解围。若它改变已存拓扑或前情，先核对受影响部分再局部保存，不覆写整图。

角色只写公开身份、与眼前事件的关系、当前动机及必要外观/状态；场景写实际地点、日夜、影响行动的空间特征；核心道具写外形、用途、归属和会影响后续的状态。普通无关物件不单独建卡。沿用现有正式名称/ID，不重复建同一人或同一场景；新人物先在戏中建置再让其承担关键作用。日夜分场，前后状态连续。

不因新建角色触发音色匹配，不因新场景触发画风选择或图片生成。不提前给未来角色占位，不在用户界面播报“生成全部资产”；只报告眼前正在发生的创作。保存成功后由产品按真实数据呈现，禁止伪造资产已出现。

## 给用户的续写方向

情绪脊也用于提示后续拓扑的可能方向。每批完成后用一两句人话给出两三个可改变的后续方向，说明主角下一步可做什么、会带来什么情绪或关系变化；不展示 PAD 数字、工作稿或内部推理。这些是供用户选择或改写的创作建议，不是已保存的未来节点或锁死的结局。

用户说“再做几个节点”“继续一点”时，从当前 frontier 接着展开一个局部单元，保留已发生的选择和后果；不重做开头、不补完整部、不重复确认已经授权的续写。用户指定方向则据此调整未展开情绪脊；具体拓扑在本批创作时落定。

## 同一 Skill 内直接写正式剧本

不走冻结包→行动底稿→增强稿→多轮报告的串行链路。用当前节点事实在一次写作中组织行动、完成场景和口语对白，再做一次冷读；发现问题只修受影响部分。必要的新资产随写作就地补充，上文循环负责真实登记，不以“白名单尚未齐全”阻止合理创作。

- 每场以【场景·时段·内/外】开始。主角行动→阻力/反馈→调整→局面变化→停止边界要清楚。每个戏剧拍带来信息、策略、关系或权力的新变化；重复证明、空走位、结果后的总结删除。
- 入口在第一轮行动反馈中让人看懂“谁、想做什么、为什么受阻”；身份、世界规则附着于行动，不另开讲解段。续集不重复首集建置。新人物先让观众知道与眼前事情的关系，再承担关键作用。
- 台词针对眼前对象、接住上一句和刚发生的事；请求/问题要有回答、拒绝或可识别回避。允许迟疑改口和无对白，不写作者腔、格言、主题总结或全员字幕式短句。动作保留有意味的争取、掩饰、舍不得，不堆装饰性调度。
- 人物位置、物件换手、日夜及已知事实前后连续。固定镜头优先，只写必要可拍动作。场景人物道具描述服务本场，不能先列全片设定清单再写戏。
- 选择卡不写剧本；顺真实入边追溯上游正文结尾和选择原文。不同支路的证据、秘密和关系不能串线；汇合正文使用共同成立的事实，并以实际支持的表达保留差异。
- 结尾落在本节点最后一次变化的可见动作/声音/物件状态。待续是待续，不赶写全作高潮和终局。正文不包含选择利弊分析、内部流程说明或未来节点规划。
- 以 CLI 实际 schema 保存剧本，分清动作与对白、核对说话人和场次。每个完整节点写完及时保存读回，再往下展开，不为展示故意延迟，也不把未保存草稿伪装成已完成。

## 一次核对、保存与接续

读通本批每条“前情→选择→后果”：主角为何这样做，依据从何而来，选项差别是否兑现，汇合是否串用了另一来路。只修具体问题，不强制多轮同义稿、逐阶段独立报告或全书通读。

按 nextplay-cli 当前 help 组装合法增量，保留原有 ID、边和用户手改；真实保存后读回。对当前已存节点直接写正式剧本，以真实节点 ID、最新版本、允许资产、逐来路前情、选择原文与停止边界绑定。不要伪造 accepted、哈希或缺失的前情。

本批节点、剧本和实际用到的文字资产读回完整后：专家模式 AskUser 给“继续创作／调整这一段／就此停止”，等待时遵守平台画布锁；继续时只展开 frontier。明确全自动完成整部时连续执行下一批，直到授权范围完成。用户没有要求整部时默认交付开头这批并询问。用户删改以当前画布为准，只修受影响部分，不恢复已删节点。仅报告真实已保存范围，开头完成不能称整部完成。

依据：用户《互动影视游戏设计规则书》2.2–2.5、3.1.2、3.5 与第四部分；本测试按用户要求将拓扑与分集内容限制为逐批展开，保留整部情绪走向。
