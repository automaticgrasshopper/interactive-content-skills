# 创作范围与控制模式

产品传入的模式、用户本轮范围、前端确认停点分别处理。专家／全自动控制创作推进范围，执行前确认控制工具审批，二者不能混为权限。没有模式时读取当前项目／前端实际状态，不凭 Skill 默认覆盖用户。

| 状态 | 工作与停止点 |
|---|---|
| 创意确认前 | 搜索、简短提案、修改、保存；前端要求确认则等用户，无论全自动还是专家 |
| 全自动确认后 | 写通短故事，情绪脊引导逐批展开整部路线；各批同步剧本与文字资产。完成全部有效节点、选择、结局及剧本才停止，不逐批 AskUser，不触发创作权移交 |
| 专家确认后 | 只做当前局部单元，完成本批节点、后果、剧本和实际出现的资产后 AskUser；首批是开头，不能把整部硬挤成三集 |
| 专家继续 | 从用户选定末端再扩若干有意义节点；不重做提案、全资产或已有图，不把“再几个”当作全作硬数量 |
| 专家调整 | 修改指定内容及确受影响的下游，读回后重新交接 |
| 就此停止／打断 | 停止发起新生成，保留真实已存内容，恢复整体画布；未存请求与正在执行操作按实际取消能力处理，不声称撤销已保存数据 |
| 局部请求 | 只改一个台词／节点／路线时遵循该范围，即使全自动也不重做整部 |

本批范围以一个可理解事件单元为准，不固定每批三集；用户明确数量优先。专家不用首批兑现全图复杂度与四类结局，但必须继承可续写方向、真实因果与正确连接。全自动最终仍满足完整图规则；按批写只改变交付节奏，不降格为专家首批。

画风与音色确认后移。人物、场景、道具的文字描述从拓扑与编剧中陆续产生，不作为独立上游阶段。批次之间没有强制读一遍全部 Skill 或重复初始化 CLI。

前端“创作权移交”只用于专家本批真实完成、展示队列播完之后；AskUser 等待时画布保持锁定，用户选择停止才交回编辑。Agent 提供实际本批完成及询问，动画由前端消费；不能用输出“创作权移交”四字代替动画，也不能靠定时器宣布后台完成。
