# 真实逐步创作与保存

全自动与专家共用这一保存节奏，二者只改变最终范围与停止点。全作因果、情绪脊和复杂图规划可以提前完成，但它们是创作缓存；正式画布随实际写作逐步长出。不能先保存全部空节点、预建全资产，再循环灌入预写好的全部剧本。不得 sleep、打空工具、逐字重复写盘来表演工作。

## 一个节点推进到可交付，再展开下一段

1. 读取本节点前情与边界，创建当前剧情节点并连接真实前驱；只补此刻用到的人物、场景、道具。选择节点与全部选项、即时后果入口一起提交，避免不完整选择。以后用 route edit 追加，不重建已有图。
2. 独立完成短底稿及检查后，才据底稿增强复写。增强稿按完整行动段推进：形成可读、格式正确的一段就用 CLI script set 保存当前累计正文与实际 mentions，等待工具返回再继续创作；不是先写完整稿再拆段补交。正文是仍会修订的当前工作稿，不宣称已冷读或本集完成，不添加进度标记到正文。
3. 推进中发现必要新人物、场景或道具，使用 asset add/update 保存真实文字设定。已有正文仍保留；新 ref 返回后，再将含该人物/场景的新段落和累计 mentions 保存到本节点。范围仍受本集事件及停点约束；不能为演示而添人物。
4. 冷读真实累计正文，有问题就以 script edit 或 set 修订原节点，保持稳定引用，重新核对相关上下文与资产。通过完整编剧验收、CLI 保存读回，才称本集完成，再创建后续单元。不要一个 shell 调用包揽整集乃至全剧的生成、资产、验收和全部写入；每个有意义的写入单独工具调用返回，使消费者有机会收到各版本。无需等前端动画。
5. 全自动继续此循环直至全作完成，再做全图和全剧最终验收；专家在本批完成后 AskUser。正在制作时末端不是结局，记录待续；不把临时末端检查提示冒充终验通过。

## 工程事实

现有 nextplay-cli 支持 route edit 的 add-node/connect，以及 script set 的累计 text/mentions 和 script edit 的唯一 old/new 替换。具体参数以当前绑定 CLI 的 references/routes.md 为准。旧正文更新使用真实读回文本，避免覆盖用户并发修改。新引用随出现补齐，不写占位 ID。

平台保存没有“已完成剧本”布尔字段时，不发明该字段；运行中画布是当前已存工作版本，只有最终检查和回执代表完成。草稿→复写→冷读顺序不变，内部底稿/分析/hash不写进正文。当前正文进度保存不等同最终验收，screenwriting.md 第4步描述的是最终验收保存。

CLI saved 仅证明工作区写入，不证明前端已经收到。正文局部进展至少有两个自然行动段时应出现先后两次真实写入；极短节点不硬拆。若平台只在整轮结束投影，准确报告这个限制，不用前端回放模拟增量。
