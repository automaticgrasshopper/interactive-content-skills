# 流程图规划师

## 0924 独立测试接续

本副本保留确定版故事与拓扑流程。只接收文字企划、人物、场景和必要道具，不要求资产图片、音色、封面、画风选择。用户已要求从一句话完成全部剧本时，路线保存读回后立即交 mazha-screenwriter-0924 逐集展开，不再次询问是否继续。用户只要流程图则在图保存后结束。辅助文件中“保存后停止”仅表示本 Skill 不写剧本，不撤销调用方已授权的连续任务。对外 Skill slug 是 mazha-route-0924；已有业务合同 capability_id 保持 episode-route-planner-biz。


用户输入第一性；满足用户硬约束与故事因果后，默认交付一张持续开扇、交织、分层结算的丰满故事网络，不能以一组B/C加大量退出路线交差。输入输出见[业务合同](references/business-interface.md)。**一集 = 一个 slot = 一个非选择剧集节点；结局剧集计入集数，选择卡另计，选项是边。**

用户说“三集”默认约束整张图的三个剧情剧集，不是每条路线各三集；“第一集、第二集”是序号，“一个节点分出两个结局”是局部关系。先结合整句话核对对象与数量，再对照企划；企划与原话不一致时修企划，不能反过来改用户口径。有真实歧义才用普通话询问，见[故事整理](references/story-development.md)。

## 内部工具与业务流程

本Skill全部脚本、缓存、冻结锁、哈希与检查结果只辅助内部工作，不是Agent继续规划、交接、保存或生成下一阶段的放行凭证。无论检查未通过、文件缺失或程序异常，都保留已有故事和画布，按[验收与局部恢复](references/acceptance.md)局部处理或直接按业务合同整理交接，不得仅因内部工具失败停止流程、要求用户修缓存或推给工程。失败如实记录，不伪造PASS或PLANNING_ACCEPTED。用户要求与当前画布事实照常核对，平台保存仍走现有网关；用户明确暂停、必要意图待答或真实外部服务不可用按实际情况处理。

## 先区分初次生成与已有画布

已有节点时，包括点击任一集“生成剧本”、继续生成素材、检查或编辑画布，先读[当前画布与用户编辑](references/current-canvas-editing.md)。当前画布优先。用户删除已是决定；首次检测到删改，围绕删除后的前后剧情，提供“接顺现有剧情／补写新的过渡／暂不处理”三个具体方案。按用户选择处理实际断线及孤立剧集后继续生成；不以恢复旧路线为默认选项，不放松原保存校验。用本Skill的当前材料绑定交给编剧。只有新建完整路线才执行以下流程。

## 新故事：一条连续流程

当前阶段以实际落盘正文和未修问题为准。审读稿里的“稍后补充”不等于已经修改；有问题先改当前正文再读，不把短故事的欠缺转交长故事或编剧。已完成的上游只读取，不因进入下个阶段再次生成。过程自动继续，不逐步请用户确认；短故事整理时及主线冻结前，须核对故事与用户意图是否匹配，发现违背用户期望则按[故事整理](references/story-development.md)先询问，收到明确意见后再继续。

1. 读用户原话、企划及[故事整理](references/story-development.md)，先完成用户意图与实际故事体量的核对。短时长与必保经历冲突时，先问取舍并等待；不能用上游“单次很短、全分支更长”的承诺当作已解决，也不能直接按短篇降低图形要求。没有时长要求时从故事本身确定体量，不继承企划默认短篇作为硬约束。在 `story-core-review.md` 简记主角的任务、阻碍、为何继续和一次确定的结果；区分用户必保事实与可舍弃的AI谜面。此时不读拓扑或图形规则，不写节点、brief或冻结文件。
2. 写 `story-core.md`，用几百字讲完主角的一次经历，不列结局菜单。结束写入后，下一次调用只读短故事全文。按故事整理要求反查关键转折：依据是否足够、时间与动作是否成立；不能只引用一句自证合理。缺口改进短故事本身，再读修订原文，才继续。
3. 只沿修订短故事独立扩写 `mainline-story.md`，补现场行动、实质交谈、发现与后果，主角和观众同步知情。该调用只写长故事，随后另次读全文、修断点。不要同时创建节点或freeze。开头讲清主角、眼前一件事及必要设定，后文各段围绕一个主要事件。
4. 读取[故事切片与拓扑展开](references/story-planning.md)和业务合同。先在原有草稿列明待用抉择及原动作的第一句，再据此选切口，写 `user-request.md`、`brief.json`、`mainline.json`；长故事已存在，不重写。另次读回每个实际切片，引用首尾句核对正文、冲突和停止边界。原行动及后果从选择之后开始，共享段的第一项行动须适用于来路。切片正确再运行 `python3 scripts/route_plan.py freeze CACHE_ROOT`。体量匹配且冲突已按用户意见解决后，才按有效时长分类：不足15分钟为短故事，不逐路计算时长或互动节奏。
5. 从冻结主线的真实裂口写完整支线故事，单独读回后再切片；拓扑新增的普通集、过渡与结局须像主线一样写清实际事件，不用选项后果的结论句充当梗概。重要路线持续双翼展开、交织后再开扇，并保留来路的事实和代价。默认小结局、期望结局、坏结局、真结局齐全，用户明确数量与类型优先。非短故事默认至少两级不同的期望结算阶梯，继续须有新的事件与代价。完整创作要求见故事切片与拓扑展开。
6. 读取[图形合同](references/graph-contract.md)，用临时ID简短探索形状，写 `exploration.md` 后废弃；不验收草图，不进入正式事实源。正式图重新组织，提交完整支线故事及正式图：`route_plan.py submit CACHE_ROOT SUBMISSION.json`。提交成功后再 `route_plan.py check CACHE_ROOT`；未提交成功不检查不存在的正式候选。
7. 非短故事检查小结局、两层分岔、真正双线交织、持续展开、继续发展占主要比重、两级期望结算阶梯；B双翼与C交织为主，A仅补充。基础结构、数量、结局类型、防末端菜单同样按合同执行。机器只检查图形、输入合同与切片投影，不审剧情或虚构状态。依[恢复规则](references/acceptance.md)只修失败项及确有问题的支线，冻结主线不动，已通过展开保留。
8. 作者读取实际路线及完整分集材料；正常使用 `route-candidate.json`，内部工具失败时使用已保留的故事、节点和真实连接。按故事切片与拓扑展开的逐来路引用要求，把每条“选择前正文→所选动作→后继事件”读通；追溯人物、证据、权限和已完成行动，不借用另一支路的事实。问题和实际修订记入原有 `story-core-review.md`，修后重读受影响路径；不以“均符合”代替逐来路阅读，不新增机器语义评分或正式回执。同时核对第一集、一集一件事及实际保存的完整梗概：标题与正文分开，无内部章节或路线说明；共享段不并列不同来路的经历，支线不退化为结论摘要。图形返修过的支线也完成此步，不能check后直接accept。
9. 作者审读完成后可运行 `route_plan.py accept CACHE_ROOT FORMAL_ROUTE.json` 派生交接对象。`PLANNING_ACCEPTED`只表示内部机器检查成功，不是业务流程前置条件。检查失败或工具不可用时按恢复规则直接整理同字段的完整交接对象，继续调用现有接口保存并读回；不要求先修好缓存。用户只要规划或画布则至此完成，有后续生成请求则交相应Skill继续，不操作平台配置。

禁止删除锁、重建缓存或把非短改成短故事绕过失败。只使用本版 `route_plan.py`，不混用旧的逐节点生长、随机抽签、A/B或编剧脚本。
