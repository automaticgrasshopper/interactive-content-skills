# 流程图规划师

## 0924 独立测试接续

本副本保留确定版故事与拓扑流程。只接收文字企划、人物、场景和必要道具，不要求资产图片、音色、封面、画风选择。用户已要求从一句话完成全部剧本时，路线保存读回后立即交 mazha-screenwriter-0924 逐集展开，不再次询问是否继续。用户只要流程图则在图保存后结束。辅助文件中“保存后停止”仅表示本 Skill 不写剧本，不撤销调用方已授权的连续任务。对外 Skill slug 是 mazha-route-0924；已有业务合同 capability_id 保持 episode-route-planner-biz。


用户输入第一性；满足用户硬约束与故事因果后，默认交付一张持续开扇、交织、分层结算的丰满故事网络，不能以一组B/C加大量退出路线交差。输入输出见[业务合同](references/business-interface.md)。**一集 = 一个 slot = 一个非选择剧集节点；结局剧集计入集数，选择卡另计，选项是边。**

用户说“三集”默认约束整张图的三个剧情剧集，不是每条路线各三集；“第一集、第二集”是序号，“一个节点分出两个结局”是局部关系。先结合整句话核对对象与数量，再对照企划；企划与原话不一致时修企划，不能反过来改用户口径。有真实歧义才用普通话询问，见[故事整理](references/story-development.md)。

## 内部工具与业务流程

本Skill全部脚本、缓存、冻结锁、哈希与检查结果只辅助内部工作，不是Agent继续规划、交接、保存或生成下一阶段的放行凭证。无论检查未通过、文件缺失或程序异常，都保留已有故事和画布，按[验收与局部恢复](references/acceptance.md)局部处理或直接按业务合同整理交接，不得仅因内部工具失败停止流程、要求用户修缓存或推给工程。失败如实记录，不伪造PASS或PLANNING_ACCEPTED。用户要求与当前画布事实照常核对，平台保存仍走现有网关；用户明确暂停、必要意图待答或真实外部服务不可用按实际情况处理。

## 先区分初次生成与已有画布

已有节点时，包括点击任一集“生成剧本”、继续生成素材、检查或编辑画布，先读[当前画布与用户编辑](references/current-canvas-editing.md)。当前画布优先。用户删除已是决定；首次检测到删改，围绕删除后的前后剧情，提供“接顺现有剧情／补写新的过渡／暂不处理”三个具体方案。按用户选择处理实际断线及孤立剧集后继续生成；不以恢复旧路线为默认选项，不放松原保存校验。用本Skill的当前材料绑定交给编剧。只有新建完整路线才执行以下流程。

## 新故事：合并创作，保留验收

本实验合并执行轮次，不降低原 references 的故事、切片、图形与逐来路因果要求。旧版为强制隔离审读设置的“下一次调用只读”“每阶段独立写文件”不再是前置；真实保存及读回仍不可省略。

1. 一次读取用户输入、当前企划和相关创作 references。以同一份工作稿完成完整短故事、连续主线、天然抉择和支线正文。先有戏再定拓扑，不拿空节点填故事；核对短故事与主线后再切片。审读直接修该工作稿，避免把同一材料在多个 Skill 间重复转述。
2. 从稳定正文切片并组织正式图。保留一集一件事、停止边界、持续双翼、交织、分层结算，以及当前图形合同适用的数量与结构要求。不能用规则书的另一套时长分档覆盖确定版流程图规则。缺少时长时按故事体量决定，不默认为三集。
3. 把图形检查和逐来路审读集中在一次验收中：检查每条实际来路的证据、知情、资产、行动和选项后果；引用受审正文，不以“均符合”代替。修正只影响问题节点及其依赖。沿用本副本的现有工具时遵守其输入合同；工具不可用依原验收恢复规则执行，不发明通过回执。
4. 通过真实 CLI 保存完整合法路线并读回。把同一份稳定故事事实和节点边界直接交给编剧，不再重新生成企划、人物表或整张图。前端负责将一次保存的图逐步展示，不为动画逐节点反复提交不完整图。


禁止删除锁、重建缓存或把非短改成短故事绕过失败。只使用本版 `route_plan.py`，不混用旧的逐节点生长、随机抽签、A/B或编剧脚本。
