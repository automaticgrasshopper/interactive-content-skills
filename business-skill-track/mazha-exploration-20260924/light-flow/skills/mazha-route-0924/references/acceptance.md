# 验收与局部恢复

## 内部检查不阻断业务

本规则适用于本Skill所有脚本及其调用链，包括route_plan、graph_check、route_contract、user_constraints和canvas_writing。内部PASS、FAIL、NEEDS_REPAIR、异常、退出码及回执只用于定位问题，不是Agent业务放行条件。Agent始终保留用户目标、当前画布和已完成故事，继续完成获授权的流程；不得仅因内部检查失败结束任务或要求工程提供恢复功能。

先读实际问题：内容或连线确有错误就只修该处；缓存、身份、投影或程序问题不重写故事。可明确修复时做一次局部恢复；同一内部故障仍在就切换直接交接，不循环重跑、不等待内部脚本全绿。直接交接时从已完成正文切片、当前节点与真实边整理业务合同字段，核对用户数量、结局、选择边界与完整材料，计算实际内容绑定，交现有平台网关保存并读回。完整梗概及前情依据一并交给下游，不只交短摘要或哈希。内部失败原因留在内部记录，不虚构机器验收通过；业务对象的accepted表示本次内容交接已确认，不代表机器检查全部成功。

内部锁只保护原始缓存，不锁住用户业务。保留锁与原始文件作追溯，不改锁、不删库；直接交接产物单独准备，不复用已失效回执。若只是内部写作绑定工具失败，直接从当前画布及已获授权的接法准备同字段写作材料，继续原请求，不能继承已断开支路或恢复已删除选择。用户“暂不处理”的决定仍须遵守。

平台拒绝保存时依据真实返回局部纠正字段或当前revision后重试，不绕过网关或宣称已保存；权限、网络、项目身份确实无法取得时说明真实外部问题，并继续可做的内容工作。内部报错本身不证明存在外部故障。

## 项目身份可以晚绑定

project_id是当前项目的运行身份，不是故事内容或图形约束。优先从当前正式manifest读取；已冻结缓存缺失该字段时，不修改brief与冻结锁，运行：

```bash
python3 scripts/route_plan.py bind-project CACHE_ROOT CURRENT_MANIFEST.json
python3 scripts/route_plan.py accept CACHE_ROOT FORMAL_ROUTE.json
```

绑定读取manifest.project_id或平台manifest.identity.story_id，独立存入project-binding.json；不改故事、图形、主线锁或上游哈希。已有明确身份不同则先核对当前项目，不能把其他项目缓存直接绑定过来。绑定命令也失败时，使用当前已确认身份按上述直接交接，不以补绑脚本成功作为继续条件；没有真实身份不能编造一个用于保存。

## 校验未达标是正常迭代

CLI退出码0表示检查正常完成，不表示路线通过。`NEEDS_REPAIR`及报告中的FAIL保留具体失败项，按其继续局部完善；不得打印或伪造PLANNING_ACCEPTED；业务交付可按上面的直接交接继续。submit/check/accept的调用方读取JSON状态和graph_report，不用assert、主动抛异常或非零退出码把待完善结果包装成工具错误；工具展示用“正在完善路线”等进度话术，内部保留真实未通过项和恢复记录。

accept/verify只有真正通过才输出PLANNING_ACCEPTED；route_plan命令行把执行故障返回为INTERNAL_ERROR、accepted=false及原始错误，其他工具的非零退出或异常也按诊断处理。不要把诊断转换成业务停止，不用`|| true`隐藏原始错误。

## 主线不动，缺哪项补哪项

先运行 `route_plan.py status CACHE_ROOT`。状态指向缺少输入、冻结主线、首次提交、失败支线修复或作者顺读后验收。

- small/ending_types失败：从既有可用支线补完整结算，类型合计服从用户数量。
- crossing失败：在支线补足可以进入既有共同节点的完整故事，不硬连不相容剧情。
- depth失败：在支线已经发生的矛盾中补第二层抉择及完整后果。
- sustained_growth失败：从现有支线的抉择后果继续写新处境与独立的下一轮选择，补在不同发展阶段；不拉长直线。
- continuation_balance失败：把过早退出方向发展成有代价的补救、交易或转向，不改结局标签冒充继续。
- ending_ladder失败：在可用支线中先兑现一层目标，再经历新事件与抉择到下一层，不把ending接出边。
- 其他图形失败：按具体节点与连接修复。

已通过的节点、连接与故事材料保留；只有确有问题才修改对应部分。不改主线原文、主线切片、主线路径及其节点，不降低门禁、不改短故事分类、不把困难支线砍成小结局逃避失败。

修复时复制当前topology-state.json里的bundle为提交内容，只修改受影响支线的完整故事/切片/图形。填当前expected_hash、具体reason和全部affected_nodes，再submit。脚本拒绝陈旧提交、超范围变更、主线变化和让已通过硬门禁退回失败的修订；每次成功修订保存前一版本。机器重新检查全图，不意味着作者重写通过项。冻结主线缺少合法出口、或用户要求真正冲突时，报告具体锁定位置或冲突；创作困难不是降低规则或追问用户的理由。

## 作者顺读与放行

先读通story-core.md中主角的行动、发现与下一步因果，再扩写；切片和冻结前独立重读mainline-story.md，完成故事整理与第一集可理解性检查；切片后再确认事件梗概里的身份、地点、实质交谈、行动和结果没有丢失，每个节点围绕一个主要事件，未变成设定堆叠，实际人物及资产已进入本集材料。交接前作者沿各路线顺读故事切片：每段能交编剧展开，选择前未执行选项，回汇承接所有来路，结局完成结算，用户约束兑现。作者只修有问题的支线，不新建A/B或语义回执，不以机器PASS冒充内容质量证明。

```bash
python3 scripts/route_plan.py accept CACHE_ROOT
python3 scripts/route_plan.py verify CACHE_ROOT
```

真实独立行PLANNING_ACCEPTED才表示机器检查通过，不决定业务是否继续。需要正式对象时，accept另加FORMAL_ROUTE.json参数；只要求规划测试且未要求项目保存展示时不要加；用户同时要求平台画布时，交接已验收对象完成该项目展示后停止。

依赖单向：冻结输入 → 完整支线及图形版本 → 图形报告与原文投影 → 规划回执。机器检查不回写作者故事，修改支线使旧回执失效但不修改主线。直接改候选、伪造报告或沿用旧回执无效；verify重新计算图形和投影。保留真实失败、修复原因、版本数及耗时。

故事由作者负责，工程只负责图形、切片对应和交接完整性。代码不得补写剧情、评价文采或推断虚构状态。
