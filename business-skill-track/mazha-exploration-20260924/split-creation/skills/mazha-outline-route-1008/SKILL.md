# 大纲与流程图

先识别当前项目、用户范围、模式和停点，用户手改高于旧计划。项目读写使用当前绑定 `nextplay-cli`；Skill 配置保存于 Maxwell，项目路线、选择和正文实际保存到后端并读回，按[CLI 与持久化](references/cli-handoff.md)，只改变前端不算完成。每次进入路线或续写前，按该参考的“视角保存与继承”读取当前选择；大纲阶段按[体验视角建议](references/creative-entry.md#推荐体验视角)推荐，玩家选择优先。

未被询问时不主动展示自动估算的体量或视频分钟数，也不让估算限制拓扑；用户明确数量和范围仍遵守。实际时长字段按[题材与提案](references/creative-entry.md)，完整图按[图形规则](references/graph-contract.md)。

## 材料接入先于创作方法

每轮先读[材料、范围与版本](references/materials-and-scope.md)，盘点各类真实材料、已完成内容与本次缺口，再按实验 SP 的创作计划协议向前端报告。此入口优先于下面普通整作与完整拓扑默认链路：完整故事、部分路线、已定图像可并存，导入/提炼不重跑对应创作，不擅自补完全部路线或剧本。前端只提供输入与开关事实，不替用户授权任务范围。

需要新构思或实质改变方向时，先读[理解需求与实际调研](references/research-before-creation.md)。公开首条进展先说明理解的需求和待研究问题，实际取得相关来源后才提出故事和选择设计；不能先确定剧情再补搜索。已有内容仅接入、格式整理或纯讨论时按缺口处理，不强制重新调研。

## 先分派任务

大纲、逐段生长、CLI 完整拓扑与已有图增量接续统一由本 Skill 负责，不再加载外部共享拓扑 Skill。先按[方法、范围与执行模式](references/modes.md)区分任务；调用当前绑定 nextplay-cli 做真实项目工程，不把 Skill 合并误当成新增底层命令。

普通完整拓扑、【一键拓扑】和普通整作文字创作，先按[当前作品续拓扑交接](references/continuation-handoff.md)读最新图，读取本次大纲关联的完整短故事；已有图时再结合主线实际推进最远的剧情同步必要变化、已有节点和各分支前沿。空图及可续做的活跃规划加载[CLI 完整拓扑](references/cli-topology.md)，保留完整短故事、主线长故事与切片、支线形状、各支线故事与切片、审读、check/complete 的原有能力；已 done 或无规划的非空图按交接参考用真实普通 route edit 增量补全。两种工程路径分别取本轮真实证据，不借旧 done，不为接续重建节点。

明确逐段生长、旧专家本批或续写本批，继续情绪脊与单元交替编剧，六种形状只约束首次开场；后续由情绪脊衔接。完整 CLI 方法不强制套逐段的内部图形门槛。全自动与执行前确认只影响审批，不能替代任务范围。图专项完成就停止；明确整作文字创作才在同 Run 继续独立编剧。

## 创作与连续衔接

1. **提案与大纲**：读[题材与提案](references/creative-entry.md)，结合整句意图逐个辨认人物、昵称和疑似网络梗，优先查抖音与 B 站资料；语境清楚就按正确对象创作，明显歧义简短问清，普通名字不硬凑梗。新恋爱或联动无需已有原作关系，不能因没搜到现成 CP 就把网络对象改成同名原创人物。保留已查明的身份与特征，主副标签合计最多 5 个，公开输出与保存数据一致，先形成 logline，再由它写通并留存完整短故事，提炼高潮前省略的预览和按视角开头的玩家介绍，三段齐备后一次保存大纲并读回。完整故事作为工作稿不公开全文；产品指定大纲确认时停在这里，不写路线或剧本。
2. **逐段方法的故事与分支方向**：确认后先读回本次大纲关联的完整短故事，按[故事整理](references/story-development.md)与[情绪脊](references/emotional-spine.md)核对最新事实，再按真实因果找岔点；已留存的故事不另起炉灶重写。本方法首次开场读[六种开场](references/expert-opening.md)，首批外仍由情绪脊续接。
3. **当前事件与路线**：按[模式和范围](references/modes.md)、[连续事件与切口](references/story-planning.md)、[图形规则](references/graph-contract.md)处理当前单元。每次设计节点先读[旧目标兑现与新目标接管](references/goal-handoff.md)。保存当前剧情材料、稳定节点与边，选择及全部即时后果入口一起提交；随事件补[文字资产](references/assets.md)，不先灌满整图。
4. **交给独立编剧，再继续路线**：按[同运行交接](references/skill-handoff.md)，加载 `mazha-screenplay-1008` 为当前已保存的剧情节点写作、修订并读回正文。这里不执行底稿、增强复写或冷读工序；编剧不替这里改图。完成当前单元后，按授权继续下一段或结束本批。
5. **验收和续接**：按[路线与批次验收](references/acceptance.md)及[真实保存节奏](references/live-creation.md)核对持久化内容。整作范围推进整作；局部请求只完成本批，按前端停点交还编辑，不把路线准备好或编剧单节点完成当本批结束。

用户仅要大纲／路线时只做该范围，不自动写剧本；仅要改剧本则直接交给独立编剧，涉及新事件或连接才先处理路线材料。按需读[画布局部修改](references/current-canvas-editing.md)、[循环／调查](references/loops.md)及[交互与真实进展](references/interaction.md)。画风、音色和媒体仍遵从用户及已选生成能力，不凭拆分扩大权限。
