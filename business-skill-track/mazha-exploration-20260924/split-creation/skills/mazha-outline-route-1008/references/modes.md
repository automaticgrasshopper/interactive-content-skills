# 创作方法、任务范围与执行模式

先分别识别三件事：本轮交付范围、路线创作方法、真实执行权限。专家模式保留原有实验及局部分批功能，不改名、不充当拓扑策略开关；全自动（full-access）和执行前确认（approval）只决定执行与审批，不能代替用户范围。Agent 不自行切换模式。

| 本轮任务 | 方法与停止点 |
|---|---|
| 新创意／只做大纲 | 本 Skill 调研并保存大纲，产品要求确认时停在确认点；不提前建图或编剧 |
| 普通完整拓扑／【一键拓扑】 | 加载 nextplay-route-planning，完成短故事、长故事和全部真实分支、回汇、结局，真实 check 与 complete 成功、next=done 后停止；不自动写正式剧本或媒体 |
| 普通整作文字创作 | 同事规划 Skill 完成完整拓扑后，同 Run 交 mazha-screenplay-1008 逐个写实际剧情节点；正式正文全部保存后结束 |
| 明确逐段生长／原专家本批／继续本批 | 使用本 Skill 的情绪脊与逐段事件法；开场适用六种形状，之后仍用情绪脊。路线与编剧按单元交替，完成授权本批即停 |
| 明确逐段生长并完成整作 | 同一逐段方法持续到全部授权路线和剧本完成，不逐批询问；可在全自动或执行前确认下运行 |
| 单集／局部路线／资产编辑 | 只改指定对象和必然影响的内容，不重新启动整作规划、不扩全剧 |
| 停止／打断 | 停止新操作，保留真实保存结果；未完成不称整作完成，恢复时读当前后端 |

【一键拓扑】是明确的完整图专项任务，即使来自专家界面也完成全图；这不改变专家模式本身。当前明确任务优先于旧会话的逐段指令，已确定方法在续写时沿用，不每次反问。没有明确选择时，普通完整图用 nextplay-route-planning；旧专家本批请求继续本来的局部创作。方法与权限可以组合，不因为 approval 改成半张图，也不因为 full-access 擅自扩大任务。

本 Skill 的图形检查器、long_story 默认和六种开场仅用于自己的逐段方法，不复制为同事 planner 的 intent 或 required_checks。同事规划严格依据其 Skill、next.input_spec 与用户原话，短篇／长篇及明确数量按其当前合同判断。未被询问时不展示 AI 估时，不把估时当用户预算；新 start 前按 creative-entry.md 核对大纲时长来源。

创作权移交效果只在完整拓扑专项或完整自动创作真实完成、实际运行结束、前端展示队列排空后触发。大纲确认、专家局部批次、单节点／资产编辑、打断、刷新和单独 Run final 都不能触发。局部任务正常结束回到编辑即可，不冒充整任务交接。仅本轮明确需要用户决定才 AskUser，执行前确认沿用真实产品审批。
