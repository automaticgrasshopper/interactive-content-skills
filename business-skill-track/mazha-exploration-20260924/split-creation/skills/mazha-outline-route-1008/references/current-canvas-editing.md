# 用户编辑后的局部工作

先读当前画布、节点、有效连接、实际剧本和相关资产。当前数据及本轮用户意图高于旧规划缓存；用户删除就是决定，不能自动恢复旧图、重编号已有节点或用旧路线覆盖手改。

用户要求已经明确接法就执行；只有删改后存在真正不同且未授权的接法，才一次询问接顺现有剧情、补写新过渡或暂不处理。选择暂不处理就停相关修复，不用“继续”推定恢复全部旧内容。

局部改连接先核对新前情、选择动作和目标第一项行动，再改依赖节点的材料／剧本；没有受影响的正文、媒体与节点保持原样。仅改台词、错字或标题不扩大为全作重新生成。后续当前写作材料取真实新入边；断开支路的独占证据与经历不再继承。

保存前读回目标当前版本，冲突就更新材料并保留用户变更，不强写旧版本。原有作品不重套初次全图数量配额；用户要求整体质量复核时报告缺项并按授权修。修正一处不代表全作重验通过。

用户要求的节点、标题、梗概、选项、连接、结局或剧本修改，必须通过当前 CLI 提交到项目的 `nextplay/current/route.json`，再读回相应节点、边或剧本核对实际结果；遵守[后端保存与读回](cli-handoff.md)。前端画布、打印内容、临时草稿或旧规划材料发生变化都不能代替后端保存。遇到用户手改，先读取后端当前状态；若页面与后端不同，以用户本轮明确意图处理差异，不能默默把旧后端内容覆盖回页面，也不能把页面变化当成已经落盘。

续写先读末端与尚未兑现的目标，保留局部情绪脊方向。把新选择的条件、动作与后果讲清，再逐批补节点、资产和剧本；不用预建全资产，不重做提案，不用假结局封口。
