# 同一个运行内交接编剧

这两个 Skill 是同一个 Agent 的两套工作说明，不是两个自行发消息的 Agent。预设同时绑定 mazha-outline-route-1008、mazha-screenplay-1008 和 nextplay-cli；确认大纲后保持同 Thread、同项目、同 Run，按需加载两者入口。缺少独立编剧能力时准确报告，不调用旧四步包冒充新流程。

路线 Skill 写通当前事件及选择后果，保存节点／连接与必要文字资产并读回稳定引用；编剧 Skill 取得实际上游资料后搜索同类型写法，用【本集剧情】与【本集剧情结束】包住自然语言事件段落，再直接写正式剧本、逐段保存。协调者完成当前单元后再展开下一段路线。选择与全部后果入口完整一起保存，未来全作空节点／资产不提前灌入。

交接使用实际 node_ref、当前梗概和停止边界、真实前驱正文与所选动作、实际资产 ref、本轮范围和项目版本。材料来自后端实际读回，补充说明可存本 Thread 缓存并绑定当前节点；缓存不能代替后端节点、边、正文。不再构造旧写作包、短底稿、增强输入、hash、冷读或验收回执。

自然语言剧情发现既定因果缺口或需要改变事件／连接时回路线 Skill，只修受影响材料并实际保存读回，再继续直接编剧。文字表达修改由编剧完成；用户手改和并发版本变化时重读当前事实，不覆盖旧 revision，不混用互斥来路。

“路线准备好”“一个节点写完”只是推进点，不发整批 final、停止 Run、AskUser 或解锁编辑。专家等本批剧情和资产全部保存读回后结束；前端另等实际运行状态与展示队列结束。全自动继续循环至全部授权内容落地。用户明确仅要路线时完成该范围可以结束，不强拉编剧；仅改文字不扩路线。

前端消费相同 route.json 的真实保存版本与 SSE，Skill 切换不增加伪造状态字段或动画。当前方案不依赖跨 Run 后台自动接续，也不结束路线 Run 后让前端偷偷发一条编剧消息。
