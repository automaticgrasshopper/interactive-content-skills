# 交互与真实进展

未被询问时不报告 AI 估算体量或总视频分钟，不把估时当制作约束；实际用户范围优先。大纲按 logline、高潮前以“……”结束的短故事预览、按视角开头的玩家介绍三段展示；全文留存与一次保存交付见 creative-entry.md，logline 不强制省略号收尾。

提案保存后按产品停点等待确认，确认读取用户最新大纲。无需插入画风、配音或全资产确认才能创作文字；执行前确认仍遵从真实审批。

所有创作入口依同一真实保存展示通路交付，适用于大纲、完整拓扑、逐段路线、单集／新增节点剧本及资产编辑。只报告实际进入且玩家能理解创作用途的调研、讲剧情或写正文阶段，不发送旧初稿／润色／冷读／终稿／合并五阶段，不编造百分比、桥接字段或内心推理。公共消息协议按当前 SP 与 frontend-protocol.md；本集梗概保存到真实节点 summary 原位展示，【本集剧情】只兼容旧解析，不另开长段正文界面。

每段实际保存可展示的成果立即交付，节点最终正文保存读回才称本集完成；整作完成按 acceptance.md。相同对象同版本不重复展示；页面刷新或恢复只读取当前结果，不重播旧内容，不确定片段不强行补演。前端自己管理展示，不等待动画才继续工程。

普通局部编辑完成正常结束回编辑。明确开头创作在当前节点正式稿保存读回、必要形象确认后可交还创作权；完整拓扑或完整自动创作按实际范围完成后交还。均须运行结束、队列排空，由前端核对，不自造移交状态。路线准备好、单节点保存、Skill 切换或 Run final 不单独证明整任务完成。需要用户关键决定才 AskUser，不每批追问。

用户打断停止新输出和操作，保留真实已存内容，不当作成功、不删除数据；取消结果不明先读回。续写使用当前后端，不能覆盖用户手改或恢复已删内容。

## 左右分工，同一内容只展示一次

右侧“创作脉络”展示真实创作进展，包括理解需求、清晰且有明确创作用途的执行、实际调研发现和正在形成的故事方向。判断标准是玩家能看懂正在解决哪个创作问题，不限于结论，也不把所有执行都排除。实际产物继续由真实保存的节点、剧本与资产展示，进展不重复整段正文。

左侧保留用户消息、必要对话、问题与确认、简短结果交付和折叠工具记录。准备进入右侧的进展必须按 SP 的【创作进展】或工具 www.what 协议输出，不作为普通 Summary/回复留在左侧；同一句、同一用途只发一次。工具 www.summary 使用简短操作标题，不复述右侧完整文案。结果交付只说“设定图已生成并保存，请确认”等必要结果，不重复解释创作过程。

## 进展说人话

输出普通进展或工具公开 annotation 前，先把实际工作译成玩家听得懂的一句话：直接说谁在做什么、遇到什么、接下来写哪段。比如“修复师完成扫描，却意外打开了潮门。我先把这个意外写成开场。”不要说“共同底稿”“投成节点”“一键拓扑”等内部工序词，不讲流程理论，不新增还未发生的进展。

阅读/调研只说实际用途和取得的发现，资料未取得不假称已研究。加载 Skill/help、定位接口、保存校验和故障恢复留在工具记录；确实阻断目标的失败在左侧简短如实说明影响，不包装成创作成果。公开进展用于阶段之间，不替代节点、剧本或资产正文。

可以公开的清晰执行，例如“查阅《魔兽世界》官方故事页，提取阵营对抗的类型体验。”“核对高奇幻、阵营战争与世界级威胁的公开背景。”“研究互动游戏的有意义选择，让每条分支承担具体代价。”仅在实际做这项工作时使用，并换成当前作品的具体问题，不照搬例子。尚在查阅就不写成已有发现，不要求固定“搜索相关题材发现”的开头。

“前一轮检索无效，改查另一来源”“限定检索召回无关内容，换来源路径”等故障恢复，以及建目录、保存工作稿、校验读回、接口/help/规范加载都不进入右侧，也不另发普通进展填满左侧，只保留真实工具记录。若失败确实阻断用户目标，在左侧简短说明影响与所需决定；用户主动问细节时如实回答。
