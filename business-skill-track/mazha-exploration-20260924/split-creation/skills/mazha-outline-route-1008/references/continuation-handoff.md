# 当前作品续拓扑交接

一键生成全部故事流程是把当前作品继续做完整，不是重写一部新作。按钮只在创作权移交玩家后出现，由前端控制；此后玩家可能随时点击，Skill 每次都读取本轮最新后端，不复用初始大纲、旧完整故事或上次按钮请求的快照。只做拓扑，保留既有剧本，不自动补写全部正式剧本或生成媒体。

## 先弄清现在写到哪里

读当前 outline、完整 route 的稳定节点和边、相关 summary/conflict/stop_boundary、真实正文与资产，再按需读当前 route generate 规划状态。先看紧凑图和全图摘要，再读取影响接续的正文、选择及条件，不能把局部视图外的节点当作不存在。用户手改、删除和已演出的选择后果高于旧草稿；空正文不等于节点不存在，只有标题的占位也不等于剧情已完成。继承已保存 perspective/player、明确数量和用户必保内容。

“最远”指当前主线实际发展到的事件与停止边界。先用用户指定的主线及现有真实连接识别连续经历，再结合节点材料、正文和已发生后果找前沿，不能取数组最后项、显示编号最大、更新时间最新或边数最长的路径。循环要区分已发生经历与仍待重复的过程，不能无限追最长路；不可达孤点、已闭合结局和未展开占位分别标明，不拿它们抬高主线进度。多个方向并存时分别记录前沿；确无依据区分、且会实质改变故事的主线歧义才简短问清，不擅自把玩家未选的方向当已发生。

## 整理一份完整而准确的故事

以当前主线最远处为锚，从已发生的开头讲到一个能兑现当前目标的完整结局，微调原来的完整短故事。已经完成的剧情作为事实保留，未来部分接住人物当前欲望、关系、线索和代价；不是只写下一集，也不是因需要一份完整故事而改掉已有开头、删除手改或提前执行未选动作。大纲与当前节点不一致时以用户最新修改和实际内容为依据，明确必要调整，不偷偷用旧大纲覆盖。

连同短故事保留这些真实信息：当前版本与入口；主线已完成经历及其 node_ref；已有节点/选择/有效边的稳定引用、必要剧情材料和正文状态；已建立的资产、关系与不可逆后果；每个未展开方向的入口、合法前驱、待接动作、停止边界及可成立的回汇位置；用户删除、禁改与必须保留的内容。主线短故事讲清一条确定经历，其他分支分别附来路和后果，不把互斥的物件、伤痕、秘密或人物关系混成全员共有事实。后续可回汇只因进入事实相容，不因标题相似。

这些是同一 Agent 读取本 Skill 的 cli-topology.md 时的创作材料，使用当前 CLI 接受的纯文本和真实字段，不另造 route 元数据、私有写作包或需要另一个 Skill 约定的 Schema。没有保存到项目的后续计划明确作为待创作部分，不说成已经发生。正式编剧之后仍从实际 script context 读取，不用交接草稿替代后端。

## 按当前工程状态继续

- 空图：按 cli-topology.md 和真实 next.input_spec 新建规划，将最新完整短故事用于实际 story-core，再完成全图。
- 有活跃未完成规划：读取当前 next 与画布；外部改图按真实 route_version reconcile，保留手改和删除。以当前材料继续尚未完成的方向；已消费的旧故事不重新提交覆盖画布，必要局部调整用 generate edit/rewrite-segment。新结局仍走真实故事切片，不能借普通 edit 绕过活跃规划的要求。
- 已 done，或非空图没有可续做的规划：当前 CLI 的普通 start 要求空图，新 start --new 的第一次 mainline-cut 要求 --replace-route，都会偏离本次保留身份的续拓扑意图。不得调用它们重建。仍以最新完整故事和上述材料为依据，由本 Skill 按真实普通 route edit 合同追加/连接/局部修补，保留已有 node_ref/edge_ref、正文、媒体和已兑现后果；只修改必然受影响的边界，不重排成另一部故事。若当前 CLI 无法完成某项增量接续，报告具体缺口，不假称已支持，更不改内部规划状态绕过。

写入前确认正在修改的版本仍是读取版本；冲突或用户又改图时重新读受影响内容并更新交接，只补未成功部分，不重放整批。所有变化真实保存后读回；不直接写 route.json，不以自然语言短故事、打印结果或前端状态代替保存。

已有图已经完整且用户没有新增故事要求时，读回确认现状即可，不为按了按钮再添一轮剧情或打破已成立的结局。未完成前沿需要的后续先写通连续故事和确定后果，再用普通 route edit 的 add-node/connect/insert-choice/update-node 等真实 operations 逐段落盘；选择及所有立即后果入口一起保存。新节点使用本次 client_key，后续改动用真实回执的稳定 ref，不把显示编号当引用。每个新 video 填真实 summary、conflict、objective 和本集实际资产，choice 只放问题与动作；summary 是确定故事切片，不是“待展开”占位。普通 route edit 不写 estimated_minutes 等仅规划输入支持的字段；已有正文保留，新剧情正式 script 可为空，图专项不提前编剧。

## 本轮完成如何判断

检查整张当前图：每个需要展开的方向都有实际后果，待续前沿已处理或按用户要求有明确边界，来路与回汇成立，所需结局齐备；已有稳定引用、有效边、剧本和用户修改得到保留。再结合实际保存读回及当前 CLI 工程检查判断，project check 通过只证明工程合法，不能单独证明故事完整。

route generate 路径须本轮真实 check/complete 和 next.step=done，独立输出真实短回执。普通 route edit 增量路径按本轮实际修改、当前全图读回和检查结果交付，不能拿历史 plan 的 done 冒充本轮完成，也不发明完成布尔字段或为收尾重新启动规划。运行结束和队列排空由前端处理；拓扑完成只结束本轮授权，不自动重写既有剧本、分镜或媒体。
