# 随创作出现的文字资产

不设“先把全部角色、场景、道具做完”的阶段。创意提案只定必要身份；写本批事件、拓扑、自然语言剧情与正式剧本时陆续发现需要的内容。

先查当前资产名称、别名与稳定引用，复用同一人物／地点／道具，不因换称呼重复建卡。新增时由统一创作协调者确认：它是否是当前事件需要、是否改变用户事实或已有规则、是否应先补入本集梗概。获得或失去物件、首次得知身份、权限与能力变化都必须在剧情里发生，不能只改资产卡让它凭空成立。

- 人物：正式名／已有别名、观众此刻可知的身份、为何与当前事件有关、必要关系、可辨认的外观与说话特点。隐藏真相只在允许揭示的节点进入写作材料。
- 场景：当前实际使用地点、可见空间特性、进出口和对行动有影响的限制；不按想象预建全城。
- 道具：当集真正使用的物件、可见特征、持有者及已确定用途／限制；普通钥匙不能临时具有未建立的遥控权限。

只对本批出现或确有变化的项目做 asset add/update；先保存并读回真实 ref，再将当前节点 assets 绑定真实资产，剧本关联由 CLI 维护。无图片／音色也能保存文字，不填假媒体 URL。标题和简介不替代戏中首次出场的自然交代。

若自然剧情或正文阶段发现缺人物／场所／物件，返回协调层补事实、资产，然后重写受影响的自然剧情与正文；不是卡死，也不是让写作者越权发明。已完整且保存的其他节点保持原样。

同时生图开启且本轮授权时，当前类型这批必要文字资产保存读回、画风确认后就加载 mazha-asset-image-direct-1008 发出该类型本批真实生图；人物批同步库音色匹配，不等整批或整作剧本写完。资产调用按真实 CLI 合同并发与等待回执；返回后继续不依赖图片决定的已授权梗概、连线与正式稿保存，不等前台展示或逐图确认。后续节点新增的必要资产另成批，既有有效图片和绑定复用。只把玩家图片确认作为前台推进、依赖该图片的分镜/视频和最终移交的门槛，不作为独立文字写作的总门槛。

生图按类型分别触发批次：第一张人物开始时只启动本批人物，前台逐人物确认；轮到第一张场景才启动本批场景，轮到第一张道具才启动本批道具。同类型内部按当前真实合同并行调用、前台顺次展示，不能在第一张人物时顺带启动场景和道具。后续集首次出现或确需改图的同类资产另成该类型新批，既有成功且未变的资产复用。
