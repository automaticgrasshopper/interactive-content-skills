# 人物、场景与道具同时生图

只在本轮授权图片任务且请求信封 ui.simultaneous_images=true，或用户明确点名生图时执行；兼容旧「同时生图：开启」「形象直出：开启」。开关是能力选择，不扩大本轮任务。关闭时不自动生图；明确只讨论、只导入、只做路线或不生图时不自动生图；大纲确认前不生图。用户给定正式图直接登记复用，参考图仅继承指定维度。

当前 ui.simultaneous_images=true 时，“默认只做开头”只限制剧情范围，不关闭开头实际必要资产的图片；三类当前选中图均保存读回且逐图确认后才允许移交创作权；有台词人物同步匹配并绑定库音色，音色匹配或试听加载不阻塞形象确认。false 时三类均不自动生图；用户明确点名某项仍按其范围执行。

人物名称、故事描述、性格是叙事设定；仅保存这些字段不构成重生图片的请求。已有形象依据实际生成提示词，用户在「我想调整」中修改该提示词并点击「重新生图」才提交新生成；复原提示词只恢复编辑开始时的内容，不生成。不要把描述/性格保存或提示词草稿编辑误当成生成授权。

## 后台生成，前台顺序确认

1. 保持当前创作计划，先用 nextplay-cli 保存本轮必要人物/场景/道具的完整文字并读回；范围只到当前开头/本批，不批量补全作。画风必须来自玩家明确指定或真实选择：未确认时先按大纲 Skill frontend-protocol 展示画风选择并等待回答；题材、预填值和模型推荐不算确认。当前类型这一批文字齐备、画风经玩家确认且获授权后立即启动这一类型的真实生图任务；人物批同步库音色匹配，不等全部路线或剧本完成，也不等第一张确认才启动后一张。后续节点首次引入的新人物、场景或道具另成新批，要求未变的成功资产直接复用。
2. 读取 `source/references/image-layout-rules.md` 与 `source/references/reference-image-rules.md`，沿用主预设视觉合同：16:9、人物左侧正侧背三视图/右上正方形特写/右下细节、场景单张环境空间、道具白模三视图与主视/细节版式、项目统一画风、参考图按用途绑定。`source/` 是主预设资产生成师只读副本；仅继承视觉与参考规则，本入口的并发范围、逐图确认、失败停留及 CLI 保存合同优先。
3. 加载 nextplay-cli 并读取其 `references/asset-materials.md`。CLI 已把当前资产文字、项目画风正负向、版式和白模真实参考加入实际模型请求。不要再调用另一套图像工具或生成二次图片；不要把本地参考图路径当图片 URL。需要附加参考时按 CLI 合同使用真实 reference-media-ref/reference-url。
4. 从已初始化的 nextplay-cli 目录执行 `./nextplay.bin asset image generate --asset-ref-id <本资产真实 ref>`；只有用户明确要求改形象时才执行 `asset image edit --asset-ref-id <ref> --edit-request '<保留什么、改什么>'`，不为改图强制改写故事描述和性格。用户在前端直接编辑实际提示词的请求由其现有真实生成接口提交，不重复调用 CLI 再生成一次。按当前 CLI 的真实并发合同，在同一次回复中一起发出本批各资产的独立 generate/edit 工具调用，每个资产一条命令；CLI 已处理并发保存，不等上一张出图或确认才提交下一张，不在一条 exec 中串行多张。每条命令前台等待真实生成、保存和读回完成，给足 timeout；不用 `&` 或虚构 `--async`。同一资产的连续修改仍串行，前端已提交的同一任务只恢复/读取，不重复提交。CLI 仍负责真实生成、登记选图和完整版式参考，不换裸图像请求。只看最终组装要求时用现有 `--dry-run`，它不联网、不生成、不写文件。
5. 成功条件必须同时满足：返回 `saved`，本资产的真实 `image_url` 非空，`selected=true`；再执行 `asset inspect --asset-ref-id <ref> --include media` 核对当前文字和选中图。保存和读回之后，使用当前真实可用的看图能力读取并审核当前选中图的版式、人物/场景/道具要求、画风与参考一致性；只有元数据不算看图审核。不通过则先修正当前图片并重新保存、读回、看图审核；未知状态先恢复，不假报通过。全部当前版本自动审核结束且通过后才进入下面的玩家确认；其他已授权资产任务可继续后台生成和保存，但不提前展示或确认。
6. 同时生图开启时，当前开头/本批实际使用的必要人物、场景、道具三类都要有真实图片；不能把道具留待分镜阶段再补，也不扩到全项目其他资产。已有资产无图也须按当前范围补图；已成功且形象要求未改变的图片复用，不无故重做。外观变更后旧图仅作为历史/编辑参考，不冒充新版完成图。

后台与前台是两套节奏：CLI 真实调用仍按其当前合同等待生成、保存和读回，不能虚构即时返回的 `--async` 或脱管进程。后台不等打字、标点停留、连线、图片特效或试听播放；前端则缓存提前到达的真实结果，逐步播完后才切换，后台完成不触发快进。新保存或图片返回不能清掉当前创作文字或其他待播步骤。每个剧情场面、选择与实际后果都完整展示；连线按其实际动画周期完整呈现，不写死秒数，文字含标点停留，图片仍按下节等待审核与确认。刷新以本轮前端断点恢复当前步骤、文字游标、剩余停顿/特效和队列，不能按后台完成位置跳转；新用户修订才替换旧队列。

## 人物生图同步匹配并绑定库音色

同时生图包含本批有台词人物的库音色匹配与绑定，不等到分镜视频才补，不再让玩家额外开启音色。用户明确不要声音、只改图或人物无台词时按该范围；场景、道具和无声人物不强配声音。声音与图片可以并行准备，前台仍只展示当前人物，不提前展示后续人物音色。资产阶段直接使用音色库现成试听，取消单独生成一句人设台词；不调用 speech 合成、试听视频、提取音轨或转写核听，不让这些任务阻塞确认形象。

继承原资产生成师 `asset-design-rules` 的结论：先设计同批角色稳定的声线年龄、音色质感、语速节奏、表达习惯和情绪底色，再逐人匹配；相近角色应能听辨差异。角色的 `attributes.voice` 使用简短自然的声音类型开头，接冒号和声音气质，如“酷飒御姐：成年女声，中低音，清晰利落，语速稳，表达直接”。这个类型依据人设，不都叫御姐；不用供应商名、英文模型、音色ID、库编号、测试串或夸张自造词。无声角色沿用真实设定，`voice` 以“无声：”开头并写明替代表达，不改成能说话。

1. 在真实文字资产保存时补齐 `voice`，仍只用 CLI 声明的资产字段。先检查已有绑定；已有符合当前人设的音色与有效库试听保留。仅改外貌、生图提示词或图片审核重试，不重新匹配或清空绑定。
2. 按当前 nextplay-cli `references/asset-materials.md` 的真实 `voice_tone_match` 合同逐角色查候选、选定后查详情，同批按轮次并发；使用原样真实 `voice_id`，不要把 `voice_library_id` 作为音色ID，也不把一份结果分给所有人物。选用详情返回的真实库试听 `preview_url`，不猜链接，不要求库示范内容说角色台词。
3. 通过当前 CLI 声明的 `asset voice bind --asset-ref-id <真实ref>` 输入合同保存 `{"voice_id":"<所选真实音色ID>","preview_audio_url":"<详情返回的库试听HTTP(S)URL>"}`，再 `asset inspect --asset-ref-id <ref> --include media` 读回一致。`voice_binding` 仍只有这两个字段；不塞入 sample_line、voice_type 或其他未声明字段。类型来自资产 `voice`，绑定来自所选库音色；匹配详情和绑定读回保留在本线程工作记录中。资源临时URL按平台现有托管/刷新合同处理，不拿 sandbox:// 当播放器URL。
4. 当前人物图片保存、读回、看图审核通过后，按下节发该图片版本的 `asset_image_confirmation`，不等待声音任务、音频加载、试听播放或核听。前端在首次展示当前人物形象时一起提供库试听小播放条，旁边仅标简短声音类型，不展示库编号、模型名称或旧的人设短句；不自动播放、不强迫听完才确认。确认仍使用“确认形象／我想调整”，文案仍是“设定图已经生成并保存，请确认。”。
5. 音色匹配或绑定明确失败可核查原因后重试一次；状态不明先恢复/检查。保留图片与有效已有绑定，不假报声音成功，但不阻塞图片确认和后续图片展示。试听加载或播放失败仅在试听区域提示，不撤销已出现的图片确认，也不触发图片重生或再次审核。
6. 正式生成有对白的分镜视频时，核对实际发声人物的真实 `voice_binding`，按当前分镜视频模型合同使用绑定声音和参考音频，让它说**已保存剧本中的原台词**，不使用库示范词或试听短句替换剧本。保持同一人物声线一致；无声人物免除此项。若缺少有效绑定或模型不支持所需声音参考，只暂停依赖该声音的视频任务并如实说明，恢复匹配/绑定或选择真实支持能力的模型；不默默改用默认声线，不倒退卡住形象确认，不扩大到修改共享后端或工具。

## 玩家反复调整与继续

画风选定后立即出现平台现有左图右文界面，右侧只打当前资产文字。后台可提前并发完成后续图片与审核，但前台每张必须完整播放文字打字→特效→审核合格图片→玩家确认；确认前不展示下一资产。右侧文字打完后仍播放3—5秒特效；真实生成或审核较慢就继续等待，不能提前展示待审图。每张包括首张，均在当前版本审核通过并完成图片展示后才出现“确认形象／我想调整”。每张轮到确认且当前版本已保存、读回及审核通过后，用 AskUser 暂停前台：仅一个 select 问题，id=asset_image_confirmation，标题包含当前资产名称并询问「请确认这个形象」，选项只有「确认形象」（value=confirm_image）和「重新生成」（value=regenerate_image）。AskUser 必须位于该版本所有自动审核和重试之后，不得先问玩家再继续审核同一版本或重生；标题绑定当前资产，不能串用另一资产结果。玩家确认只适用于该选中版本；之后不再自动替换或重复弹相同审核。不新增第三个选项，不提前在前台展示下一张或切换路线/剧本画面；这不是后台写作前置。真实图片调用返回后，先继续已获授权且不依赖玩家改图决定的节点、连线和剧本文字保存，不把每个图片 AskUser 插到独立写作之间。确实需要玩家决定时再暂停对应依赖；已启动的同批后台任务不因此取消。人物、场景、道具都执行此 AskUser，普通回复“请确认”不能代替可提交的确认问题。前端承接形象查看与提示词调整；直接修改提示词生成完成仍留在本资产确认，不把图片成功当确认。

收到 value=regenerate_image 且 label=“已调整，请审核当前形象”，或【前端形象已调整】请求时，表示前端已同步真实生图并保存选中结果：只读取、看图审核这个新版本，不重复发起生成；不通过才按真实审核问题修复，审核通过后发新的单图确认问题，不能沿用旧版本问题。生成中不提供可用确认按钮。

收到确认形象后，读取该资产最新选中图和当前文字，才按原获授权范围展示下一项；如果本轮只是局部改图则完成后停止，不复活旧队列。重新生成时只处理当前资产；提示词以用户刚保存/提交的最新真实版本为准，保留其他资产与历史图片，成功后再次等待相同确认。失败保留已有可用版本并如实提示，旧图不冒充新结果。

重新生成一提交，展示应进入同一图片框的生成特效；生成时操作按钮和提示词输入只读，画风折叠栏仍可展开查看。界面状态不能证明真实保存，当前图必须按准确 asset ref 与媒体结果匹配。人物设定展示区只展示描述和性格，不提供修改形象的暗中入口。画风与画风负面要求位于提示词末尾、默认折叠并可编辑；资产通用/本类禁止项、自动附加参考说明、固定比例与版式作为生成合同保留，编辑界面不暴露成用户字段。隐藏不代表从真实模型请求删除。

## 失败和停止

图片任务明确 `failed` 可以核查原因后重试一次；仍失败停在当前资产，保留文字、历史和当前画面，不跳过继续下游。`unknown`、`save_pending`、`partial_saved` 保留真实任务及产物信息，检查/恢复已有结果，不重新提交重复任务，不假报成功。
玩家停止后不得继续创作；玩家给新要求则重新读取当前项目并定位应修改的阶段和资产，不消费旧队列。后台已返回的旧图不作为新要求的结果，不自动覆盖新文字或新选择。

## 面向玩家的文字

图片保存、读回并审核通过后，给玩家的确认文案固定为“设定图已经生成并保存，请确认。”，不追加后续图片已在后台完成、并发、缓存或展示队列等内部机制；审核未通过时不使用成功文案。

日常进展只描述当前人物、空间或道具正在形成，避免工程状态、JSON、任务 ID、测试、耗时与工具报错。不要重复完整资产正文到 Agent 聊天，不提前宣告后续内容已完成。玩家主动问进度/失败/实现时如实回答；不谎称生成成功。不额外输出无正文的结束说明标签；遵守实验 SP 的公开展示协议。

生图按类型分别触发批次：第一张人物开始时只启动本批人物，前台逐人物确认；轮到第一张场景才启动本批场景，轮到第一张道具才启动本批道具。同类型内部按当前真实合同并行调用、前台顺次展示，不能在第一张人物时顺带启动场景和道具。后续集首次出现或确需改图的同类资产另成该类型新批，既有成功且未变的资产复用。
