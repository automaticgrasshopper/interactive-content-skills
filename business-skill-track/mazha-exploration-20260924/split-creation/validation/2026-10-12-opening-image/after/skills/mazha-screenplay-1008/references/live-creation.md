# 写到哪里，真实保存到哪里

开场局部单元中只处理协调者交接的当前真实剧情节点；该节点正式稿完成后交回协调者继续本批其他分支后果，不因第一集写完就结束整批。前端逐节点完整播放梗概、构思、正文、回图；后台按真实保存继续写作，不等动画，不另发可替代全批正文的摘要。

本集梗概先保存到当前节点 summary 并在节点原位展示，短底稿及 enhancer-input.txt 只留内部工作区。完成底稿后，增强复写阶段才开始写正式剧本。形成可读、格式正确的完整行动段时，用 CLI `script set --text <正文文件路径|->` 保存当前累计纯文本正文；资产引用按节点 assets 和 CLI 合同维护，工具返回后继续写下一段。不先写完整剧本再拆段补交，不 sleep、刷空工具或写假进度。极短节点不硬拆，有多个自然行动段时保留前后两次实际正文写入。

需要新资产时先核对当前事实与已有 ref，按 assets.md 保存读回，然后将新增段落写入同一节点的累计正文，同步实际节点资产关联。事实或连接要改变则返回路线协调，不由正文擅自新增规则、来源或结果。

用户局部改字、台词或小段表达时可直接修订当前正文，使用 CLI script edit/set 保留无关手改、资产关联与媒体；既定戏剧拍不变时不重跑全套。明确重写场景或改变戏剧拍时，先同步受影响的本集材料与底稿，再增强复写；不另加冷读或写作验收。写完后实际保存、读回目标正文和资产引用一致，才返回节点完成。没有平台完成字段不自行发明。

每个有意义的保存分别工具调用，不把全剧所有操作包成一次调用。内部材料和搜索笔记不进正式剧本。不等前端动画，页面按真实 SSE 版本排队展示；保存成功不代表页面已经同步，尚未同步要如实说明。协调中的单节点完成不结束整批运行，直接用户单节点请求完成后可以正常回复。

每个剧情节点正式稿最后一次真实保存、读回一致后，输出一次仅供前端定位播放边界的消息：
【剧本节点完成】
{"request_id":"本轮请求信封内真实ID","node_id":"实际node.id"}
【剧本节点完成结束】
这不是平台完成字段、保存回执或整批完成证明，不写入项目正文。累计正文的中途保存不能发送；之后重写该节点时重新保存读回并重新发送。前端在本节点正式稿完整播放后回图，再展示选择与后果。不要等待前端动画才继续后台工作。
